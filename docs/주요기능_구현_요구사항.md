## 0. 요구사항 표기 규칙

- 요구사항 ID: `FR-<영역>-NN` (기능), `NFR-NN` (비기능), `IFR-NN` (인터페이스).
- 우선순위: **[필수]** 핵심 동작 / **[중요]** 주요 사용성 / **[선택]** 옵션·실험.
- 각 기능은 **(1) 기능 요구사항** + **(2) 구현 요구사항(데이터·규칙·위치)** 으로 기술합니다.

## 1. 시스템 개요 및 아키텍처 요구사항

### 1.1 제품 정의
| 항목 | 내용 |
|------|------|
| 제품명 | 지엠티 프로젝트 매니저 (표시 제목은 환경설정에서 변경 가능) |
| 목적 | 여러 프로젝트의 WBS(작업 분해)를 한곳에서 관리·시각화·공유하고, 팀 서버에 동기화하며 주간보고를 돕는다 |
| 주요 사용자 | PM·과제 담당자, 팀 리더·팀원, 조직 책임자, 시스템 관리자 |
| UI 언어 | 한국어 (메뉴·도움말·단축키 안내 전부) |
| 접근 | 웹 브라우저(반응형, 데스크톱 우선) |

### 1.2 아키텍처 요구사항

- **NFR-01 [필수]** 클라이언트는 **React 19 + TypeScript + Vite 6 + Tailwind CSS 4** 기반 SPA여야 한다.
- **NFR-02 [필수]** 전역 상태는 React Context로 구성한다: `WBSProvider`(작업·프로젝트·설정), `AuthProvider`(세션), `OrganizationProvider`(조직도), `LevelColorsProvider`(레벨 색), `ToastProvider`(알림).
- **NFR-03 [필수]** 백엔드는 **Supabase**(PostgreSQL + Auth + 선택적 Realtime + Edge Functions)를 사용한다.
- **NFR-04 [필수]** 로컬 저장은 `localStorage`를 기본으로 하고, 실패·용량 초과 시 **IndexedDB**(`wbs_mg` / store `kv`)로 폴백한다.
- **NFR-05 [필수]** 정적 호스팅(Vercel)으로 배포 가능해야 한다.
- **NFR-06 [선택]** Yjs 기반 동시 편집(`yjsSupabaseProvider`)은 실험적 옵션으로만 제공한다.

### 1.3 실행 모드 요구사항
- **FR-MODE-01 [필수]** `VITE_SUPABASE_URL`이 없으면 **로컬 전용 모드**로 동작한다(로그인·동기화 UI 비활성/우회, 브라우저 저장만으로 전 기능 사용).
- **FR-MODE-02 [필수]** Supabase 설정 시 인증·동기화·협업이 활성화된다.
- **FR-MODE-03 [선택]** `VITE_ENABLE_PRESENCE`가 `1`/`true`일 때만 동시 편집 표시(Presence) 채널을 구독한다.

## 2. 데이터 모델 요구사항

> 정의: [`src/types.ts`](../src/types.ts), 스키마: [`supabase/migrations/`](../supabase/migrations/)

- **FR-DATA-01 [필수]** 핵심 엔티티를 다음과 같이 둔다.

| 엔티티 | 키 속성 | 관계 |
|--------|---------|------|
| `projects` | name, projectKind, start/endDate, assignments(jsonb), ownerId, minWorkEffortDays, workEffortUnit, report_*(주간보고), groupId, pmName/poName, includeInDashboard | `auth.users` 1:N |
| `tasks` | name, parentId(트리 자기참조), start/endDate, progress(0~100), weight, workEffort, assignee, status, dependencies(uuid[]), checklist, deliverables, baseline_*, isMilestone/isIssue/isActionItem, userLockedFields, customFields, sortOrder, updatedAt | `projects` 1:N, 자기참조 트리 |
| `wbs_settings` | id='default'(단일 전역 행), level1/2/3_prefix, maxLevel, statusConfigs, linkStatusAndProgress, wrapTextInCells, showCriticalPath, tableColumns, config_json(customColumns·favoriteProjectIds·projectGroups·appTitle) | 전역 1행 |
| `profiles` | id=auth.users.id, email, full_name, is_admin, approved, level_colors, department, managed_org_node_id | `auth.users` 1:1 |
| `project_members` | role(owner/editor/viewer), UNIQUE(project_id,user_id) | N:M |
| `project_invites` | token(uuid), role, expires_at(기본 +7d) | 초대 |
| `project_access_requests` | requested_role, status(pending/approved/rejected) | 권한 요청 |
| `wbs_audit_log` | entity_type, entity_id, action(create/update/delete/bulk_update), changes(jsonb) | 이력 |
| `visits` | session_id, visit_date, UNIQUE(session_id,visit_date) | 접속 통계 |
| `org_nodes` / `org_members` | 조직 트리 / 인원(name·department·position) | 조직도 |

- **FR-DATA-02 [필수]** 작업 `updatedAt`은 트리거로 자동 갱신하고, 동시 수정 감지(낙관적 잠금)에 사용한다.
- **FR-DATA-03 [필수]** 신규 DB 구축 시 마이그레이션을 **파일명 타임스탬프 오름차순으로 전부** 적용해야 한다(`FIX_*`·`FULL_SETUP_*`는 수동 복구용 제외).

## 3. 인증·회원·승인 (FR-AUTH)

### 기능 요구사항
- **FR-AUTH-01 [필수]** 이메일+비밀번호 및 Google·GitHub OAuth로 가입·로그인할 수 있다.
- **FR-AUTH-02 [필수]** 가입 직후에도 **앱을 즉시 사용**할 수 있어야 한다(로컬에서 프로젝트·작업 생성·편집). 단 **승인 전에는 서버 동기화(업로드/다운로드) 불가** 안내를 제공한다.
- **FR-AUTH-03 [필수]** 승인(`profiles.approved=true`)된 사용자는 서버와 동기화하고, **등록된 모든 프로젝트를 조회**할 수 있다. 단 **편집은 별도 권한(소유/멤버/요청 승인)**이 있을 때만 가능하다.
- **FR-AUTH-04 [필수]** 관리자(`profiles.is_admin=true`)는 회원 목록·승인·계정 삭제 등을 수행할 수 있다.

### 구현 요구사항
- **FR-AUTH-05 [필수]** 로그인 시 `rpc('ensure_profile')`로 프로필을 보장하고, **첫 가입자는 자동으로 `is_admin=true`**(트리거 `handle_new_user`).
- **FR-AUTH-06 [필수]** 관리자 권한 게이팅은 클라이언트 단일 진입점 `effectiveIsAdmin = (isAdmin || adminOverride) && !memberPreview`로만 분기한다([App.tsx](../src/App.tsx)). 신규 관리자 기능은 반드시 이 변수만 참조한다.
- **FR-AUTH-07 [중요]** **관리자 비밀번호 모드**(`adminOverride`, sessionStorage): 앱 비밀번호로 임시 관리자 권한을 부여하고, 세션 종료 시 해제. Edge Function `admin-delete-user`도 `WBS_ADMIN_PASSWORD`로 우회 허용.
- **FR-AUTH-08 [중요]** **회원 체험 모드**(`memberPreview`): 관리자가 일반 회원 시점으로 화면을 미리 볼 수 있다.

## 4. 조직도 (FR-ORG)

- **FR-ORG-01 [필수]** 부서/팀 트리(`org_nodes`)와 인원(`org_members`: 이름·부서·직급·성별)을 관리하고 `OrganizationContext`로 일관 제공한다.
- **FR-ORG-02 [중요]** 조직 회원 이름과 일치하는 담당자/PM/PO는 대시보드·투입현황 등에서 **직급과 함께** 표시한다.
- **FR-ORG-03 [중요]** **조직 책임자**(`profiles.managed_org_node_id`)는 본인 산하 노드의 자손 부서 회원만 관리할 수 있다(범위 계산: [`lib/orgProfileScope.ts`](../src/lib/orgProfileScope.ts)).
- **FR-ORG-04 [선택]** 엑셀 부서명 → 조직 노드 매핑을 위해 `org_nodes.department_aliases`를 둔다.

## 5. 프로젝트 관리 (FR-PROJ)

### 기능 요구사항
- **FR-PROJ-01 [필수]** 프로젝트를 생성·이름/설명/기간 수정·삭제할 수 있다.
- **FR-PROJ-02 [필수]** 프로젝트를 **복사**하면 소속 작업이 포함된 새 프로젝트가 생기고, 복사본은 **나의 소유**가 된다.
- **FR-PROJ-03 [필수]** 프로젝트에 시작·종료 기간을 두면 **그 범위를 벗어나는 작업 일정은 허용하지 않는다**.
- **FR-PROJ-04 [중요]** 프로젝트 단위로 **투입 인원·투입 비율(%)·월별 투입**(`assignments`, 키 `YYYY-MM`)을 둘 수 있다.
- **FR-PROJ-05 [중요]** **최소 작업 공수(일)** 기준(`minWorkEffortDays`)으로 WBS 세분화를 참고한다.
- **FR-PROJ-06 [중요]** **공수 단위**(`workEffortUnit`: 분/시간/일/주)를 프로젝트별로 둔다. 스케줄링은 MD로 환산(8h=1MD, 1주=5영업일).
- **FR-PROJ-07 [중요]** **항목 구분**(`projectKind`: 상품·연구·용역·유지·제품·내부·연습·개인·기타)을 둔다. **연습·개인은 소유자 본인에게만** 목록·대시보드 등에 노출한다.
- **FR-PROJ-08 [중요]** 프로젝트 저장 시 **PM 이름(`pmName`) 필수**, PO 이름(`poName`)은 선택.
- **FR-PROJ-09 [선택]** 사용자 정의 **그룹**(`projectGroups`/`groupId`)으로 프로젝트를 분류한다([ProjectGroupManagerModal](../src/components/ProjectGroupManagerModal.tsx)).
- **FR-PROJ-10 [선택]** `includeInDashboard=false`면 대시보드 집계·카드에서 제외한다.

### 구현 요구사항
- **FR-PROJ-11 [필수]** 프로젝트 페이지(`/projects`)는 카드/목록으로 CRUD·공유·삭제·복사를 제공한다([ProjectsPage](../src/components/ProjectsPage.tsx)).
- **FR-PROJ-12 [필수]** 주간보고용 메타(`reportCategory·reportAgency·reportBudgetThisYear·reportTotalPeriod·reportNameShort·reportNameFull`)를 프로젝트에 저장한다.

## 6. 작업(WBS) 트리 (FR-WBS)

### 기능 요구사항
- **FR-WBS-01 [필수]** 작업은 **트리(상위·하위)** 구조이며, 레벨별 접두 규칙으로 WBS 번호를 부여한다(기본 L1 `W`, L2 `W`, L3 `T`, maxLevel 4 — 환경설정에서 변경).
- **FR-WBS-02 [필수]** 작업 속성: 이름·시작/종료일·진행률·담당자·상태·공수·설명·산출물·체크리스트.
- **FR-WBS-03 [필수]** 작업 **추가·삭제**, **들여쓰기/내어쓰기**, **위/아래 이동·드래그**로 순서·계층을 변경할 수 있다.
- **FR-WBS-04 [중요]** 여러 작업을 선택해 **일괄** 들여쓰기/내어쓰기·속성 반영(안전한 경우)을 할 수 있다.
- **FR-WBS-05 [중요]** **마일스톤**(시점)·**이슈**·**액션 항목** 플래그를 켤 수 있다.
- **FR-WBS-06 [중요]** **베이스라인**(기준 시작/종료/공수)을 저장하고 현재 일정과 차이를 비교할 수 있다.
- **FR-WBS-07 [중요]** **사용자 정의 컬럼**(`customColumns`/`customFields`)을 추가해 작업별 값을 입력할 수 있다.
- **FR-WBS-08 [중요]** 사용자가 직접 수정한 필드는 `userLockedFields`로 잠겨 **자동 재계산이 덮어쓰지 않는다**(dependencies/startDate/endDate/workEffort/progress).

### 구현 요구사항
- **FR-WBS-09 [필수]** 트리 조작은 `useTaskMovement`(indent/outdent/move)·`useWbsDragDrop`·`useWbsBulkEdit`·`useWbsSelection` 훅으로 구현한다.
- **FR-WBS-10 [필수]** 우클릭 컨텍스트 메뉴([ContextMenu](../src/components/ContextMenu.tsx))로 추가/삭제/복사/붙여넣기/들여·내어쓰기 등을 제공한다.

## 7. 일정 자동 산정·의존성·캘린더 (FR-SCHED)

> 핵심 로직: [`lib/schedule.ts`](../src/lib/schedule.ts), [`lib/calendar.ts`](../src/lib/calendar.ts), [`lib/projectTaskSchedule.ts`](../src/lib/projectTaskSchedule.ts)

- **FR-SCHED-01 [필수]** **영업일·한국 휴일**을 반영해 공수→종료일을 산정한다.
- **FR-SCHED-02 [필수]** **선행 작업(Finish-to-Start) 의존성**을 지정하면 후행 일정이 자동 조정된다.
- **FR-SCHED-03 [필수]** **순환 의존성**은 차단한다.
- **FR-SCHED-04 [필수]** 작업 일정은 소속 **프로젝트 기간 범위를 벗어날 수 없다**(FR-PROJ-03과 연동).
- **FR-SCHED-05 [중요]** 선행 관계에 맞춰 **프로젝트 전체 일정을 한 번에 재계산**할 수 있다.
- **FR-SCHED-06 [중요]** 부모 작업 일정은 자식 일정으로 일관성 유지(`syncParentRollups`).
- **FR-SCHED-07 [중요]** 자동 산정 시 `userLockedFields`에 지정된 필드는 보존한다(FR-WBS-08).

## 8. 상태·진척도·가중치·롤업 (FR-STATUS)

> 로직: [`lib/rollups.ts`](../src/lib/rollups.ts), [`lib/statusColor.ts`](../src/lib/statusColor.ts)

- **FR-STATUS-01 [필수]** 상태(`statusConfigs`)는 id·이름·색·해당 상태의 진척도(%)로 정의한다. 기본 4종: 할 일(0)·진행 중(10)·지연됨(50)·완료(100).
- **FR-STATUS-02 [중요]** **상태↔진척도 연동**(`linkStatusAndProgress`)을 켜면 상태 변경 시 진척도가 맞춰지고, 기존 작업 진척도를 상태에 맞게 **일괄 정렬**할 수 있다.
- **FR-STATUS-03 [필수]** 부모 작업의 상태·진척도는 **자식 롤업으로 자동 산정**한다. 단 `progress`가 잠긴 부모는 롤업으로 덮어쓰지 않는다.
- **FR-STATUS-04 [중요]** **가중치(`weight`, 소수 1자리)**가 지정되면 상위·요약 진척률을 **가중평균**으로 계산한다(미지정 시 공수 기준). 형제 합이 100일 필요는 없다.
- **FR-STATUS-05 [중요]** 담당자 일괄 변경 등은 하위로 **자동 캐스케이드**한다.

### 8.1 계획율·계획 대비 진척 차이 (FR-STATUS-06~09)

> **요구사항 취지:** "오늘 일정상 이뤄져 있어야 할 진척(**계획율**)"과 "실제 진척과의 **차이**(앞섬/지연 정도)"를 작업·프로젝트·전체 단위로 알 수 있어야 한다.
>
> **현재 상태: 구현됨.** 계산 정본은 [`lib/plannedProgress.ts`](../src/lib/plannedProgress.ts)(단위 테스트 [`__tests__/plannedProgress.test.ts`](../src/lib/__tests__/plannedProgress.test.ts)). 노출: 표 컬럼 "계획(%)·차이(%p)"([WBSTable](../src/components/WBSTable.tsx)·[SortableTaskRow](../src/components/SortableTaskRow.tsx)), 표 요약 바 "전체 계획율·계획대비" 칩([SummaryBar](../src/components/WBSTable/SummaryBar.tsx)·[useWbsSummaryStats](../src/components/hooks/useWbsSummaryStats.ts)), 대시보드 프로젝트 카드 "계획·차이" 줄([Dashboard](../src/components/Dashboard.tsx)). 번다운(작업 수)·베이스라인(일정·공수)과는 **별개의 % 기반 지표**다.

- **FR-STATUS-06 [중요] 계획율(계획 진척률) 산정**
  - 기준일 `D`(기본 오늘)에 대한 작업 계획율 = 일정상 경과 비율.
    - `D ≤ 시작일` → **0%**, `D ≥ 종료일` → **100%**, 그 사이 → `(시작일~D 영업일) / (시작일~종료일 영업일) × 100`.
  - 영업일·휴일 기준은 일정 산정과 동일하게 적용한다(FR-SCHED-01, [calendar.ts](../src/lib/calendar.ts)). 단순화가 필요하면 달력일 선형 보간도 허용.
  - 기준 일정은 **베이스라인이 설정된 경우 베이스라인**(`baselineStartDate`/`baselineEndDate`)을, 없으면 현재 계획 일정(`startDate`/`endDate`)을 사용한다(베이스라인 연동, FR-WBS-06).
  - 마일스톤(시점) 작업은 `D ≥ 시점`이면 100%, 아니면 0%로 본다.
- **FR-STATUS-07 [중요] 롤업 계획율**
  - 상위·요약·프로젝트·전체의 계획율은 리프 작업 계획율을 **가중치(`weight`) 또는 공수(`workEffort`) 가중평균**으로 집계한다(실제 진척 롤업 FR-STATUS-03·FR-STATUS-04과 **동일한 가중 기준** 사용).
- **FR-STATUS-08 [중요] 계획 대비 진척 차이(일정 변동)**
  - `진척차이(%p) = 실제 진척율 − 계획율`.
    - 양수(+) = 계획보다 **앞섬**, 음수(−) = 계획 대비 **지연**, 0 = 정상.
  - 작업·프로젝트·전체 단위로 제공하고, 부호에 따라 색으로 구분한다(앞섬/정상 = 정상색, 지연 = 경고색 — 상태 색 규칙과 정합).
- **FR-STATUS-09 [중요] 노출 위치**
  - **표 뷰:** 선택형 컬럼 **"계획율(%)"**, **"진척차이(%p)"** 추가(표시/숨김·열 너비 설정 대상, FR-SET-03·FR-VIEW-11).
  - **대시보드:** 프로젝트별·전체의 계획율/실제/차이 요약과 **지연(음수) 프로젝트 강조·정렬**(FR-VIEW-01).
  - **간트(선택):** 막대 위에 오늘 기준 계획율 마커(기대 진척 위치)를 표시한다(FR-VIEW-06).
  - **주간보고(선택):** 요약 텍스트에 계획 대비 진척 차이를 포함할 수 있다(FR-REPORT-03).
  - 기준일 `D`는 기본 오늘이되, 가능하면 사용자가 변경할 수 있도록 한다.

- **NFR-07 [필수]** 새로고침 후에도 작업 중이던 데이터가 유지된다(FR-SYNC-05).
- **NFR-08 [필수]** 로고·푸터(라이선스·버전) 등 브랜딩 영역을 둔다.
- **NFR-09 [중요]** 대량 작업(가상 스크롤·배치 upsert 200건)에서도 반응성을 유지한다.

## 20. 외부 인터페이스 요구사항 (IFR)

- **IFR-01 [필수]** Supabase JS 클라이언트로 `projects·tasks·wbs_settings·project_members·project_invites·project_access_requests·wbs_audit_log·profiles` CRUD 및 RPC를 호출한다([lib/db/](../src/lib/db/)).
- **IFR-02 [필수]** Edge Function `admin-delete-user`(Deno): POST + `Authorization: Bearer <JWT>`, body `{userId, wbsAdminPassword?}`, 성공 `{ok:true}`.
- **IFR-03 [필수]** Excel I/O는 `xlsx` 라이브러리, 한글 헤더 매핑(WBS번호·작업명·시작일·종료일·진행률·담당자·상태·선행작업·작업공수·산출물 등), 날짜는 ISO 또는 Excel 시리얼.
- **IFR-04 [필수]** 환경 변수: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_ENABLE_PRESENCE`(클라이언트); `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WBS_ADMIN_PASSWORD`(Edge).

- ~~**OUT-03** 계획율·계획 대비 진척 차이~~ → **구현 완료**(FR-STATUS-06~09, §8.1 참조). 계산 [`lib/plannedProgress.ts`](../src/lib/plannedProgress.ts), 표 컬럼·요약 바·대시보드 카드에 노출. 간트 마커·주간보고 포함은 선택 항목으로 향후 확장 여지.
