## 1. 개요

WBS(Work Breakdown Structure) 기반 프로젝트 관리 도구. 단일 페이지 React 앱이며 Supabase를 백엔드로 쓰고, 동시에 로컬(IndexedDB/localStorage)에도 저장해 오프라인에서도 동작합니다. Yjs + Supabase Realtime으로 다중 사용자 동시 편집을 지원합니다.

### 주요 기능
- WBS 표 (편집·드래그·키보드 단축키 77개)
- 간트 차트 (드래그로 일정 조정·의존성·크리티컬 패스)
- 마인드맵 / 칸반 / 대시보드 / 투입현황 / 베이스라인 비교
- 엑셀·JSON·Markdown 내보내기/가져오기
- AI(Gemini) 분석으로 WBS 자동 생성
- 주간보고 자동 생성
- 프로젝트 공유 + 권한 관리(관리자/소유자/편집자/뷰어)
- 변경 이력(감사 로그) + 실시간 알림

## 8. 주요 데이터 흐름

### 8.1 작업 수정 → DB 저장
```
사용자 입력
  → updateTask() (useTaskOps)
  → setAllTasks(prev => ...)
  → bumpDirty() → collabPushNonce++
  → [500ms 디바운스]
  → pushChangesToDb('all') (WBSContext)
  → upsertTasks() (lib/db/tasks.ts)
  → Supabase postgres_changes
  → 다른 사용자에게 Realtime 전파
```

### 8.2 로컬 저장 (오프라인 대응)
```
allTasks/projects/wbsSettings/deletedTaskIds/deletedProjectIds 변경
  → [1초 디바운스]
  → Promise.allSettled([
      saveJsonWithIdbFallback('wbs-projects', ...),
      saveJsonWithIdbFallback('wbs-tasks', ...),
      saveJsonWithIdbFallback('wbs-settings', ...),
      saveJsonWithIdbFallback('wbs-deleted-task-ids', ...),
      saveJsonWithIdbFallback('wbs-deleted-project-ids', ...),
    ])
  → localStorage.setItem 시도 (1차)
  → throw 시(보통 QuotaExceededError·시크릿 모드 등) IndexedDB 폴백
  → 둘 다 실패하면 used: 'none' (DEV 환경에서 console.warn)
```

별도 저장 키:
- UI: `wbs.lastExportPrefs`, `wbs.split.wbsTableWidth`, `wbs:gantt:sidebarWidth`, `wbs-theme-mode`(FOUC 방지용 React 로드 전 읽음)
- 클립보드: `wbs-task-clipboard-v1`
- 레벨 색: `wbs-level-colors`
- AI: `gemini-api-key`, `wbs-correction-prompt`
- 안내 본 적: `wbs.toast.tipSeen.*`
- 칸반 정렬: `wbs-kanban-order-v1-*`
- sessionStorage: `wbs-admin-override`, `wbs-current-project`, `wbs-visit-session-id`

### 8.3 초기 로딩
```
페이지 로드
  → index.html 인라인 스크립트 (다크모드 즉시 적용)
  → React 마운트
  → WBSProvider
    → 로컬 설정 읽기 (favoriteProjectIds, themeMode 보존)
    → Supabase DB에서 프로젝트/작업/설정 로드
    → 로컬과 머지 (DB 우선, 로컬 전용 필드 보존)
    → Realtime 구독 시작
```

### 8.4 실시간 협업 (TaskModal 본문)
```
사용자 A 타이핑 → Yjs 문서 업데이트
  → yjsSupabaseProvider가 변경분을 인코딩
  → Supabase Realtime broadcast
  → 사용자 B Yjs 문서에 머지
  → TipTap 에디터에 반영 (커서 위치도 표시)
```

## 9. 권한 모델 (2계층)

[AppWithProviders](../src/App.tsx)에서 계산되어 [WBSProvider](../src/context/WBSContext.tsx)·[AppHeader.tsx](../src/components/AppHeader.tsx)·[ProjectsPage.tsx](../src/components/ProjectsPage.tsx)·[ShareModal.tsx](../src/components/ShareModal.tsx) 등으로 전파됩니다.

| 계층 | 가드 | 해당 기능 |
|---|---|---|
| **시스템 관리자** | `effectiveIsAdmin = isAdmin \|\| adminOverride` | 회원 관리/승인, 모든 프로젝트의 감사 로그, 전체 백업/복원, 데이터 리셋, 전체 삭제, 다른 사용자 프로젝트 수정/삭제, 관리자 비밀번호 모달 |
| **프로젝트 소유자(만든 사람)** | `canEditCurrentProject` (소유자) | 본인이 만든 프로젝트의 작업 CRUD, 들여쓰기/이동, 일정 편집, 엑셀 가져오기, 프로젝트 설정/공유, AI 분석 적용, 해당 프로젝트 감사 로그 |
| **그 외 (뷰어)** | 로그인만 됨 | 보기 전환, 필터, 검색, 엑셀·JSON **내보내기**, 주간보고 조회, 알림. 다른 사람 프로젝트는 **읽기 전용** (editor 멤버여도 동일) |

### 권한 헬퍼 (UI 게이팅)
- `canManageProject(p)` = `canEditProject(p)` = `effectiveIsAdmin || ownerId === user.id` — 프로젝트 수정/공유/삭제, 작업 CRUD 모두 동일
- `canEditCurrentProject` (WBSContext): 현재 보고 있는 프로젝트의 편집 권한 = `isAdmin || (currentProject.ownerId === user.id)`

> ⚠️ UI 가드는 보조이고 **실제 시행은 Supabase RLS**가 담당. RLS 정책도 owner 기준으로 동일하게 시행됨([RESTORE_OWNER_BASED_POLICIES.sql](../supabase/migrations/RESTORE_OWNER_BASED_POLICIES.sql)). 서버에서 막히면 `pushChangesToDb`가 에러를 반환하고 토스트로 표시됨.

> 변경 이력: 이전에는 editor 멤버도 수정 가능했지만, 정책 단순화를 위해 "프로젝트는 만든 사람만 수정"으로 통일했습니다. `getMyEditableProjectIds()` RPC와 `editableProjectIds` prop은 호환성을 위해 남아 있지만 UI 게이팅에는 더 이상 사용되지 않습니다.

## 11. Supabase

### Migrations (48개)
[supabase/migrations/](../supabase/migrations/) — 일자별 SQL 마이그레이션. 주요:
- `20250307000000_initial_schema.sql` — 초기 스키마 (projects, tasks, settings)
- `20250310000000_add_auth_and_sharing.sql` — RLS, 멤버 테이블, 초대 토큰
- `20250310010000_add_profiles_and_admin.sql` — profiles 테이블 + is_admin
- `20250312010000_add_profiles_approved.sql` — approved 컬럼 (관리자 승인)
- `20250312110000_add_wbs_audit_log.sql` — 감사 로그
- `20260313100000_approved_users_see_all_projects_and_access_requests.sql` — 승인 사용자 전체 조회

### Edge Functions
| 함수 | 역할 |
|---|---|
| `admin-delete-user` | 관리자가 회원을 완전 삭제. `WBS_ADMIN_PASSWORD` 환경변수로 비밀번호 검증 |

### RLS
- profiles: 본인 + (승인된 사용자는 다른 프로필도 조회 가능)
- projects: 소유자 + 멤버 + 관리자
- tasks: 부모 프로젝트 권한을 따라감
- audit_log: 프로젝트 멤버 + 관리자
