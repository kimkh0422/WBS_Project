| 항목 | 값 |
|---|---|
| 문서 버전 | v0.4.144 (2026-05-07) |

## 0. 표기·용어 약속

| 표기 | 의미 |
|---|---|
| `[FD-XXX-NN]` | 기능 ID. 검토·QA·이슈 트래킹에서 사용 |
| `effectiveIsAdmin` | UI 게이팅용 관리자 판정. **회원 체험 모드** 반영 |
| `RLS` | PostgreSQL Row Level Security |
| `MD` | Man-Day. 1인 1일 작업량(8시간 = 1MD, 1주 = 5영업일 MD) |
| `FS` | Finish-to-Start. 선행작업 종료 → 후행작업 시작 |
| `WBS` | Work Breakdown Structure. 작업 분해 구조(트리) |

| 용어 | 정의 |
|---|---|
| **소유자(owner)** | 프로젝트를 만든 사람. 모든 권한 보유 |
| **편집자(editor)** | 프로젝트의 작업을 추가·수정·삭제 가능 |
| **보기 권한(viewer)** | 프로젝트 내용 조회만 가능 |
| **승인 회원(approved)** | 관리자가 승인한 회원. 모든 프로젝트 조회 가능(편집은 별도 권한) |
| **관리자(admin)** | `profiles.is_admin = true`. 전역 관리 권한 |
| **조직 책임자** | `profiles.managed_org_node_id` 지정. 본인 산하 부서 회원만 관리 가능 |
| **회원 체험 모드** | 관리자가 일반 회원 시점으로 화면을 보는 임시 모드 (sessionStorage) |
| **잠금 필드** | `userLockedFields`. 자동 재계산·AI 분석에서 제외할 필드 표시 |

## 1. 제품·아키텍처 개요

### 1.1 제품 정의

| 항목 | 내용 |
|---|---|
| 제품명 | 지엠티 프로젝트 매니저 |
| 표시 제목 | 환경설정에서 변경 가능 (`wbs_settings.app_title`) |
| 주요 사용자 | PM, 팀 리더, 팀원, 관리자, 조직 책임자 |
| 언어 | 한국어 (단축키 안내·설정·메뉴 모두 한국어) |
| 접근 방식 | 웹 브라우저 (반응형) — 데스크톱 우선, 모바일 보조 지원 |
| 배포 모델 | 정적 호스팅 (Vercel) + Supabase 백엔드 |

### 1.2 핵심 가치

1. **여러 프로젝트 통합 관리**: 한 사용자가 보고/편집할 수 있는 모든 프로젝트를 하나의 표·간트에서 본다.
2. **권한 일관성**: UI 가시성과 DB RLS가 일치 — `effectiveIsAdmin` 단일 게이트로 모든 관리자 전용 기능을 제어.
3. **빠른 입력**: Excel/스프레드시트 패턴(2단계 클릭, F2 편집, Tab 연속편집, Enter 새 행).
4. **자동화**: 일정 자동 산정(의존성·휴일), 진척도 롤업, 가중치 재분배, AI 보조.
5. **실시간 협업**: 같은 프로젝트를 여는 다른 사용자와 동시 편집 표시(Presence).

### 1.3 기술 스택

### 2.2 핵심 엔티티 상세

#### `tasks` (작업)

| 필드 | 타입 | 설명 | 자동 갱신 |
|---|---|---|---|
| `id` | uuid | PK | — |
| `project_id` | uuid | FK projects | — |
| `parent_id` | uuid? | FK tasks (트리) | indent/outdent로 변경 |
| `name` | text | 작업명 | — |
| `start_date` | date | 시작일 | 의존성·롤업 |
| `end_date` | date | 종료일 | 공수·의존성·롤업 |
| `progress` | numeric | 진척률 0~100 | 상태·자식 롤업 (잠금 시 제외) |
| `weight` | numeric? | 가중치 (소수 1자리) | 부모 입력 시 자식 비율 재분배 |
| `work_effort` | numeric? | 공수 (프로젝트 단위) | — |
| `assignee` | text | 담당자명 (콤마 구분 가능) | 일괄 변경 시 하위 자동 캐스케이드 |
| `status` | text | statusConfigs.id 매칭 | 자식 상태 기반 자동 |
| `dependencies` | uuid[] | 선행작업 ID 배열 | — |
| `description` | text? | 설명 | AI 분석 |
| `checklist` | jsonb | `[{id, text, completed}]` | — |
| `deliverables` | text? | 산출물 | — |
| `user_locked_fields` | text[]? | 자동 재계산 제외 필드 | 사용자 직접 편집 시 자동 추가 |
| `is_milestone` | bool | 마일스톤 여부 | — |
| `is_issue` | bool | 이슈 강조 | — |
| `baseline_start_date` | date? | 기준선 시작 | "베이스라인 설정" 액션 |
| `baseline_end_date` | date? | 기준선 종료 | 〃 |
| `baseline_work_effort` | numeric? | 기준선 공수 | 〃 |
| `custom_fields` | jsonb | `{[colId]: value}` | 사용자 정의 컬럼 값 |
| `sort_order` | int | 형제 사이 순서 | indent/outdent/move |

## 3. 권한 모델

### 3.1 사용자 종류

| 종류 | 식별 | 일반 권한 |
|---|---|---|
| **시스템 관리자** | `profiles.is_admin = true` | 모든 프로젝트·회원·설정 관리 |
| **조직 책임자** | `profiles.managed_org_node_id` 지정 | 본인 산하 조직 회원 관리 + 일반 회원 권한 |
| **승인 회원** | `profiles.approved = true` | 모든 프로젝트 조회 가능, 편집은 별도 권한 필요 |
| **미승인 회원** | 기본값 | 본인 소유·멤버 프로젝트만 조회 |
| **관리자 비밀번호 모드** | `adminOverride` (sessionStorage) | 임시 관리자 권한, 새 탭/세션 종료 시 해제 |
| **회원 체험 모드** | `memberPreview` (sessionStorage) | 관리자가 일반 회원 시점으로 화면 보기 |

### 3.2 프로젝트 멤버 역할

| 역할 | 설명 |
|---|---|
| **owner** | 프로젝트 생성자. 모든 편집·공유·삭제·이력 조회 |
| **editor** | 작업 추가·수정·삭제, 일정 변경, AI 분석 |
| **viewer** | 표·간트 조회만. 본인 작업의 진척도 입력은 일부 허용 |

### 3.3 권한 게이팅 — 클라이언트 단일 진입점

```ts
// App.tsx
const effectiveIsAdmin = (isAdmin || adminOverride) && !memberPreview;
```

이 단일 변수로 다음을 모두 게이팅:
- 헤더 더보기 메뉴의 "관리자 기능" 섹션
- 회원 관리, 변경 이력, 마인드맵, 투입현황, AI 분석 진입
- 환경설정의 전역 설정(웹 타이틀·WBS prefix·표 컬럼·상태/진척도·색상)
- 대시보드의 클라이언트측 프로젝트 필터(false면 본인 참여 프로젝트만)
- 헤더 v버전 / 푸터 변경이력 진입 메뉴

> **컨벤션**: 새 관리자 전용 기능을 추가할 때 반드시 `effectiveIsAdmin`만 보면 자동으로 모든 모드(회원 체험 포함)에 적용됨. 직접 `isAdmin`이나 DB 플래그를 분기 조건으로 쓰지 말 것.

### 3.4 프로젝트별 편집 권한

```ts
// WBSContext.canEditCurrentProject
const canEditCurrentProject = (() => {
  if (!currentProjectId || currentProjectId === 'all') return false;
  if (isAdmin) return true;             // 관리자는 모든 프로젝트
  return currentProject.ownerId === user.id;  // 본인이 만든 프로젝트
})();
```

> 멤버(editor)도 편집 가능하지만 RLS와 일치를 위해 컨텍스트는 owner/admin 기준만 사용. UI는 멤버일 때 별도 분기.

### 3.5 서버측 권한 — RLS

| 테이블 | SELECT | INSERT/UPDATE/DELETE |
|---|---|---|
| `projects` | 본인 소유 + 멤버 + 관리자 | 본인 소유 + 관리자 (편집/삭제는 editor 멤버 추가) |
| `tasks` | 프로젝트 SELECT 가능자 | 프로젝트 INSERT/UPDATE 가능자 |
| `profiles` | 본인 + 관리자 + 승인 회원(공유 표시명용) + 프로젝트 소유자(공유 멤버 표시) | 본인(`profiles_update_own`) + 관리자 |
| `wbs_settings` | 모든 인증 사용자 | 모든 인증 사용자 (단일 전역 설정) |
| `wbs_audit_log` | 본인 소유/멤버 프로젝트 + 관리자(`is_admin_user()`) | 인증 사용자 |
| `project_members` | 본인 멤버십 + 프로젝트 소유자 + 관리자 | 프로젝트 소유자 + 관리자 |
| `org_nodes` / `org_members` | 인증 사용자 | 관리자 + 조직 책임자 |

`public.is_admin_user()` 함수: `EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND is_admin = true)`. RLS 재귀 회피를 위해 `SECURITY DEFINER`로 정의.

## 4. 인증·회원·승인

### 4.1 회원가입·로그인

| ID | 기능 | 설명 |
|---|---|---|
| FD-AUTH-01 | 이메일/비밀번호 가입 | 회사 도메인 제한(`@gmtc.kr`)·OTP 인증 |
| FD-AUTH-02 | OAuth 가입/로그인 | Google·GitHub (선택) |
| FD-AUTH-03 | 비밀번호 재설정 | 이메일 링크 재설정 |
| FD-AUTH-04 | 세션 관리 | Supabase JWT 자동 갱신 |
| FD-AUTH-05 | 로그아웃 | 헤더 사용자 메뉴 |

### 4.2 회원 승인 흐름

1. 가입 직후: `approved` 기본값 — 환경 마이그레이션에 따라 true 또는 false
2. 승인된 회원: 모든 프로젝트 조회 가능 (RLS의 `approved_users_see_all_*` 정책)
3. 미승인 회원: 본인 소유 프로젝트만 조회
4. 관리자 / 조직 책임자가 회원 관리 모달에서 토글

### 4.3 자동 프로필 생성 — `ensure_profile()` RPC

로그인 시 자동 호출. `auth.users`에는 있지만 `profiles`에 행이 없는 경우 자동으로 생성. 첫 가입자(맨 처음 사용자)는 자동으로 `is_admin = true` 지정.

### 4.4 관리자 비밀번호 모드 (`adminOverride`)

- Shift+F12 → `AdminPasswordModal` → 비밀번호 입력 → `adminOverride = true` (sessionStorage `wbs-admin-override`)
- 임시로 관리자 권한이 부여되어 회원 관리·계정 삭제 등 가능
- 새 탭/브라우저 종료 시 자동 해제
- 비밀번호는 `src/constants/adminBypass.ts`의 `WBS_ADMIN_PASSWORD` 상수
- 비밀번호 검증이 필요한 회원 삭제 등은 Edge Function에 비밀번호도 함께 전달

### 6.4 작업 일정 범위 제한

- 작업의 `startDate` / `endDate`는 프로젝트의 `start_date` ~ `end_date` 범위를 벗어날 수 없음

### 6.5 공수 단위 (`work_effort_unit`)

| 단위 | 표시 | 환산 |
|---|---|---|
| `minute` | 분 | 1MD = 480m |
| `hour` | 시간 | 1MD = 8h |
| `day` (기본) | 일 | 1MD = 1d |
| `week` | 주 | 1MD = 1/5w |

스케줄링은 항상 MD로 환산. 작업의 `workEffort` 저장값은 프로젝트 단위 그대로.

## 7. 작업(WBS) 트리

### 7.1 WBS 번호

- 자동 계산: `level1Prefix` + 숫자 (`P1`, `P1.1`, `P1.1.1`)
- `wbsMap`(저장용 ID), `displayWbsMap`(사용자 정의 prefix 적용 표시용)
- 정렬·필터 시에도 트리 구조 유지

### 7.2 트리 조작

| 액션 | 단축키 | 동작 |
|---|---|---|
| 들여쓰기 | `Tab` | 직전 형제의 자식이 됨 (parentId 변경) |
| 내어쓰기 | `Shift+Tab` | 부모의 형제가 됨 |
| 위로 이동 | `Alt+↑` | 같은 부모 내에서 sort_order 교환 |
| 아래로 이동 | `Alt+↓` | 〃 |
| 펼치기/접기 (행) | `Shift+→` / `Shift+←` | 트리 토글 |
| 펼치기 (전체 N 레벨) | `Ctrl+Alt+1~9` | 1~9 레벨로 펼침 |

> **제한**: WBS 정렬·필터가 켜져 있으면 indent/outdent/move 비활성화 (트리 표시 순서와 충돌 방지).

### 7.3 다중 선택 일괄 액션

- Space: 체크박스 토글
- 체크 2개 이상: 하단 일괄 수정 바 표시
- 일괄 변경 가능 항목: 상태, 담당자(하위 캐스케이드), 공수, 진척율, 가중치, 시작일, 완료일
- 일괄 액션 버튼:
  - **선행 순차 연결**: 표시 순서대로 위→아래 행을 선행작업으로 연결
  - **선행작업 지우기**: 선택 작업의 모든 의존성 제거 + `userLockedFields.dependencies` 추가
  - **삭제**: 선택 작업 일괄 삭제 (확인 다이얼로그)

### 7.4 컨텍스트 메뉴 (우클릭)

| 항목 | 설명 |
|---|---|
| 새 작업 추가 | 위/아래/하위에 새 형제 또는 자식 추가 |
| 복사 / 잘라내기 / 붙여넣기 | localStorage 클립보드 (Ctrl+C/X/V와 동일) |
| 들여쓰기 / 내어쓰기 | Tab / Shift+Tab과 동일 |
| 마일스톤 토글 | `is_milestone` |
| 이슈 토글 | `is_issue` 강조 |
| 베이스라인 설정/해제 | 현재 일정·공수를 baseline에 스냅샷 |
| 선행 순차 연결 | 2개 이상 선택 시 노출 |
| 삭제 | 작업 삭제 (확인) |

### 7.5 사용자 정의 컬럼

- 환경설정 → 표 컬럼 → "컬럼 추가" 버튼 (모든 회원 가능, v0.4.142~)
- ID 형식: `custom:<timestamp>`
- 데이터 저장: `tasks.custom_fields` JSONB → `{[colId]: "셀 텍스트"}`
- 표시명: `wbs_settings.config_json.customColumns[].name`
- **모든 사용자에게 공유**되며, 비관리자에게는 안내 문구 표시

## 8. 일정 자동 산정·의존성·캘린더

### 8.1 영업일·휴일

- `lib/calendar.ts`에서 한국 공휴일 자동 계산 (음력·임시 공휴일 포함)
- 주말 + 공휴일 = 휴일로 간주
- `getHolidaysForTaskDates(tasks)`로 작업 일정 범위에 해당하는 휴일만 캐싱

### 8.2 공수 → 종료일 산정

```
endDate = computeEndDateFromEffort(startDate, effortMD, assignments, holidays)
```

- 시작일에서 영업일 수만큼 진행
- `assignments`(투입율) 적용: 투입율 50% → 작업 기간 2배
- 휴일 제외하며 누적

### 8.3 의존성(dependencies) — Finish-to-Start

- 후행 작업의 `startDate` ≥ 선행 작업의 `endDate + 1 영업일`
- 후행 작업의 종료일은 공수 기준 자동 산정
- `applyDependencySchedule(tasks, projectAssignments, excludeIds)`:
  1. 모든 작업을 위상 정렬
  2. 각 작업의 `startDate` = max(선행작업.endDate + 1 영업일)
  3. `userLockedFields`에 startDate/endDate가 있는 작업은 자동 이동 제외
  4. 같은 담당자 후행 작업만 자동 시프트(부하 균형)

### 8.4 순환 의존성 차단

`hasDependencyCycle(tasks, taskId, newDeps)` — DFS로 사이클 감지. 발견 시 토스트 경고 + 변경 거부.

### 8.5 자동 일정 동기화 트리거

다음 변경 시 자동 재스케줄:
- 작업 시작/종료일 변경
- 작업 공수 변경
- 의존성 추가/제거
- 프로젝트 일정 변경 (작업 클램프)

### 8.6 부모 일정 일관성 — `syncParentRollups`

자식 일정 변경 시:
```
parent.startDate = min(children.startDate)
parent.endDate   = max(children.endDate)
```

- `userLockedFields`의 startDate/endDate는 무시하고 항상 동기화 (롤업과 자동 재스케줄은 다른 개념)
- 재귀적으로 조상까지 전파

## 9. 상태·진척도·가중치·롤업

### 9.1 상태 정의 (`status_configs`)

```json
[
  { "id": "todo", "name": "시작 전", "color": "bg-stone-100 ...", "progress": 0 },
  { "id": "doing", "name": "진행 중", "color": "bg-blue-50 ...", "progress": 50 },
  { "id": "done", "name": "완료", "color": "bg-emerald-50 ...", "progress": 100 }
]
```

- 환경설정에서 추가/이름·색·진척도 변경 (관리자만)
- 색상 프리셋 + 사용자 정의 HEX (#RRGGBB)
- 진척도 0~100 정수

### 9.2 상태 ↔ 진척도 연동 (`linkStatusAndProgress`)

- true: 상태 변경 시 진척도 자동 설정
- false: 상태 변경해도 진척도 그대로 (수동 입력)
- 환경설정 → 상태/진척도 탭에서 토글

### 9.3 부모 상태·진척도 자동 산정 — `syncParentStatus` / `syncParentRollups`

자식들의 상태를 보고 부모 상태 도출:
- 자식 모두 완료(progress=100) → 부모 완료 상태
- 일부 완료/진행 → 부모 진행 중 상태 (가장 작은 progress의 진행 중 상태 우선)
- 자식 모두 시작 전(progress=0) → 부모 시작 전 상태

진척률 가중평균:
```
parent.progress = Σ(child.progress × weight) / Σ(weight)
weight = child.weight ?? child.workEffort ?? 0
```

- weight 합 0이면 단순 평균 fallback
- 부모 진척률을 `userLockedFields.progress`에 잠갔다면 자식 변경에도 자동 롤업 안 됨 (수동 편집 보존)
- 강제 롤업 옵션(`forceProgress=true`): 자식 변경 전파 시에는 잠금 무시

### 9.4 가중치 — 소수 1자리

- 표시·저장 모두 1자리(`formatNum1`/`round1`)
- 부모 weight 직접 입력 시 자식 비율 유지 자동 재분배 (`redistributeWeightsDown`)
- 부모 progress 직접 입력 시 자식들에 비례 분배 (`distributeProgressDown`)

### 9.5 자동 캐스케이드

| 변경 | 캐스케이드 |
|---|---|
| 상태 변경 (linkStatusAndProgress=true) | 진척도 자동 설정 + 부모 상태/진척도 롤업 |
| 자식 추가/삭제 | 부모 일정·진척도 롤업 |
| 자식 일정 변경 | 부모 시작/종료 동기화 |
| 자식 가중치 변경 | 부모 진척도 가중평균 재계산 |
| 부모 가중치 변경 | 자식 비율 유지 재분배 (재귀) |
| 부모 progress 직접 입력 | 자식 비례 분배 (재귀) |

### 10.3 인라인 편집 — Excel 패턴

#### 셀 클릭 (2단계)

| 단계 | 동작 |
|---|---|
| 1차: 다른 행의 셀 클릭 | 그 행 포커스 + 그 셀이 포커스 셀로 지정. **편집 시작 안 함** |
| 2차: 같은 행의 셀 클릭 (같거나 다른 셀) | 해당 셀 편집 시작 |

> 이전엔 첫 클릭으로 바로 편집됐던 동작을 두 단계로 분리. WBS ID 칸도 클릭 시 행 포커스만 잡음(첫 편집 가능 컬럼으로 셀 포커스 자동 지정).

#### 키보드

| 키 | 비편집 상태 | 편집 중 |
|---|---|---|
| `↑` / `↓` | 행 포커스 이동 (셀 포커스 동기화), tableEditMode 자동 ON | input 기본 동작 (number는 값 ±1) |
| `←` / `→` | 셀 포커스 이동. 행 끝에서 wrap | input 기본 동작 (텍스트 커서) |

| `Enter` (name 셀) | (편집 시작) | 같은 레벨 새 형제 추가 + 새 작업 이름 편집 (빠른 입력) |
| `Enter` (비-name 셀) | (편집 시작) | 값 커밋 후 같은 셀 유지 (←/→로 이동 가능) |
| `Shift+Enter` (name) | — | 위에 새 형제 추가 |
| `Shift+Enter` (비-name) | — | 다음 행 같은 컬럼으로 포커스 이동 |

| `Delete` | 선택 행(들) 삭제 | (입력 텍스트 삭제) |
| `Esc` | 편집·선택 해제 | 편집 취소 |
| `Space` | 체크박스 토글 | 입력 텍스트 |
| `Ctrl+C/X/V` | 복사/잘라내기/붙여넣기 | (입력 텍스트) |
| `Ctrl+A` | 전체 선택 | (입력 전체 선택) |

#### 편집 종료 후 ←/→ 이동

- 편집 중 ←/→는 input 커서만 이동 (의도치 않은 셀 이탈 방지)
- 셀 이동은 Enter(커밋) / Esc(취소) / Tab(연속 편집) 후에만 가능
- 행 끝에서 wrap: → at last col → 다음 행 첫 컬럼, ← at first col → 이전 행 마지막 컬럼

### 10.4 정렬 · 필터

- 컬럼 헤더 클릭 → 정렬 (WBS 기본 / 컬럼별 토글)
- 필터 바 (상단):

  - 레벨 (특정 N 레벨만)
  - 기한 지난 (`pastDueOnly`), 이번 주 완료 (`completedThisWeekOnly`)
  - 작업명/설명 텍스트 검색
- WBS 정렬·필터가 있으면 트리 모드 해제 → indent/outdent/move 비활성화

### 10.5 검색 (`SearchModal`)

- `Ctrl+K`로 모달 열기
- 작업명 / WBS / 담당자 / 설명에서 부분 검색
- 결과 클릭 시 해당 작업으로 이동·편집 시작

### 10.6 가상 스크롤

- `react-window`로 행 가상화. 수백~수천 작업도 부드럽게 스크롤

- 다른 사용자가 편집 중인 셀에 색상 ring 표시 (사용자별 색상)
- 셀 헤더에 사용자 표시 (`otherFocusByCellKey`)

### 10.8 일괄 수정 바 (다중 선택 시)

- 화면 하단에 floating bar 표시
- 입력 항목: 상태, 담당자, 공수(d), 진척율(%), 가중치, 시작일, 완료일
- 적용 버튼: 입력된 항목 모두 일괄 적용
- 별도 액션 버튼:
  - **선행 순차 연결** (2개 이상 선택 시)
  - **선행작업 지우기**
  - **삭제** (편집 가능 프로젝트만)

## 11. 작업 모달(TaskModal)

### 11.1 진입 경로

- 표 행 우클릭 → "작업 상세 편집"

- ↑↓로 항목 선택, Enter로 픽
- 마우스 클릭으로도 선택

### 11.4 잠금 필드 (`userLockedFields`)

- 사용자가 직접 편집한 필드는 자동으로 잠금 추가
- 잠금된 필드는 AI 분석·자동 재계산에서 제외
- 모달에서 시각 표시 (자물쇠 아이콘 등)

### 11.5 권한별 표시

- 보기 전용(viewer 또는 비편집): readOnly 상태로 표시
- 편집 가능: 모든 필드 활성화
- 삭제 버튼은 owner / admin만

- 비관리자: customColumns + tableColumns(자동 보강)만 저장. 기타 전역 설정은 그대로 보존

## 19. 회원 관리·회원 체험 모드

### 19.1 회원 관리 모달 (`MembersModal`)

#### 진입

- 헤더 → 더보기 → 관리자 기능 → "회원 관리"
- 표시 조건: `effectiveIsAdmin` 또는 조직 책임자

#### 표시 항목

- 이름, 이메일, 가입일, 접속횟수, 마지막 접속, 승인 여부, 역할 (회원/관리자)
- 정렬·필터 가능 (이름, 가입일 등)

#### 액션

| 액션 | 권한 |
|---|---|
| 이름 수정 | 관리자 |
| 역할 변경 (회원 ↔ 관리자) | 관리자. **본인 강등 차단** |
| 승인 토글 | 관리자 + 조직 책임자(자기 산하만) |
| 프로젝트 권한 보기/수정 | 관리자 + 조직 책임자 |
| 삭제 | 관리자. 본인 제외 일괄 삭제 옵션 (확인 문구 입력 필요) |
| 권한 요청 승인/거절 | 프로젝트 소유자 + 관리자 |

### 19.2 본인 강등 차단

- 본인 행은 정적 배지로 표시 (변경 불가)
- 마지막 관리자가 실수로 강등되어 잠기는 위험 방지
- 회원 시점 미리보기는 **회원 체험 모드**로 대체 안내

### 19.3 회원 체험 모드 (`memberPreview`)

#### 진입

- 헤더 → 더보기 → 관리자 기능 → "회원 화면 체험 시작" (관리자만)

#### 동작

- `memberPreview = true` (sessionStorage `wbs-member-preview`)
- `effectiveIsAdmin = (isAdmin || adminOverride) && !memberPreview` → false
- 모든 관리자 전용 UI 자동 숨김:
  - 대시보드 데이터 → 본인 참여 프로젝트만 (클라이언트 필터)
  - 회원 관리, 변경 이력, 마인드맵, 투입현황, AI 분석, 주간보고
  - 환경설정 전역 항목 → 보기 전용
  - 헤더 v버전 / 푸터 변경이력 진입 메뉴
- 헤더 상단에 "회원 화면 체험 중" + "관리자로 돌아가기" 배너 항상 노출
- 새로고침에도 유지 (sessionStorage)
- DB 권한은 그대로 관리자 → 데이터 일부는 자연스럽게 더 많이 보일 수 있음. 클라이언트 필터로 보완.

### 19.4 관리자 비밀번호 모드 vs 회원 체험 모드

| 비교 | 관리자 비밀번호 (`adminOverride`) | 회원 체험 (`memberPreview`) |
|---|---|---|
| 트리거 | Shift+F12 + 비밀번호 | 메뉴 클릭 |
| 효과 | 비관리자가 일시적으로 관리자 권한 획득 | 관리자가 일시적으로 비관리자 시점 |
| 식별 | sessionStorage `wbs-admin-override` | sessionStorage `wbs-member-preview` |
| 해제 | 새 탭/세션 종료 | 헤더 배너 "관리자로 돌아가기" |

## 20. 감사 로그(변경 이력)

### 20.1 기록 대상

- **작업**: 생성, 수정, 삭제, 일괄 수정
- **프로젝트**: 생성, 수정, 삭제
- 변경 필드 diff (`diffTaskFields`, `diffProjectFields`)
  - 추적 필드: name, start_date, end_date, progress, assignee, status, work_effort, description, is_milestone, is_issue (작업) / name, description, start_date, end_date (프로젝트)
- 사용자 표시명 (`user_display`), 시각

### 20.2 조회 권한 (RLS)

```sql
CREATE POLICY "wbs_audit_log_select" ON wbs_audit_log FOR SELECT
  USING (
    public.is_admin_user()
    OR project_id IN (
      SELECT id FROM projects WHERE owner_id = auth.uid()
      UNION
      SELECT project_id FROM project_members WHERE user_id = auth.uid()
    )
  );
```

| 사용자 | 범위 |
|---|---|
| 일반 회원 (소유) | 본인 프로젝트만 |
| 일반 회원 (멤버) | 자신이 멤버인 프로젝트만 |
| 관리자 | 모든 프로젝트 (v0.4.121~) |

### 20.3 진입 경로

- **프로젝트별**: 헤더 프로젝트 드롭다운 → 각 행의 ⏱ 변경 이력 버튼 (소유자/관리자)
- **전체**: 헤더 → 더보기 → 관리자 기능 → "전체 변경 이력" (관리자만, 모든 프로젝트 통합)

### 20.4 모달 표시 (`AuditLogModal`)

- 헤더: "변경 이력 — <프로젝트명>" 또는 "변경 이력 — 전체 프로젝트"
- 컬럼: 일시, 사용자, **프로젝트** (전체 모드만), 구분(작업/프로젝트), 대상, 작업(생성/수정/삭제), 변경 내용
- 최근 100건 (한도 변경 가능)
- 변경 내용은 필드명을 콤마 구분 표시

## 24. 동기화·자동 저장·실시간

### 24.1 자동 저장 (디바운스)

- 작업 변경 후 디바운스(1.5초) 뒤 자동 DB 업로드
- `dirtyEpochRef`, `bumpDirty`로 변경 시그널 추적
- 충돌 감지: `updated_at` 비교 (낙관적 잠금)
- 충돌 시 토스트 안내 + "DB 동기화" 버튼 제공

### 24.2 수동 동기화

- 헤더의 동기화 아이콘 → 강제 pull (서버 우선)
- 일괄 변경 후 즉시 반영 필요 시 사용

### 24.3 Realtime (실시간)

- Supabase Realtime 채널 구독: `tasks`, `projects`, `wbs_settings`, `project_members`
- 같은 프로젝트를 연 다른 사용자의 변경이 즉시 반영
- 토글 가능 (현재 기본 OFF — 안정성 위해; 필요 시 사용자가 켬)

### 24.4 Presence (동시 편집 표시)

- `usePresence` 훅으로 현재 보고 있는 사용자 목록 추적
- 셀 단위로 다른 사용자가 편집 중임을 색상 ring으로 표시

### 24.5 로컬 백업

- localStorage에 작업·프로젝트·설정 자동 백업
- 오프라인 임시 작업 가능 (로그인 안 된 상태에서도 사용)
- 로그인 후 DB 우선, 로컬은 백업 용도

### 24.6 Undo/Redo (`useWbsHistory`)

- 작업 단위로 이전 상태 스택 보존 (최대 50개)
- `Ctrl+Z`: 되돌리기
- `Ctrl+Y` / `Ctrl+Shift+Z`: 다시 실행
- 히스토리 변경 시 자동 DB 업로드

## 28. DB 스키마·마이그레이션·RLS

### 28.1 마이그레이션 적용 가이드

#### 신규 환경 설정

1. Supabase 프로젝트 생성
2. `supabase/migrations/FULL_SETUP_NEW_PROJECT.sql` 1회 실행 (전체 스키마 + RLS + 시드)
3. 또는 `supabase db push`로 시간순 마이그레이션 일괄 실행

- 새 마이그레이션 파일은 시간순 prefix (`YYYYMMDDHHmmss_`)

- 직접 SQL Editor에서 실행도 가능 (모든 마이그레이션은 `IF NOT EXISTS` / `IF EXISTS` 가드 → 재실행 안전)

## 30. 성능·확장성 고려

### 30.1 가상 스크롤

- `react-window`로 행 가상화 (수천 행도 부드럽게)
- 동적 행 높이 지원

### 30.2 선택적 렌더링

- `React.memo` + 비교 함수 (`areRowPropsEqual`)로 행 리렌더 최소화
- 컬럼별 독립 cell 컴포넌트

### 30.3 Lazy Loading

- 큰 모달은 `React.lazy`로 코드 분할 (TaskModal, AIAnalysisModal, ExportModal 등)
- 마인드맵·간트 등 무거운 뷰도 lazy

### 30.4 DB egress 절감

- 작업 목록 조회 시 큰 컬럼(`description`, `checklist`)은 포함하되 페이지 사이즈 1000으로 분할 fetch
- 특정 컬럼이 미존재할 경우 fallback SELECT (스키마 차이 호환)

### 30.5 Realtime 부하

- Realtime은 기본 OFF (사용자 토글)
- 활성화 시에도 디바운스 + 필요한 채널만 구독

### 30.6 Portal 활용

- 표 셀 안의 드롭다운(선행작업 검색 등)은 React `createPortal`로 body에 렌더링
- `.data-cell`의 overflow 클리핑 우회

### D.3 필터·정렬 × 트리 조작

#### D.3.1 필터 ON/OFF 영향

| 항목 | 동작 |
|------|------|
| `filterOn=false` | 필터 객체는 **메모리에 보존**, 단 `FilterBar` 자체가 미렌더 ([FilterBar.tsx:68](../src/components/FilterBar.tsx#L68)). 표시는 무필터로 동작 |

| 필터 ON에서 `Alt+↑/↓` | **차단** (동일) |

#### D.3.2 정렬 영향

| 정렬 키 | 트리 조작 | WBS 번호 표시 | sort_order DB |
|---------|:---------:|:--------------:|:--------------:|
| `wbs asc`(기본) | ✓ | ✓ | 순서 그대로 |
| 그 외(`name`, `status`, `dueDate` 등) | **차단** | 트리 들여쓰기는 유지(depth 패딩) | 변경 없음 — UI 표시만 |

> 정렬은 **저장 안 됨**. Task에 `sort_order` 컬럼 없음. 새 세션에서 다시 `wbs asc` 기본값으로 표시. 정렬은 보기 편의용 일시 도구.

#### D.3.3 비자명 시나리오

**S-D.3-1: 정렬+필터 동시 ON에서 신규 추가**
- 정렬·필터 둘 다 켜진 상태에서 Enter는 **추가는 되지만**(같은 레벨 형제) 추가된 행이 즉시 안 보일 수 있다(필터 미일치). 들여쓰기·이동만 차단된다.

**S-D.3-2: 다른 컬럼으로 정렬 후 트리 펼치기**
- 정렬 키가 `wbs`가 아니어도 `Shift+→`/`Shift+←`로 **펼치기/접기는 가능**. 트리 구조가 시각적으로 유지(depth 패딩)되므로 자식이 부모 바로 아래에 안 와도 펼침 토글은 유효.

**S-D.3-3: WBS 번호와 표시 순서 불일치**
- 정렬을 `name asc`으로 바꾸면 표시 순서가 `P1, P3, P2.1, ...`처럼 보일 수 있다. WBS 번호는 부모-자식 트리 기준으로 자동 계산되므로 **표시 순서를 바꿔도 번호는 그대로**.

**S-D.3-4: 필터 ON에서 작업 검색 점프 후**
- 검색에서 작업 선택 → `expandAncestors`로 펼침. 그러나 작업이 필터에 의해 가려지면 **펼쳤는데도 안 보이는 상태**가 된다. 이 경우 사용자는 필터를 직접 해제하거나 `filterOn=false`로 토글해야 함.

### D.5 잠금 필드 × 자동 재계산·롤업

#### D.5.1 잠금 가능 필드

#### D.5.2 비자명 시나리오

**S-D.5-1: 부모 progress 50% 잠금 + 자식 100% 완료**
- *Given*: 부모 P, `userLockedFields=['progress']`, `progress=50`. 자식 C1, C2 — C1 완료 후 C2 완료.
- *When*: C2 완료 시점.
- *Then*: 자식 변경 전파 경로(`forceProgress=true`)이면 부모 progress=100으로 갱신, 잠금 무시. 부모 단독 표시 갱신만 일어나는 경로(`forceProgress=false`)이면 50% 그대로. **현재 코드는 자식 변경 시점에 forceProgress=true를 전달하여 강제 동기화**.

**S-D.5-2: 자식 startDate 잠금 + 선행작업 종료일 변경**
- *Given*: child.userLockedFields=['startDate'], 선행 P의 endDate가 +3일.
- *Then*: child.startDate **변경 안 됨** ([schedule.ts:291](../src/lib/schedule.ts#L291) — `if (taskLocked.has('startDate')) continue`). 결과적으로 P-child 간 FS 제약 위반 가능 — 시각적 경고는 별도 표시 없음(개선 후보).

**S-D.5-3: workEffort 잠금 + 종료일 수동 변경**
- *Given*: workEffort=5MD 잠금, endDate를 수동으로 +5일 변경.
- *Then*: workEffort 자동 재산정 안 됨(잠금). 단 startDate를 endDate-5MD로 다시 계산하지도 않음(잠금이 계산 입력값을 보호). 결국 사용자가 입력한 endDate만 반영, 다른 필드 그대로.

**S-D.5-4: 부모 weight 직접 입력**
- *Given*: 부모 P weight=20 → 사용자가 30으로 변경.
- *When*: 입력 직후.
- *Then*: 형제와 합 100 보장을 위해 자동 재분배(`rescaleSiblingsToSum100`). 자식들 weight는 **비율 유지**한 채 부모 비율 변화에 맞게 스케일.

**S-D.5-5: AI 분석 결과 적용 시 잠금 보호**
- AI 분석이 startDate/endDate/workEffort/progress를 제안해도 잠금 필드는 덮어쓰지 않음. AI 결과 미리보기에서 잠금 필드는 회색 표시(예정).

**S-D.6-2: A가 작업 추가, B 화면 즉시 반영?**
- 현재 Realtime 비활성화 상태에서는 **즉시 반영 안 됨**. 5분 풀 또는 수동 동기화 시 반영. Realtime 활성화 시 broadcast 즉시 반영(로컬 변경 없으면).

**S-D.6-3: A가 셀 편집 중 B가 동기화 트리거**
- A의 로컬 변경 보존 우선. B의 동기화로 들어온 서버 값은 fingerprint 비교 후 다르면 UI 업데이트 스킵(A 화면이 깜빡 변경되지 않음). 단 A가 저장한 직후 B가 다시 동기화하면 A 변경이 서버에 반영된 상태에서 다시 받게 됨.

**S-D.6-4: Presence 환경변수 OFF**
- `VITE_ENABLE_PRESENCE=false` 빌드면 동시 사용자 표시·셀 포커스 표시 모두 미동작. 동시 편집은 여전히 LWW.

### D.7 저장 모드 (Cloud / Local-only) × CRUD

#### D.7.1 모드 정의

| 모드 | 진입 조건 | 데이터 위치 |
|------|-----------|-------------|
| Cloud | Supabase 환경변수 설정 + 로그인 + 승인 회원 | DB(Supabase) + 로컬 캐시(IndexedDB/localStorage) |
| Local-only | Supabase 환경변수 미설정 또는 비승인 / 명시적 useLocalOnly | localStorage / IndexedDB만 |

> 런타임 토글 UI는 현재 없음 — 환경변수·승인 상태로 결정.

#### D.7.2 자동 저장·동기화 매트릭스

| 항목 | Cloud 모드 | Local 모드 |
|------|-----------|-----------|
| 자동 로컬 저장 | 1000ms 디바운스 | 동일 |
| DB 동기화 트리거 | 수동 [동기화] / 5분 풀(탭 복귀) | n/a |
| Realtime broadcast | 비활성화 (현재 false) | n/a |
| 백업/복원 | DB → JSON 파일 / JSON → DB | 로컬 → JSON / JSON → 로컬 |
| Undo 스택 한계 | 50개 | 동일 |
| 프로젝트 전환 시 Undo | 보존 (전역 스택) | 동일 |

#### D.7.3 비자명 시나리오 — 손실 위험

**S-D.7-1: 자동 저장 디바운스 중 탭 닫기**
- 1000ms 디바운스 중 닫으면 마지막 변경분 일부 손실 가능. 현재 `beforeunload` 가드 없음 — 개선 후보.

**S-D.7-2: Local → Cloud 전환**
- Local에서 추가한 작업은 Cloud 모드로 전환(예: 환경변수 설정 후 재로딩) 시 **덮어쓰기로 손실**. 현재 마이그레이션 도구 없음. 사전 JSON 백업 후 복원 권장.

**S-D.7-3: 동기화 도중 네트워크 끊김**
- 업로드 부분 실패 시 롤백 메커니즘 없음(부분 반영 가능). 다운로드 실패는 catch에서 무시하고 로컬 유지. 다음 수동 [동기화]로 재시도.

**S-D.7-4: Undo 후 즉시 동기화**
- Undo는 `bumpDirty()` 호출로 `hasLocalChangesSinceSync=true` 설정. 다음 동기화에서 Undo 후 상태가 서버에 업로드. 동시 다른 사용자의 변경이 있었다면 LWW로 덮어쓸 위험 → 동기화 직전 충돌 알림은 있지만 사용자 확인 후 강행이 일반 흐름.

**S-D.7-5: 자동 저장 실패 시**
- localStorage 실패 → IndexedDB 시도 → 둘 다 실패 시 콘솔 경고만, **UI 인디케이터 없음**. 사용자는 변경 손실을 모를 수 있음. 개선 후보(저장 상태 토스트).

#### D.7.4 알려진 한계 정리

1. **Realtime 비활성화** — 현재 5분 풀에 의존. 다중 사용자가 같은 프로젝트를 활발히 편집하면 동기화 지연 체감.
2. **editor 멤버 미구현** — 역할은 있으나 `canEditCurrentProject`에서 owner/admin만 인정.
3. **'전체' 보기 + 추가 진입점 폴백** — `addTask`에서 `projects[0]`로 자동 폴백되는 경우 사용자 인지 부족(주로 마인드맵·임포트 경로).
4. **필터 ON에서 추가 시 가시성** — 추가는 되지만 필터 미일치로 즉시 사라짐, 보정 없음.
5. **TaskModal 열린 채 프로젝트 전환** — 모달 자동 닫기 없음, 데이터 정합성 위험.
6. **검색 점프 시 view 강제 변경** — 칸반/마인드맵에 있던 사용자가 표로 강제 이동.
7. **동시 편집 차단 없음** — 셀 단위 락 메커니즘 없음, LWW.
8. **자동 저장 디바운스 손실 위험** — `beforeunload` 가드 없음.
9. **Local → Cloud 전환 손실** — 마이그레이션 도구 없음.
