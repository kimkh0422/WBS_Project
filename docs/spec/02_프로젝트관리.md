## 0. 그룹 개요

### 0.1 범위

프로젝트(Project)는 작업 트리의 컨테이너이자 권한·일정·공수 단위·보고 단위의 기준이다. 본 그룹은 **프로젝트 자체의 생애주기와 메타데이터 관리**를 다룬다. 프로젝트 안의 작업 동작은 [01_작업관리](./01_작업관리.md), 일정 자동 산정 규칙은 [03_일정_상태_진척도](./03_일정_상태_진척도.md), 권한 모델은 [05_인증_권한_조직](./05_인증_권한_조직.md)에 둔다.

### 0.2 비-목표

- 작업 트리 조작 (→ FD-TM)
- 멤버 권한 부여 UI (→ FD-AUTH-010 회원 관리)
- 외부 시스템 연동 (→ FD-IO)
- 보고서 PDF 출력 (→ FD-IO-007)

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **프로젝트** | 단일 목표·기간·소유자를 가진 작업 묶음. `projects` 테이블의 1행 |
| **소유자(Owner)** | 프로젝트를 생성한 사용자. 모든 권한 보유 |
| **편집자(Editor)** | (현재 미구현) 향후 확장 — 프로젝트 데이터 편집 권한 |
| **보기 권한(Viewer)** | 프로젝트 데이터 조회만 |
| **그룹** | 여러 프로젝트의 분류 라벨. 사용자가 임의로 정의 (예: "시범사업", "유지보수") |
| **일정 범위** | `projects.start_date` ~ `projects.end_date`. 작업 일정 클램프의 기준 |
| **공수 단위** | 프로젝트가 사용하는 노력의 단위 (`MD`, `MM`, `H` 등). 모든 작업 공수의 단위 |
| **베이스라인** | 특정 시점의 일정·공수 스냅샷. 변경 추적 비교용 |
| **즐겨찾기** | 사용자별 프로젝트 핀. 헤더 드롭다운 상단 노출 |

## 2. 상세 기능 정의

### FD-PM-001 — 프로젝트 생성

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |
| 페르소나 | 시스템 관리자, 일반 회원(권한 정책에 따라) |

#### 1. 목적

새 작업 컨테이너를 만들어 작업 입력을 시작할 수 있게 한다.

#### 2. 사용자 시나리오

1. 헤더 [+ 프로젝트] 또는 프로젝트 페이지 [+ 새 프로젝트] 클릭.
2. 프로젝트 모달이 열림.
3. 프로젝트명·설명·기간·공수 단위·보고 메타 입력.
4. [저장] → 모달 닫힘 → 새 프로젝트가 헤더 드롭다운에 등장 → 자동 선택.

#### 3. 사전 조건

- 사용자=`Member` 이상.
- 클라우드 모드: `Member`(승인 회원)만 DB 저장. `Pending`은 로컬 전용.

#### 4. 입력

| 필드 | 필수 | 유효성 |
|------|:---:|--------|
| 프로젝트명 | ○ | 1~120자, 동일 소유자 내 중복 허용(경고) |
| 설명 | ✗ | ≤2000자 |
| 시작일 | ✗ | YYYY-MM-DD. 종료일과 함께면 시작일≤종료일 |
| 종료일 | ✗ | 〃 |
| 공수 단위 | △ | 기본 `MD`. 변경 시 기존 작업 공수 환산 안 함 |
| 최소 공수 | ✗ | ≥0 |
| 보고 메타 (카테고리·기관·예산·기간·약칭·풀네임) | ✗ | 자유 |
| 멤버 투입율 (`assignments`) | ✗ | 사용자별 0~1 |

#### 5. 처리 규칙

##### 5.1 소유자 자동 지정

- `owner_id = current user`. 변경 불가(이전은 [FD-PM-002](#fd-pm-002--프로젝트-수정-메타데이터)에서 별도).

##### 5.2 기본 공수 단위

- 프로젝트 생성 시 기본값 `MD`(Man-Day).
- 사용자가 `MM`(Man-Month) 또는 `H`(시간) 선택 가능.
- 단위 변경은 표시·계산에만 영향. 작업의 `work_effort` 숫자는 그대로(단위 환산 자동 안 함).

##### 5.3 일정 미입력

- 시작일·종료일 모두 미입력 가능 (= 무제한). 작업 일정 클램프는 [FD-PM-007](#fd-pm-007--프로젝트-일정-범위-적용-작업-클램프) 참조.

##### 5.4 자동 동작

- 생성 직후 `currentProjectId` = 새 프로젝트.
- 뷰가 `'projects'`였다면 `'list'`로 자동 전환.

#### 6. 사후 조건

- `projects` INSERT.
- 작업은 0건. 작업 추가 안내 빈 상태 표시.
- 헤더 드롭다운·프로젝트 페이지에 즉시 반영.
- `wbs_audit_log` INSERT (`entity='project'`, `action='create'`).

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 빈 프로젝트명으로 [저장] | [저장] 비활성, "이름을 입력하세요" 표시 |
| EX-002 | 시작일 > 종료일 | 입력 단계에서 빨간 테두리, [저장] 비활성 |
| EX-003 | DB 저장 실패 | 토스트 "저장 실패. 로컬에 임시 저장됨" + 재시도 버튼 |
| EX-004 | `Pending` 회원이 시도 | 로컬에만 저장 + 안내 "승인 후 클라우드 동기화됩니다" |

#### 8. 권한

| 등급 | 동작 |
|------|------|
| Anon | 미지원 |
| Pending | 로컬 전용 생성 |
| Member | 본인 소유로 생성 가능 |
| Admin | 〃 (모든 프로젝트의 소유자가 될 수 있음) |

#### 9. UI 요소

- 모달 제목: "새 프로젝트" (편집 시 "프로젝트 수정")
- 좌측: 기본 정보 / 우측: 보고 메타 / 하단: 멤버 투입율 표
- [저장] / [취소]

#### 10. 데이터 영향

| 테이블 | 작업 |
|--------|------|
| `projects` | INSERT |
| `wbs_audit_log` | INSERT |

#### 11. 수용 기준

```
AC-FD-PM-001-1
  Given 사용자=Member, 헤더 [+ 프로젝트]
  When 모달 열림 → 이름 "신규 사업" → 시작 2026-06-01 → 종료 2026-12-31 → 저장
  Then projects 테이블에 1행 INSERT (owner_id=user.id)
       헤더 드롭다운에 즉시 등장
       currentProjectId=신규 프로젝트 ID
       view가 'projects'였다면 'list'로 전환

AC-FD-PM-001-2
  Given 모달, 시작 2026-06-30, 종료 2026-06-01 입력
  When [저장]
  Then [저장] 비활성, "종료일은 시작일 이후여야 합니다" 메시지

AC-FD-PM-001-3
  Given 사용자=Pending
  When 프로젝트 생성 시도
  Then 로컬에만 저장됨 (DB INSERT 안 됨)
       토스트 "승인 후 클라우드와 동기화됩니다"
```

#### 12. Out of Scope

- 멤버 초대 메일 발송
- 권한 부여 UI (→ FD-AUTH-010)

### FD-PM-002 — 프로젝트 수정 (메타데이터)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

프로젝트의 메타·일정·공수 단위·보고 정보를 변경한다.

#### 2. 사용자 시나리오

- 헤더 드롭다운에서 프로젝트의 ⋮ → [편집] 또는 프로젝트 페이지 카드 더블클릭.
- 모달이 [편집] 모드로 열림.

#### 4. 입력 — FD-PM-001과 동일 + 수정 제약

| 필드 | 수정 가능? |
|------|:----------:|
| `id` | ✗ |
| `name` | ✓ |
| `description` | ✓ |
| `owner_id` | △ — 관리자만, 별도 동작 ([FD-AUTH-010](./05_인증_권한_조직.md)) |
| `start_date` / `end_date` | ✓ (작업 클램프 동반) |
| `work_effort_unit` | ✓ (단순 라벨 변경) |
| `report_*` | ✓ |
| `assignments` | ✓ |
| `group_id` | ✓ |
| `is_archived` | ✓ |

#### 5. 처리 규칙

##### 5.1 일정 변경 시 작업 클램프

- 시작일을 늦추면: `task.startDate < newStart`인 작업의 `startDate`를 `newStart`로 클램프.
- 종료일을 당기면: `task.endDate > newEnd`인 작업의 `endDate`를 `newEnd`로 클램프.
- 클램프 후 `startDate > endDate`이면 `startDate=endDate`.
- 클램프된 작업 수 + 잠금 필드(`startDate`/`endDate`)로 인한 미클램프 작업 수를 토스트로 안내.

##### 5.2 공수 단위 변경

- 단순 라벨 변경. 기존 작업의 `work_effort` 숫자는 그대로.
- 사용자에게 "기존 작업 공수는 환산하지 않고 유지됩니다" 확인 후 진행.

##### 5.3 멤버 투입율 변경

- 자동 일정 산정에 사용 — 작업의 종료일 재계산 트리거([FD-SCH-002](./03_일정_상태_진척도.md)).

#### 11. 수용 기준

```
AC-FD-PM-002-1
  Given 프로젝트 P (start=2026-06-01, end=2026-12-31), 작업 T (start=2026-11-01, end=2026-12-15)
  When P의 종료일을 2026-11-30으로 단축 저장
  Then T.endDate=2026-11-30으로 클램프됨
       토스트 "작업 1건의 종료일이 조정되었습니다"

AC-FD-PM-002-2
  Given 작업 T가 endDate 잠금 (userLockedFields=['endDate'])
  When P의 종료일 단축
  Then T.endDate 미변경 (잠금)
       토스트 "잠금된 작업 1건은 조정되지 않았습니다"

AC-FD-PM-002-3
  Given 사용자=비-소유자 비-관리자
  When 프로젝트 ⋮ 메뉴 진입 시도
  Then [편집] 항목 미노출
```

### FD-PM-003 — 프로젝트 복사

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

기존 프로젝트의 구조·작업·메타를 그대로 복제하여 새 프로젝트를 빠르게 시작한다 (예: 동일 사업의 차년도 버전).

#### 4. 처리 규칙

##### 4.1 복사 옵션

- **메타 + 작업 트리** 복사 (기본).
- **메타만** 복사 — 작업 0건으로 시작.
- 일정 시프트: 시작일 변경 시 모든 작업의 일정을 동일 일수만큼 시프트.

##### 4.2 ID 재발급

- `projects.id`, 모든 `tasks.id` 새 UUID.
- `parent_id`, 의존성(`dependencies`)는 매핑 테이블로 새 ID로 재구성.

##### 4.3 멤버 투입율

- 복사 옵션 — 동일 멤버 유지 / 본인만 / 빈 상태.

##### 4.4 기본 이름

- "{원본 이름} 사본". 사용자가 수정 가능.

#### 11. 수용 기준

```
AC-FD-PM-003-1
  Given 프로젝트 P (작업 50건, 의존성 30개)
  When [복사] → 모달에서 시작일 +1년 시프트 → 저장
  Then 새 프로젝트 P' 생성, 작업 50건·의존성 30개 그대로 복제
       모든 작업의 시작/종료일이 +365일 시프트됨
       원본 P 변화 없음

AC-FD-PM-003-2
  Given 프로젝트 P (멤버 A·B 투입)
  When [복사] → "본인만" 선택 → 저장
  Then P' 의 assignments에 본인만 포함, A·B 제외
```

### FD-PM-004 — 프로젝트 삭제

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

프로젝트와 그 모든 작업·이력을 영구 삭제하거나 보관(아카이브)한다.

#### 4. 처리 규칙

##### 4.1 삭제 vs 보관

- **보관(Archive)**: `is_archived=true`. 헤더 드롭다운·기본 목록에서 숨김. 별도 [보관함] 탭에서 조회 가능.
- **영구 삭제**: 프로젝트 + 작업 + 감사 로그까지 제거. 복구 불가 (DB 백업으로만 복원 가능).

##### 4.2 확인 절차

- 보관: 단일 확인 다이얼로그.
- 영구 삭제: 프로젝트명을 사용자에게 입력시켜 일치 확인 (`confirm name match`).

##### 4.3 작업·이력

- 영구 삭제 시 `tasks`, `wbs_audit_log`, 베이스라인 모두 cascade.

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 다른 프로젝트가 이 프로젝트의 작업을 의존성으로 참조 (cross-project은 허용 안 함이 기본) | 의존성은 같은 프로젝트 내로 제한되므로 발생하지 않음 |
| EX-002 | 동시 다른 사용자가 작업 편집 중 | 다음 동기화에서 토스트 "프로젝트가 삭제되었습니다" + 모달 강제 닫기 |

#### 11. 수용 기준

```
AC-FD-PM-004-1
  Given 프로젝트 P
  When ⋮ → [보관] → 확인
  Then P.is_archived=true
       헤더 드롭다운·프로젝트 페이지 기본 목록에서 사라짐
       [보관함] 탭에서 보임 + [복원] 버튼

AC-FD-PM-004-2
```

### FD-PM-007 — 프로젝트 일정 범위 적용 (작업 클램프)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

프로젝트 일정 변경이 작업 일정에 일관되게 반영되도록 한다 (작업이 프로젝트 밖으로 벗어나지 않게).

#### 4. 처리 규칙

##### 4.1 트리거

- 프로젝트 `start_date` 또는 `end_date` 변경 시 자동.
- 작업 추가·이동·붙여넣기 시에도 같은 클램프 적용.

##### 4.2 클램프 알고리즘 — 의사코드

```
clampTaskToProjectRange(task, project):
    if project.startDate and task.startDate < project.startDate:
        task.startDate = project.startDate
    if project.endDate and task.endDate > project.endDate:
        task.endDate = project.endDate
    if task.startDate > task.endDate:
        task.startDate = task.endDate
```

##### 4.3 잠금 필드 존중

- `userLockedFields`에 `startDate` 또는 `endDate`가 있으면 해당 필드 클램프 제외.

##### 4.4 사용자 안내

- 변경된 작업 수와 잠금된 작업 수를 토스트로 표시.

#### 11. 수용 기준

```
AC-FD-PM-007-1
  Given 프로젝트 P (range=2026-06-01~12-31), 작업 T (range=2026-05-15~2026-08-01)
  When (자동 또는 수동) clamp 실행
  Then T.startDate=2026-06-01 (시작일 클램프됨)
       T.endDate=2026-08-01 (변경 없음)

AC-FD-PM-007-2
  Given 작업 T (startDate=2027-02-01, userLockedFields=['startDate']), P 종료일 2026-12-31
  When clamp 실행
  Then T.startDate 미변경
       토스트 "잠금된 작업 1건은 조정되지 않았습니다 — 일정 충돌 점검 필요"
```

### FD-PM-008 — 공수 단위 설정

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

조직·프로젝트별 관행에 맞게 공수 단위를 선택한다.

#### 4. 처리 규칙

##### 4.1 지원 단위

| ID | 표시 | 1 단위 = MD |
|----|------|-------------|
| `MD` | Man-Day | 1 |
| `MM` | Man-Month | 20 (영업일 기준) |
| `H` | 시간 | 0.125 (8시간 = 1 MD) |

##### 4.2 표시·환산

- 표·간트 컬럼 헤더 라벨에 단위 부착 ("공수 (MD)").
- 자동 일정 산정([FD-SCH-002](./03_일정_상태_진척도.md))은 내부적으로 MD 환산 후 영업일 누적.

##### 4.3 단위 변경 시

- 작업의 `work_effort` 숫자는 그대로 유지 (자동 환산 안 함).
- 사용자에게 명시 확인 다이얼로그.

#### 11. 수용 기준

```
AC-FD-PM-008-1
  Given 프로젝트 P (work_effort_unit='MD'), 작업 T (workEffort=5)
  When P의 단위를 'MM'으로 변경 → 확인
  Then T.workEffort 그대로 5 (환산 안 함)
       표 컬럼 라벨이 "공수 (MM)"으로 변경됨
       자동 산정 시 5 MM = 100 MD로 계산하여 종료일 산출
```

### FD-PM-009 — 베이스라인 설정·비교

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 1. 목적

특정 시점의 일정·공수를 스냅샷으로 보존하여 이후 변동을 정량 비교한다.

#### 4. 처리 규칙

##### 4.1 베이스라인 저장

- 작업별 `baseline.startDate / endDate / workEffort` 필드.
- 컨텍스트 메뉴 [베이스라인 설정] / [해제]로 단일 작업.
- 프로젝트 단위 일괄 [베이스라인 전체 설정] (관리자).

##### 4.2 표시

- 간트 차트에 베이스라인 막대 (회색)와 현재 막대 (색상) 동시 표시.
- 표 컬럼: `baseline_start`, `baseline_end`, `baseline_effort` (옵션 표시).

##### 4.3 비교

- 별도 [베이스라인 비교 보기] 화면 — 변동 일수·공수 차이 표시.

#### 11. 수용 기준

```
AC-FD-PM-009-1
  Given 작업 T (start=2026-06-01, end=2026-06-15)
  When 우클릭 [베이스라인 설정]
  Then T.baseline_start=2026-06-01, baseline_end=2026-06-15

AC-FD-PM-009-2
  Given T 베이스라인 설정 후, end를 2026-06-20으로 변경
  When 간트 차트 보기
  Then 회색 베이스라인 막대(원래 6/15까지) + 색상 현재 막대(6/20까지) 동시 표시

AC-FD-PM-009-3
  Given [베이스라인 비교 보기]
  When 진입
  Then 작업별 변동 일수(+5일) 표시, 합계로 프로젝트 변동 요약
```
