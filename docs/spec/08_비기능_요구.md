## 1. 상세 기능 정의

### FD-NFR-001 — 성능 (가상 스크롤·렌더 최적화)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 요구 수준

##### 4.1 응답 시간

| 동작 | 목표 |
|------|------|
| 셀 클릭 → 편집 진입 | < 100ms |
| 작업 추가 → 표 반영 | < 200ms |
| 자동 일정 산정 (작업 100건 기준) | < 500ms |
| 동기화 시작 → 완료 (작업 1000건) | < 5초 |
| 표 스크롤 (작업 1000건) | 60fps 유지 |
| 초기 로드 (작업 500건) | < 2초 (Cloud) / < 1초 (Local) |

##### 4.2 가상 스크롤

- 작업 ≥ 100건일 때 가상 스크롤 활성.
- 보이는 행 + 위·아래 버퍼 5행만 DOM.

##### 4.3 선택적 렌더링

- React.memo, useMemo, useCallback 적극 사용.
- 셀 단위 메모이제이션 — 한 셀 변경이 다른 셀 재렌더 유발 안 되도록.

##### 4.4 Lazy Loading

- 모달·간트·마인드맵 등 큰 컴포넌트는 React.lazy + Suspense.
- 라이브러리(xlsx, html2canvas 등)는 동적 import.

#### 11. 수용 기준

```
AC-FD-NFR-001-1
  Given 표 화면, 작업 1000건
  When 스크롤
  Then DevTools FPS 메터 60fps 유지
       메모리 사용 < 200MB

AC-FD-NFR-001-2
  Given 작업 100건의 자동 일정 산정 트리거
  When 산정 진행
  Then UI 동결 없음 (긴 동기 작업 분리)
       완료 < 500ms

AC-FD-NFR-001-3
  Given 마인드맵 뷰 첫 진입
  When 라우팅
  Then 마인드맵 컴포넌트 + react-flow lazy 로드
       초기 번들 크기 영향 없음
```

### FD-NFR-002 — 접근성 (a11y)

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 요구 수준

##### 4.1 키보드 전용 사용

- 모든 동작이 키보드만으로 가능.
- 포커스 시각 표시(outline) 항상 표시.

- WCAG 2.1 AA 기준 — 본문 텍스트 4.5:1 이상.
- 색상만으로 의미 전달 금지 (예: 이슈는 빨간색 + 아이콘).

##### 4.4 폰트 크기

- 기본 14px. 사용자 환경설정으로 +2/-2 조정 가능.

##### 4.5 다크 모드

- 시스템 설정 자동 감지 + 사용자 토글 (P2).

#### 11. 수용 기준

```
AC-FD-NFR-002-1

  Then 모든 버튼·링크·셀에 포커스 가능
       포커스 ring 시각 표시

AC-FD-NFR-002-2
  Given 토스트 표시 발생
  When NVDA/JAWS 리더

AC-FD-NFR-002-3
  Given Chrome DevTools Lighthouse a11y
  When 검사
  Then 점수 90 이상
```

### FD-NFR-003 — 보안 (RLS·CSP·세션)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 요구 수준

##### 4.1 Row Level Security (RLS)

- 모든 DB 테이블에 RLS 활성화.

```sql
-- tasks_select 예시
CREATE POLICY "tasks_select" ON tasks FOR SELECT
USING (
  -- 관리자
  EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND is_admin = true)
  OR
  -- 본인 소유 프로젝트
  project_id IN (SELECT id FROM projects WHERE owner_id = auth.uid())
  OR
  -- 본인이 멤버인 프로젝트
  project_id IN (SELECT project_id FROM project_members WHERE user_id = auth.uid())
);
```

##### 4.2 CSP (Content Security Policy)

- `default-src 'self'`, Supabase URL 화이트리스트.
- 인라인 스크립트 차단.
- AI 호출은 사용자 동의 도메인만.

##### 4.3 세션

- Supabase JWT, 1시간 만료, 자동 새로 고침.
- 로그아웃 시 토큰 + localStorage 정리.

##### 4.4 비밀번호 정책

- 최소 8자, 영문+숫자.
- (선택) 강도 표시 + 사전 단어 차단.

##### 4.5 환경변수

- `VITE_*` 변수만 클라이언트 노출. 서버 시크릿(Service Role Key)은 절대 클라이언트 미노출.

##### 4.6 SQL Injection·XSS

- Supabase SDK 파라미터 바인딩 사용.
- 사용자 입력은 React가 자동 이스케이프.
- `dangerouslySetInnerHTML` 사용 금지 (메모 마크다운 렌더링은 sanitizer 거쳐서).

##### 4.7 감사 로그

- 모든 권한·환경설정 변경 기록.
- 비정상 시도(권한 부족) 별도 로깅 (P2).

#### 11. 수용 기준

```
AC-FD-NFR-003-1
  Given 권한 없는 사용자 X, 다른 사용자의 프로젝트 P 작업 ID 직접 접근 시도 (URL 변조)
  When DB SELECT 시도
  Then RLS로 0행 반환, "권한 없음"

AC-FD-NFR-003-2
  Given 사용자 입력에 <script>alert(1)</script>
  When 작업명 표시
  Then 텍스트로 표시되고 실행 안 됨 (React 자동 이스케이프)

AC-FD-NFR-003-3
  Given 클라이언트 번들
  When 정적 분석
  Then SUPABASE_SERVICE_ROLE_KEY 미포함, ANON_KEY만 포함
```

### FD-NFR-004 — 반응형/모바일

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 요구 수준

##### 4.1 브레이크포인트

| 폭 | 동작 |
|----|------|
| ≥ 1280px | 풀 데스크톱 |
| 768~1279px | 사이드바 접힘 |
| < 768px | 헤더 슬림 + 표 가로 스크롤 + 모바일 안내 배너 |

##### 4.2 모바일 동작

- 표 셀 편집은 터치로 진입 가능 (탭 1회 = 행 선택, 탭 2회 = 편집).
- 컨텍스트 메뉴: 길게 누름.
- 풀스크린 자동 권장.

##### 4.3 모바일 안내

- 첫 진입 시 "모바일에서는 일부 기능이 제한됩니다 — 데스크톱 권장" 배너 1회 표시 후 닫기.

#### 11. 수용 기준

```
AC-FD-NFR-004-1
  Given iPhone (Safari, 375px 폭)
  When 앱 진입
  Then 모바일 배너 표시
       헤더 슬림, 표는 가로 스크롤
       체크박스·토글 터치 영역 ≥ 44px

AC-FD-NFR-004-2
  Given 768~1279px (태블릿)
  When 진입
  Then 사이드바 자동 접힘, 다른 동작은 데스크톱 동등
```

### FD-NFR-009 — DB egress·쿼리 최적화

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 요구 수준

##### 4.1 풀 시 페이지네이션

- 작업이 많은 프로젝트는 페이지네이션 또는 윈도우 풀 (한 번에 1000건).

##### 4.2 fingerprint 기반 변경 감지

- 동기화 시 클라이언트 → 서버 fingerprint 비교 → 변경된 행만 INSERT/UPDATE.

##### 4.3 인덱스

- `tasks(project_id)`, `tasks(parent_id)`, `tasks(assignee)`, `wbs_audit_log(entity_id, created_at)`.

##### 4.4 휴일 캐싱

- `getHolidaysForTaskDates(tasks)` — 작업 일정 범위에 해당하는 휴일만.

##### 4.5 Realtime 구독 한정

- 현재 프로젝트 + 사용자 권한 범위만 구독. 전체 DB는 구독하지 않음.

#### 11. 수용 기준

```
AC-FD-NFR-009-1
  Given 프로젝트 P (작업 5000건)
  When 풀 트리거
  Then 페이지네이션으로 1000씩 분할 풀, 사용자에게 진행률 표시
       완료 < 5초

AC-FD-NFR-009-2
  Given 동기화 시점, 변경된 작업 = 10건 / 전체 1000건
  When 푸시
  Then UPDATE 10건만, INSERT/DELETE 0건
       egress 최소화
```

### FD-NFR-010 — 로깅·모니터링

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 4. 요구 수준

##### 4.1 클라이언트 로깅

- 콘솔 로그 레벨 (DEBUG/INFO/WARN/ERROR).
- 환경변수로 prod에서는 ERROR 이상만.

##### 4.2 에러 리포팅

- Sentry·SimpleAnalytics 등 외부 서비스 연동 (옵션).
- 사용자 동의 후 활성.

##### 4.3 사용 분석

- 페이지뷰·뷰 전환·주요 액션 카운터.
- 개인 식별 정보 미수집.

##### 4.4 감사 로그 활용

### FD-NFR-012 — 데이터 보존·삭제 정책

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 4. 요구 수준

##### 4.1 작업·프로젝트

- 보관(archive) → 무기한 보존.
- 영구 삭제 → 복구 불가 (DB 백업 의존).

##### 4.2 감사 로그

- 무기한 보존 (현재).
- 향후 N년(예: 5년) 후 자동 정리 정책 (P3).

##### 4.3 회원 탈퇴

- 회원 영구 삭제: `auth.users` + `profiles` cascade.
- 본인이 소유한 프로젝트: 사전 다른 사용자에게 양도 또는 archive.

##### 4.4 GDPR·개인정보

- 사용자 요청 시 본인 데이터 export 제공 ([FD-IO-003] 백업 + 변경 이력).
- 삭제 요청 시 30일 내 처리.

#### 11. 수용 기준

```
AC-FD-NFR-012-1
  Given 사용자 X 탈퇴 요청
  When 처리
  Then X.profiles 삭제, X 소유 프로젝트는 사전 양도/archive 강제
       감사 로그의 actor_id는 'deleted_user' 익명화
```
