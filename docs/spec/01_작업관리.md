## 0. 그룹 개요

### 0.1 범위

이 그룹은 **WBS 트리의 노드(=작업)를 만들고·바꾸고·옮기고·삭제하는 일체의 인터랙션**을 정의한다. 작업의 일정 자동 산정 규칙은 [03_일정_상태_진척도](./03_일정_상태_진척도.md)에, 화면별 표시 규칙은 [04_화면_뷰](./04_화면_뷰.md)에 둔다. 본 그룹은 "어떤 입력으로 어떤 트리 변형이 일어나야 하는가"에 집중한다.

### 0.2 비-목표 (Out of Scope)

- 작업의 자동 일정 계산 규칙 (→ FD-SCH)
- 작업 표시 화면(표·간트·칸반·마인드맵)의 렌더링 규칙 (→ FD-UI)
- 작업 변경의 동기화·실시간 반영 (→ FD-SYNC)
- 작업과 외부 시스템(Excel·AI)의 데이터 교환 (→ FD-IO)

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **작업(Task)** | WBS 트리의 단위 노드. 단일 프로젝트에 귀속 |
| **WBS 번호** | 부모-자식 트리상의 위치를 나타내는 자동 부여 식별자 (`P1`, `P1.1`, `P1.1.1` …) |
| **루트 작업** | `parentId=null`인 작업. 프로젝트 직속 |
| **하위 작업** | 부모 작업의 자식. 트리 깊이는 무제한(권장 9 레벨) |
| **형제 작업** | 같은 `parentId`를 가진 작업들 |
| **표시 순서** | 트리 내에서 같은 부모 자식들의 좌→우 순서. `sortOrder`로 결정 |
| **잠금 필드** | 자동 산정·롤업·AI 보정에서 제외할 작업의 특정 필드 (`userLockedFields`) |

## 1. 데이터 정의 — `tasks` 테이블 (본 그룹 관점)

본 그룹이 직접 변경하는 필드만 정리한다. 자동 산정에 의해 변경되는 필드는 [FD-SCH](./03_일정_상태_진척도.md)에서 정의한다.

| 필드 | 타입 | 의미 | 본 그룹의 변경 |
|------|------|------|----------------|
| `id` | uuid | 작업 식별자 | 신규 시 클라이언트가 발급 |
| `project_id` | uuid | 소속 프로젝트 | 신규 시 결정, 이후 불변 |
| `parent_id` | uuid \| null | 부모 작업 | 들여쓰기·내어쓰기·이동·붙여넣기 시 변경 |
| `sort_order` | int | 같은 부모 내 표시 순서 | 형제 추가·이동·삭제 시 재계산 |
| `name` | text | 작업명 | 인라인 편집·모달 편집 |
| `parent_id_path` | text[] | 조상 체인(쿼리 최적화용) | parent_id 변경 시 자동 |
| `wbs_number` | text (계산 캐시) | 트리 위치 표시용 | parent_id·sort_order 변경 시 자동 |
| `is_milestone` | bool | 마일스톤 표시 | 컨텍스트 메뉴·일괄 액션 |
| `is_issue` | bool | 이슈 강조 | 〃 |
| `expanded` | bool | 트리 펼침 상태 | 펼치기/접기 |
| `custom_fields` | jsonb | 사용자 정의 컬럼 값 | 사용자 정의 컬럼 입력 |
| `user_locked_fields` | text[] | 잠금 필드 목록 | 모달 편집·일괄 액션 |

> `wbs_number`는 DB에 저장하지만 항상 **트리에서 재계산** 가능. 정합성이 어긋나면 클라이언트가 재계산 결과를 우선한다.

## 2. 상세 기능 정의

### FD-TM-001 — 작업 추가

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |
| 페르소나 | PM, 팀원, 관리자 |
| 의존 기능 | FD-AUTH-006(편집 권한 판정), FD-SCH-001(기본 일정값) |

#### 1. 목적

WBS 트리의 임의 위치에 새 작업 노드를 빠르게 추가한다. 사용자가 기획·설계 중 떠오른 작업을 흐름을 끊지 않고 입력하도록 다수의 진입점과 단축키를 제공한다.

#### 2. 사용자 시나리오 (메인 플로우)

1. 사용자는 작업을 추가하려는 위치(트리상 어디)와 관계(형제/자식)를 결정한다.
2. 시나리오에 맞는 진입점을 선택한다 (아래 진입점 표 참조).
3. 작업명을 입력한다.
4. Enter로 확정 또는 모달의 [저장] 버튼을 누른다.
5. 새 작업이 트리에 등장하고, 해당 행이 선택·포커스된다.

#### 3. 사전 조건

- 사용자는 로그인 상태이며 `Member` 이상.
- `currentProjectId !== 'all'` 이거나, 사용자는 `Admin`(이 경우 첫 프로젝트로 자동 귀속).
- 사용자는 대상 프로젝트의 `Owner` 또는 `Admin` (편집 권한).

#### 4. 입력

작업 추가의 입력은 **위치 정보** + **초기 데이터**로 분리한다.

| 입력 | 필수 | 출처 | 기본값 |
|------|------|------|--------|
| 부모 작업 ID (`parentId`) | ○ | 진입점이 결정 | `null`(루트) 또는 진입 위치 |
| 삽입 위치 (`insertAfterId`) | △ | 〃 | 형제 끝 |
| 작업명 (`name`) | ○ | 사용자 입력 | (빈값 입력 시 행 자동 삭제) |
| 시작일 (`startDate`) | △ | 활성 필터의 `filters.startDate` 우선 → 프로젝트 시작일 → 오늘 | 위 |
| 종료일 (`endDate`) | △ | 활성 필터의 `filters.endDate` 우선 → 시작일 | 위 |
| 공수 (`workEffort`) | △ | 0.5 (단위: MD 또는 프로젝트별 단위) | 0.5 |
| 진척도 (`progress`) | △ | 0 | 0 |
| 상태 (`status`) | △ | `'todo'` (또는 칸반 컬럼의 status) | `'todo'` |
| 담당자 (`assignee`) | △ | 활성 필터의 `filters.assignee` 우선 | `''` |

#### 5. 처리 규칙

##### 5.1 진입점 → 위치 결정 매핑

| 진입점 | parentId | insertAfterId | projectId 결정 |
|--------|----------|---------------|----------------|
| 헤더 [+새 작업] | 사용자가 모달에서 선택 | 형제 끝 | `currentProjectId`. `'all'`이면 모달에서 선택 또는 첫 프로젝트 |
| 표 하단 인라인 입력 | `null`(루트) | 마지막 | `currentProjectId` |
| 표 행 내 인라인 추가(자식) | 부모 행 ID | 직전 형제 | 부모 행의 `projectId` |
| 표 `Enter` (작업명 편집 중) | 현재 행의 `parentId` | 현재 행 ID | 현재 행 `projectId` |
| 표 `Shift+Enter` | 현재 행의 `parentId` | 직전 형제 ID | 〃 |
| 표 `Insert` | 기준 행의 `id` (자식) | 기준 행 ID | 〃 |
| 표 `Shift+Insert` | 기준 행의 `parentId` | 직전 형제 ID | 〃 |
| 표 `Ctrl+V` | 클립보드 매핑 | 선택 행/마지막 | 〃 |
| 컨텍스트 메뉴 [위/아래/하위에 추가] | 메뉴 항목별 | 〃 | 〃 |
| 칸반 [카드 추가] | `null`(루트 강제) | 컬럼 내 끝 | `currentProjectId`(다중·`'all'` 시 첫 프로젝트) |
| 마인드맵 루트 [작업 추가] | `null` | 끝 | `currentProjectId`(`'all'` 시 첫 프로젝트) |
| 마인드맵 자식(`Tab`/`Ctrl+Enter`) | 선택 노드 ID | 끝 | 선택 노드 `projectId` |
| 작업 모달 신규 | 모달 내 사용자 선택 | 호출자 결정 | 〃 |

##### 5.2 가중치 자동 분배

신규 작업이 기본 가중치(weight) 미지정으로 추가되면, **같은 부모 자식들의 합 = 100** 규칙을 보장한다.

- `n` = 새 작업 추가 후 그룹 형제 수
- 새 작업 weight = `100/n` (소수 둘째 자리 반올림)
- 기존 형제는 비율 유지하며 `100 - 100/n`을 비례 재분배

명시적 weight 값이 입력에 포함된 경우(임포트·복사) 그 값을 유지하고 형제만 비례 재조정한다.

##### 5.3 일정 자동 보정

- `startDate`/`endDate`가 프로젝트 일정 범위를 벗어나면 범위 안으로 클램프한다.
- `startDate > endDate`이면 `startDate = endDate`로 정규화한다.
- 의존성 자동 시프트는 본 기능에서 다루지 않음(추가 후 [FD-SCH-006](./03_일정_상태_진척도.md) 자동 트리거).

##### 5.4 부모 일정·진척도 롤업

신규 작업 추가 후 `parentId` 체인을 따라 조상의 `startDate`(자식 최소)·`endDate`(자식 최대)·`progress`(가중평균)·`status`(자식 상태에서 도출)를 재계산한다. 잠금 필드 정책은 [FD-SCH-009](./03_일정_상태_진척도.md)를 따른다.

##### 5.5 빈 작업명 처리

작업명을 비운 채 Enter/blur 한 경우:
- 표 인라인 추가에서는 **취소로 간주**하여 행을 삭제한다.
- 모달에서는 [저장] 버튼이 비활성화된다.

#### 6. 출력 / 사후 조건

- 새 작업이 트리에 등장.
- 해당 행이 시각적으로 선택(`lastSelectedId`) + 작업명 인라인 편집 모드 진입.
- 가중치·일정·진척도·상태가 위 규칙에 따라 보정됨.
- 부모 체인의 롤업 갱신.
- 자동 저장 디바운스(1초) 후 로컬 저장. 클라우드 동기화는 사용자 수동 트리거.

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | `currentProjectId='all'` + 일반 회원 | 모든 진입점 비활성. 토스트 안내 "프로젝트를 선택하세요" |
| EX-002 | `currentProjectId='all'` + 관리자 + 진입점이 단일 프로젝트를 결정하지 않음 | 모달이면 프로젝트 선택 강제, 그 외(임포트·마인드맵 루트)에서는 정렬 첫 프로젝트로 자동 귀속 + 토스트로 어느 프로젝트인지 안내 |
| EX-003 | 권한 없는 프로젝트(보기 권한) | 진입점 비활성·미렌더 |
| EX-004 | 활성 필터로 인해 새 작업이 즉시 가려짐 (예: 상태=완료 필터 + 신규 todo) | 토스트 "필터에 의해 가려졌습니다 — 필터 해제" 액션 제공 |
| EX-005 | WBS 정렬·필터 ON 상태에서 신규 추가 | 추가는 허용. 단 위치 결정은 `parentId`·`insertAfterId`만 따르고 정렬은 표시만 영향 |
| EX-006 | 빈 작업명으로 Enter | 행 삭제(취소) |
| EX-007 | 동일 작업명 다수 추가 시도 | 허용 (작업명 유일성 제약 없음) |
| EX-008 | 트리 깊이 9 초과 | 추가는 허용하되 사용자에게 깊이 경고 토스트(권장 한도 9) |
| EX-009 | 동시 사용자가 같은 위치에 추가 | 둘 다 추가됨(LWW 충돌 없음, sort_order만 다름) |
| EX-010 | 자동 저장 디바운스 중 탭 닫기 | `beforeunload` 가드로 저장 완료 대기 |

#### 8. 권한

| 등급 | 동작 |
|------|------|
| Anon | 미지원 |
| Pending | UI는 보이나 추가 시도 시 "승인 대기" 토스트 |
| Member | 본인이 소유한 프로젝트만 추가 가능 |
| Manager | Member와 동일 (조직 책임자 권한은 회원 관리에만 적용) |
| Owner | 해당 프로젝트에 추가 가능 |
| Admin | 모든 프로젝트에 추가 가능. 회원 체험 모드 ON 시에는 본인 소유분만 |

#### 9. 화면 / UI 요소

- **헤더 [+새 작업] 버튼**: 헤더 우측. 비편집 시 회색·비활성. 호버 툴팁으로 사유 안내.
- **표 하단 인라인 입력 행**: 마지막 행 아래에 항상 보이는 입력 행 ("새 작업 추가 (Enter 키 입력)..." placeholder).
- **표 행 내 인라인 입력**: 행 호버 시 작업명 우측 [+] 아이콘. 클릭 시 자식 추가 입력 행 표시.
- **컨텍스트 메뉴**: 행 우클릭 → "위에 추가" / "아래에 추가" / "하위에 추가" 항목.
- **칸반 [카드 추가]**: 각 컬럼 하단 [+ 카드 추가] 텍스트 버튼.
- **마인드맵 [작업 추가]**: 빈 상태 중앙 버튼. 노드 선택 시 우측 사이드의 [+ 자식 추가].
- **모달**: 작업명·일정·공수·담당자·상태·부모·의존성·가중치·잠금·체크리스트 입력.

### FD-TM-002 — 작업 수정 (인라인 셀 편집)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |
| 페르소나 | PM, 팀원(소유자), 관리자 |

#### 1. 목적

작업의 단일 필드를 모달을 거치지 않고 표 셀에서 직접 빠르게 변경한다. 엑셀 사용 패턴을 모방하여 키보드 중심 편집을 보장한다.

#### 2. 사용자 시나리오

1. 사용자가 표에서 편집할 셀을 클릭한다 (1차 클릭 = 행 선택).
2. 같은 셀을 다시 클릭하거나 F2/Enter를 누른다 (2차 = 편집 진입).
3. 값을 입력 또는 드롭다운에서 선택한다.
4. Enter (확정) 또는 Esc (취소) 또는 다른 셀로 이동(Tab/화살표) 시 자동 확정.

#### 3. 사전 조건

- 사용자=Owner 또는 Admin (대상 프로젝트).
- 셀이 편집 가능 컬럼 (모든 컬럼이 편집 가능하지는 않음 — 자동 산정 컬럼은 잠금 표시).

#### 4. 입력 — 컬럼별 타입

| 컬럼 | 입력 방식 | 유효성 |
|------|-----------|--------|
| 작업명 | 텍스트 | 빈 문자열 허용(저장 시 부모 트리에서 표시 시 placeholder) |
| 시작일/종료일 | 날짜 피커 또는 yyyy-mm-dd 직접 | 프로젝트 일정 범위 내 클램프 |
| 공수 | 숫자 (소수 1자리) | ≥0. 단위는 프로젝트 `work_effort_unit` |
| 진척도 | 숫자 (0~100, 소수 2자리까지) | 0 이상 100 이하 |
| 가중치 | 숫자 (소수 1자리) | ≥0. 형제 합 100 자동 재분배 |
| 상태 | 드롭다운 | `wbs_settings.status_configs`에 정의된 ID |
| 담당자 | 자동완성 | 조직 회원 목록에서 선택 또는 자유 텍스트 |
| 의존성 | 다중 선택 드롭다운 | 같은 프로젝트 내 작업만, 순환 불가 |
| 사용자 정의 컬럼 | 텍스트 | 자유 |

#### 5. 처리 규칙

##### 5.1 클릭 패턴

- 1차 클릭: 행 선택 (`lastSelectedId` 갱신, 셀 포커스).
- 2차 클릭(같은 셀): 편집 진입.
- 더블클릭(다른 셀): 행 더블클릭 = 모달 열기 (FD-TM-003).
- F2: 현재 포커스 셀을 편집 모드로.
- Enter: 비-편집 시 편집 진입. 편집 중 확정.

##### 5.2 편집 종료

- Enter / Tab / 화살표 / 다른 셀 클릭: 확정.
- Esc: 취소 (변경 무효).
- Blur(외부 클릭): 확정.

##### 5.3 편집 종료 후 키보드 동작

| 키 | 동작 |
|----|------|
| Enter (편집 중) | 확정 + 한 행 아래 같은 컬럼으로 이동 (작업명 컬럼은 신규 작업 추가) |
| Tab | 확정 + 다음 컬럼 |
| Shift+Tab | 확정 + 이전 컬럼 |
| ↑/↓ (편집 중) | 편집 종료 + 같은 컬럼 위/아래 행으로 이동 (편집은 종료된 채) |
| ←/→ (편집 중) | 셀 내 커서 이동 (편집 유지). v0.4.143~ 편집 중 ←/→로 셀 이동하지 않음 |
| ←/→ (비-편집) | 같은 행에서 컬럼 이동. 행 끝/처음에서 자동 wrap (이전/다음 행) |

##### 5.4 자동 캐스케이드

- 시작/종료/공수 변경: [FD-SCH-002](./03_일정_상태_진척도.md) 자동 산정.
- 의존성 변경: [FD-SCH-003](./03_일정_상태_진척도.md) 자동 시프트.
- 상태 변경 (`linkStatusAndProgress=true`인 경우): 진척도 자동 설정.
- 가중치 변경: 형제 합 100 재정규화.

#### 6. 출력 / 사후 조건

- 변경된 셀이 시각적으로 강조(잠시).
- 자동 캐스케이드된 다른 셀들도 갱신.
- 자동 저장 1초 후 로컬 저장.
- `wbs_audit_log`에 변경 이력 기록.

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |

### FD-TM-003 — 작업 수정 (모달 편집)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

작업의 모든 속성을 한 번에 보고 편집한다. 인라인 편집으로 다루기 어려운 항목(체크리스트, 잠금 필드 토글, 의존성 다중 편집, 메모)을 다룬다.

#### 2. 사용자 시나리오

1. 표 행을 더블클릭 / 칸반 카드 클릭 / 마인드맵 노드 더블클릭.
2. 모달이 열림.
3. 폼 필드를 편집.
4. [저장] 또는 [취소].

#### 3. 사전 조건 / 4. 입력

인라인 편집 가능한 모든 필드 + 다음 추가:

| 필드 | 의미 |
|------|------|
| 메모 (`memo`) | 마크다운 텍스트. 하단 미리보기 |
| 체크리스트 (`checklist`) | 작업 내 체크 항목들. 항목 추가/삭제/체크 |
| 잠금 필드 (`userLockedFields`) | 자동 산정 제외 필드 토글 |
| 의존성 (`dependencies`) | 다중 선택 |
| 부모 (`parentId`) | 다른 작업으로 이동 |

#### 5. 처리 규칙

##### 5.1 잠금 필드 토글

- 체크 ON: 해당 필드를 `user_locked_fields`에 추가. 자동 산정·롤업·AI 보정 시 제외.
- 체크 OFF: 배열에서 제거. 다음 자동 산정에서 갱신될 수 있음.

##### 5.2 체크리스트 → 하위 작업 변환

- 체크리스트 항목 우측 [하위 작업으로 변환] 버튼.
- 클릭 시 해당 항목을 부모 작업의 자식으로 신규 작업 생성, 항목은 체크리스트에서 제거.

##### 5.3 부모 변경

- 같은 프로젝트 내 다른 작업으로 부모 변경 가능.
- 자기 자신·후손은 부모 후보에서 제외(순환 방지).

#### 6. 출력 / 사후 조건

- 모달 닫힘.
- 변경 사항 저장.
- 자동 캐스케이드.
- 감사 로그.

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 모달 열린 채 프로젝트 전환 | 모달 자동 닫힘 + "저장하지 않은 변경이 있습니다" 확인 |
| EX-002 | 모달 열린 채 동시 사용자가 해당 작업 삭제 | 저장 시 토스트 "삭제된 작업입니다" + 모달 닫기 |
| EX-003 | 부모를 후손으로 지정 시도 | 드롭다운에서 후손 항목 미노출 |

#### 8. 권한

`canEditCurrentProject=false` 시 모달은 열리되 모든 입력 disabled, [저장] 비활성. 보기 전용 모드.

#### 9. 화면 / UI 요소

- 좌측: 기본 정보(작업명·일정·공수·담당자·상태)

### FD-TM-004 — 작업 삭제

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

작업과 그 모든 후손을 트리에서 제거한다.

#### 2. 사용자 시나리오

1. 행 선택 → Delete 키 / 컨텍스트 메뉴 [삭제] / 모달 [삭제] / 다중 선택 일괄 삭제.
2. 확인 다이얼로그 (1건이면 짧게, 다건이면 상세).
3. 확인 → 삭제.

#### 3. 사전 조건

- 권한: `canEditCurrentProject=true`.

#### 4. 처리 규칙

##### 4.1 후손 일괄 삭제

작업 삭제 시 모든 후손도 함께 삭제한다. 트리 보존을 원하면 사전에 자식을 다른 부모로 옮기도록 안내.

##### 4.2 의존성 정리

- 삭제된 작업이 다른 작업의 선행이었다면, 그 후행 작업의 `dependencies`에서 해당 ID를 제거.
- 후행 작업의 일정 자동 산정 재실행.

##### 4.3 형제 가중치 재정규화

같은 부모 형제들의 weight를 합 100으로 재분배.

##### 4.4 부모 롤업

부모 체인의 일정·진척도·상태 재계산.

#### 7. 예외 / 엣지 케이스

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 다중 선택 중 일부만 권한 있음 | 권한 있는 것만 삭제, 토스트로 "N건 권한 없음 — 건너뜀" |
| EX-002 | 삭제 후 즉시 Undo | 작업·후손·의존성·가중치·롤업 모두 복원 (히스토리 스냅샷 기반) |
| EX-003 | 동시 다른 사용자가 같은 작업 편집 중 | 동기화 시점에 LWW. 편집자 화면에서는 다음 동기화 시 토스트 "삭제된 작업입니다" |

#### 11. 수용 기준

```
AC-FD-TM-004-1
  Given 작업 T (자식 C1·C2, C1의 자식 D1)
  When T 선택 → Delete → 확인
  Then T, C1, C2, D1 모두 삭제됨
       T의 형제들 weight 합 100 재정규화

AC-FD-TM-004-2
  Given 작업 A→B 의존성 (A 선행, B 후행), 사용자가 A 삭제
  When 확인
  Then A 삭제됨, B.dependencies에서 A 제거됨, B 일정 자동 재산정

AC-FD-TM-004-3
  Given T 삭제 직후
  When Ctrl+Z (Undo)
  Then T와 모든 후손·의존성 복원
       형제 weight 원복
```

### FD-TM-005 — 작업 복사·잘라내기·붙여넣기

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

같은 프로젝트 또는 다른 프로젝트 사이에 작업 트리(부모+후손)를 복제·이동한다.

#### 2. 사용자 시나리오

1. 행 선택 (단일 또는 다중).
2. Ctrl+C (복사) 또는 Ctrl+X (잘라내기).
3. 붙여넣을 위치(다른 행 또는 빈 영역) 선택.
4. Ctrl+V.

#### 4. 처리 규칙

##### 4.1 복사 데이터 형식

- localStorage 클립보드 키 `wbs:clipboard:v1`에 작업 트리 + 메타(타임스탬프, 모드='copy'|'cut') 저장.
- 다른 탭과 공유 가능 (같은 도메인).
- 시스템 클립보드와는 별개 (시스템 클립보드는 텍스트 형식만 — Excel 호환용).

##### 4.2 ID 재발급

- 복사 시: 모든 작업에 새 UUID 발급. `parentId`는 매핑 테이블로 새 ID로 변환.
- 잘라내기 시: 원본 ID 유지하되 `parent_id`만 변경.

##### 4.3 의존성 처리

- 복사 시: 클립보드 내부 의존성만 새 ID로 매핑. 외부 의존성은 제거.
- 잘라내기 시: 의존성 그대로.

##### 4.4 다른 프로젝트로 붙여넣기

- 새 `projectId` 적용. 일정 범위 클램프.
- 의존성 중 다른 프로젝트 작업 참조는 제거.

#### 11. 수용 기준

```
AC-FD-TM-005-1
  Given 작업 T (자식 C1, C2)
  When T 선택 → Ctrl+C → 다른 행 R 선택 → Ctrl+V
  Then T, C1, C2의 복사본이 R 다음 형제로 추가됨
       모두 새 UUID
       T 복사본의 자식 = C1, C2 복사본 (parentId 매핑됨)
       원본 T는 그대로

AC-FD-TM-005-2
  Given 작업 T를 Ctrl+X
  When 다른 프로젝트 P2의 작업 R 선택 후 Ctrl+V
  Then T가 P2로 이동 (project_id 변경)
       T의 일정이 P2의 일정 범위로 클램프됨
       T가 다른 프로젝트 작업과 가졌던 의존성은 제거됨

AC-FD-TM-005-3
  Given Ctrl+X 후 30초 경과 (다른 동작 없이)
  When Ctrl+V
  Then 그대로 이동 동작 (잘라내기는 만료 없음, localStorage 영구)
```

```
       다른 사용자에게도 다음 동기화 시 반영

AC-FD-TM-012-2
  Given 사용자 정의 컬럼 "발주처"에 작업 100건이 값 입력
  When [컬럼 삭제] 시도
  Then 확인 다이얼로그 "100건의 작업에서 값이 사라집니다"
       확인 → 컬럼 정의 + 모든 작업의 해당 키 제거
```

### FD-TM-013 — 작업 검색·이동

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

전 프로젝트의 작업을 키워드로 빠르게 찾고 해당 위치로 점프한다.

#### 4. 처리 규칙

##### 4.1 진입

- 헤더 [검색] 버튼 또는 Ctrl+K (`/` 단축키도 검토).

##### 4.2 검색 범위

- 작업명·메모·담당자·사용자 정의 컬럼 텍스트.
- 사용자가 접근 권한 가진 프로젝트의 작업만 (RLS).

##### 4.3 결과 정렬

- 작업명 일치 우선 → 메모 일치 → 기타.

##### 4.4 점프 동작

- 결과 클릭 시:
  - `currentProjectId` = 작업의 프로젝트로 변경.
  - 뷰 = `'table'`로 강제(또는 현재 뷰 유지 — 정책 결정).
  - 해당 작업의 조상 모두 펼침.
  - 행으로 스크롤 + 포커스.
  - 필터로 가려졌으면 토스트 "필터에 의해 가려졌습니다 [필터 해제]".

#### 11. 수용 기준

```
AC-FD-TM-013-1
  Given Ctrl+K
  When 검색창 표시 → "발표 자료" 입력
  Then 작업명·메모에 "발표 자료" 포함 작업 목록 (최대 20건)
       작업별로 프로젝트명·WBS 번호 함께 표시

AC-FD-TM-013-2
  Given 검색 결과의 작업 T (다른 프로젝트 P2 소속)
  When 결과 클릭
  Then currentProjectId=P2, view='table'
       T의 조상 모두 expanded=true
       T 행으로 스크롤 + 포커스 + 선택 표시

AC-FD-TM-013-3
  Given 검색 결과 클릭, T가 활성 필터로 가려짐
  When 점프 직후
  Then 토스트 "필터에 의해 가려졌습니다 [필터 해제]"
       [필터 해제] 클릭 시 filterOn=false로 전환 + T가 보임
```
