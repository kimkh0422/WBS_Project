## 0. 문서 개요

### 0.1 두 관점의 차이

| | 사용자 관점 (US) | 시스템 관점 (SR) |
|---|---|---|
| **답하려는 질문** | "사용자는 무엇을 하고 싶은가?" | "시스템은 어떻게 동작해야 하는가?" |
| **언어** | 일상 한국어, 비즈니스 가치 중심 | 데이터·규칙·제약 중심 |
| **검증 주체** | 사용자/PM (수용 기준 체크) | 개발자/QA (자동·통합 테스트) |
| **변경 이유** | 사용자 요구·시장 반응 | 데이터 모델·성능·보안 |
| **추적 단위** | 워크플로우·결과 | 함수·트랜잭션·필드 |

### 0.2 사용 방법

- 새 기능을 정의할 때: 먼저 **US**를 쓰고, 그것을 충족시키기 위한 **SR**들을 도출.
- 기존 기능을 검수할 때: US 수용 기준으로 사용자 동작 확인 → 통과하면 SR로 내려가서 데이터·동시성·성능 점검.
- 결함이 발생하면: 어느 층에서 깨졌는지 분류 → US 미충족(요구 정의 잘못)인지, SR 미충족(구현 결함)인지.

### 0.3 추적성

기능 ID `FD-TM-NNN` 하나는 1개 이상의 US와 1개 이상의 SR로 분해된다. 본 문서 마지막 섹션의 **추적성 매트릭스**(C.6)에서 매핑을 확인한다.

## A. 사용자 관점 요구사항 (User Requirements)

### A.1 페르소나

| 페르소나 | 주된 동기 | 사용 빈도 |
|---|---|---|
| **PM (Project Manager)** | 다수 프로젝트의 일정을 빠르게 입력·정리하고 진척을 추적 | 매일 |
| **팀원** | 본인 담당 작업의 일정·상태를 빠르게 갱신 | 주 2~3회 |
| **관리자** | 전사 작업·프로젝트를 점검하고 표준 환경을 관리 | 필요 시 |
| **외부 보고 대상** | 주간 보고/대시보드를 빠르게 훑어보기 | 월 1회 |

### A.3 사용자 스토리 상세

#### US-TM-001 — 작업 추가

> **As a** PM, **I want** 트리의 임의 위치에 새 작업을 흐름이 끊기지 않게 빠르게 추가할 수 있기를, **so that** 기획·회의 중 떠오른 작업을 그 자리에서 입력하고 곧장 다음 사고로 넘어갈 수 있다.

- **사용자 가치**: 입력 마찰 최소화 → 누락된 작업이 줄어들고 WBS 완성도 상승.
- **수용 기준** (사용자가 직접 확인):
  - [ ] 표 작업명 셀에서 Enter 한 번으로 같은 레벨 새 행 추가, 자동으로 새 행 작업명 편집 모드 진입
  - [ ] 표 상단의 청색 [+ 새 작업 추가] 입력 행이 스크롤해도 항상 헤더 바로 아래에 보임
  - [ ] 칸반 컬럼 [+ 카드 추가]로 추가하면 그 컬럼의 상태로 작업 생성
  - [ ] 마인드맵에서 노드 선택 + Tab으로 자식 노드 추가
  - [ ] 본인 소유가 아닌 프로젝트에서는 추가 버튼이 회색·비활성으로 보임 + 호버 시 사유 안내

#### US-TM-002 — 인라인 셀 편집

> **As a** 팀원, **I want** 본인 작업의 시작일·종료일·진척도를 모달을 거치지 않고 표 셀에서 바로 고치기를, **so that** 매일 짧게 들어와 한두 셀만 빠르게 갱신하고 나갈 수 있다.

- **사용자 가치**: 일상적 갱신 작업의 마찰을 거의 0에 가깝게.
- **수용 기준**:
  - [ ] 셀을 클릭하면 행이 선택되고, 같은 셀을 한 번 더 클릭하면 입력 모드로 들어감 (엑셀 패턴)
  - [ ] F2 또는 Enter로도 편집 진입 가능
  - [ ] Enter는 값 확정, Esc는 변경 취소, Tab은 다음 컬럼
  - [ ] 담당자 셀을 클릭하면 조직 회원이 자동완성으로 노출, "김"을 치면 김씨만 좁혀짐
  - [ ] 보기 권한만 있으면 셀이 클릭은 되지만 입력 모드로 들어가지 않음

#### US-TM-003 — 작업 모달 편집

> **As a** PM, **I want** 작업의 모든 속성(메모·체크리스트·잠금·의존성·부모)을 한 화면에서 검토·수정하기를, **so that** 표 셀로는 다루기 어려운 항목까지 한 번에 정리할 수 있다.

- **사용자 가치**: 작업의 "전체 상태"를 한눈에 보고 누락 없이 점검.
- **수용 기준**:
  - [ ] 표 행 더블클릭, 칸반 카드 클릭, 마인드맵 노드 더블클릭으로 모달 열림
  - [ ] 메모는 마크다운으로 입력하고 미리보기를 동시에 볼 수 있음
  - [ ] 체크리스트 항목을 [하위 작업으로 변환] 버튼으로 정식 작업으로 승격
  - [ ] 부모 드롭다운에서 자기 자신·후손은 후보로 나타나지 않음(순환 방지)
  - [ ] 보기 권한만 있으면 모달은 열리되 [저장]이 비활성

#### US-TM-004 — 작업 삭제

> **As a** PM, **I want** 잘못 만들거나 더 이상 필요 없는 작업과 그 모든 후손을 한 번에 지우고, **so that** 트리를 깨끗하게 유지할 수 있다.

- **수용 기준**:
  - [ ] 행 선택 + Delete 또는 우클릭 [삭제]로 확인 다이얼로그 노출
  - [ ] 삭제 후 형제 가중치는 합 100으로 자동 재분배됨
  - [ ] 삭제된 작업을 선행으로 가졌던 다른 작업의 의존성에서도 자동 제거
  - [ ] Ctrl+Z 한 번으로 작업·후손·의존성·가중치 모두 복원
  - [ ] 다중 선택에서 일부 작업이 권한 없으면 권한 있는 것만 삭제, 토스트로 건너뛴 수 안내

#### US-TM-005 — 복사·잘라내기·붙여넣기

> **As a** PM, **I want** 같은 구조가 반복되는 작업 묶음(예: 반복되는 주간 의례)을 복사해서 다른 위치나 다른 프로젝트에 빠르게 적용하기를, **so that** 동일 입력을 여러 번 반복하지 않을 수 있다.

- **수용 기준**:
  - [ ] Ctrl+C로 복사한 트리를 Ctrl+V로 붙여넣으면 새 ID로 복제됨 (원본 그대로)
  - [ ] Ctrl+X로 잘라낸 작업을 다른 프로젝트에 붙여넣으면 그 프로젝트로 이동, 일정은 새 프로젝트 범위로 자동 클램프
  - [ ] 다른 프로젝트 작업과 가졌던 의존성은 자동 제거됨

#### US-TM-006 — 들여쓰기 / 내어쓰기

> **As a** PM, **I want** 평면으로 빠르게 적은 작업들을 Tab 한 번으로 부모-자식 트리 구조로 잡기를, **so that** 머릿속의 분류 흐름을 멈추지 않고 입력에서 곧바로 정리로 이어갈 수 있다.

- **수용 기준**:
  - [ ] 작업명 입력 직후 Tab을 누르면 직전 형제의 자식이 됨
  - [ ] Shift+Tab으로 부모의 형제로 올림
  - [ ] 들여쓰기·내어쓰기 시 그 작업의 자식들도 같이 따라 옴
  - [ ] WBS 정렬·필터가 켜져 있으면 들여쓰기 키가 동작하지 않고 안내 토스트
  - [ ] 첫 자식 위치에서 Tab을 누르면(직전 형제 없음) 차단 + 토스트

#### US-TM-007 — 작업 순서 이동

> **As a** PM, **I want** 같은 부모 안에서 형제 작업의 위·아래 순서를 키보드로 빠르게 바꾸기를, **so that** 마우스 드래그 없이 정렬을 다듬을 수 있다.

- **수용 기준**:
  - [ ] Alt+↑ / Alt+↓로 한 칸씩 이동
  - [ ] 이미 첫째/끝이면 무동작 (오류 없이 무시)
  - [ ] WBS 정렬·필터가 켜져 있으면 비활성

#### US-TM-008 — 트리 펼치기·접기

> **As a** 팀원, **I want** 큰 프로젝트에서 내 담당 영역만 펼쳐 보고 나머지는 접기를, **so that** 화면이 정보로 압도되지 않게 한다.

- **수용 기준**:
  - [ ] 행 좌측 ▶ / ▼ 아이콘으로 단일 토글
  - [ ] Shift+→ / Shift+←로 키보드 토글
  - [ ] Ctrl+Alt+숫자(1~9)로 모든 작업을 N 레벨까지 일괄 펼치기
  - [ ] 검색에서 작업으로 점프하면 그 작업의 조상이 자동으로 펼쳐짐

#### US-TM-009 — 다중 선택

> **As a** PM, **I want** 여러 작업을 한꺼번에 선택해서 같은 동작을 한 번에 적용하기를, **so that** 동일 동작을 N번 반복하지 않을 수 있다.

- **수용 기준**:
  - [ ] 체크박스 클릭으로 단일 토글
  - [ ] Shift+클릭으로 마지막 선택~클릭 사이 모두 선택
  - [ ] Ctrl+클릭으로 비연속 추가/제거
  - [ ] 헤더 체크박스로 현재 보이는 작업 모두 선택/해제 (필터로 가려진 작업은 미선택)

#### US-TM-010 — 일괄 수정

> **As a** PM, **I want** 선택한 작업들의 상태·담당자·일정 같은 공통 속성을 한 번에 바꾸기를, **so that** 분기 말 같은 일괄 정리 작업이 빠르게 끝난다.

- **수용 기준**:
  - [ ] 2개 이상 선택 시 화면 하단에 일괄 수정 바 등장
  - [ ] 담당자 일괄 변경 시 "자식 캐스케이드" 옵션으로 후손까지 같은 담당자 적용
  - [ ] [선행 순차 연결]로 선택 표시 순서대로 위→아래 FS 의존성 자동 체인
  - [ ] 권한 없는 작업이 섞여 있으면 그것만 건너뛰고 토스트 안내

#### US-TM-011 — 컨텍스트 메뉴

> **As a** PM, **I want** 마우스 우클릭으로 자주 쓰는 동작(추가·삭제·들여쓰기·마일스톤 토글 등)을 바로 호출하기를, **so that** 단축키를 외우지 않아도 빠르게 작업할 수 있다.

- **수용 기준**:
  - [ ] 행 우클릭으로 메뉴 노출 (위·아래·하위 추가, 들여쓰기, 복사·붙여넣기, 마일스톤·이슈, 베이스라인, 변경 이력, 삭제)
  - [ ] 보기 권한만 있으면 메뉴에 [변경 이력]만 노출, 편집 항목은 미표시
  - [ ] 단일 선택일 때 [선행 순차 연결]은 미노출 (다중 전용)

#### US-TM-012 — 사용자 정의 컬럼

> **As a** PM, **I want** 우리 조직 고유의 메타데이터(예: 발주처, 산출물 코드)를 표 컬럼으로 추가하기를, **so that** 별도 엑셀 없이 한 표에서 모든 정보를 다룰 수 있다.

- **수용 기준**:
  - [ ] 환경설정에서 [컬럼 추가] → 이름 입력 → 모든 사용자의 표에 즉시(또는 다음 동기화 시) 반영
  - [ ] 컬럼 삭제 시 영향 작업 수가 다이얼로그에 표시됨
  - [ ] 일반 회원도 추가/수정/삭제 가능 (단, 안내 문구로 "모든 사용자에게 공유됨" 명시)

#### US-TM-013 — 검색·이동

> **As a** PM, **I want** 키워드 한 번으로 전 프로젝트의 작업을 찾고 그 위치로 점프하기를, **so that** 어느 프로젝트에 있는지 기억하지 않아도 된다.

- **수용 기준**:
  - [ ] Ctrl+K로 검색창 즉시 열림
  - [ ] 입력에 따라 작업명·메모·담당자에서 매칭 (사용자가 접근 권한 가진 프로젝트만)
  - [ ] 결과 클릭 시 해당 프로젝트로 전환 + 표 화면으로 점프 + 조상 자동 펼침 + 행 강조
  - [ ] 작업이 활성 필터로 가려져 있으면 토스트 "필터로 가려졌습니다 [필터 해제]" 안내

## B. 시스템 관점 요구사항 (System Requirements)

### B.1 일반 비-기능 요구사항 (cross-cutting)

| ID | 분류 | 요구 |
|---|---|---|
| SR-TM-NFR-PERF-01 | 성능 | 단일 작업 추가/수정 후 표 반영 < 200ms (작업 1000건 이내) |
| SR-TM-NFR-PERF-02 | 성능 | 작업 1000건 표 스크롤 60fps 유지 |
| SR-TM-NFR-PERF-03 | 성능 | 자동 일정 산정(작업 100건) < 500ms |
| SR-TM-NFR-DATA-01 | 데이터 | 모든 변경은 1초 디바운스 후 IndexedDB(또는 localStorage 폴백)에 영속화 |
| SR-TM-NFR-DATA-02 | 데이터 | DB 동기화는 사용자 명시 트리거 또는 5분 주기 풀 (Realtime은 옵션) |
| SR-TM-NFR-AUDIT-01 | 감사 | 모든 작업 INSERT/UPDATE/DELETE는 `wbs_audit_log`에 기록 |
| SR-TM-NFR-AUTH-01 | 권한 | 모든 변경은 클라이언트 `canEditCurrentProject` + DB RLS의 이중 게이팅 |
| SR-TM-NFR-CONC-01 | 동시성 | 같은 셀 동시 편집은 LWW(Last-Write-Wins) — 시각적 표시만, 명시 충돌 해소 UI 없음 |

### B.2 기능별 시스템 요구사항

각 SR는 다음 항목으로 정의된다:
- **트리거**: 어떤 조건/이벤트에 발동
- **입력 무결성**: 입력 검증·필수 필드
- **처리 규칙**: 핵심 알고리즘·자동 보정
- **데이터 영향**: 어떤 테이블/필드에 어떤 작업
- **사후 조건**: 트랜잭션 후 보장되어야 하는 상태
- **예외**: 실패·차단 케이스
- **검증 방법**: 자동 테스트 가능한 단위 테스트/통합 테스트

---

#### SR-TM-001 — 작업 추가

- **트리거**: `addTask(newTask, insertAfterId?, projectIdOverride?)` 호출
- **입력 무결성**:
  - `name`은 필수 (빈 문자열 허용 — UI에서 빈 작업명 행은 자동 삭제)
  - `parentId`는 같은 `projectId`의 기존 작업 ID이거나 `null`
  - `parentId`가 자기 자신이거나 후손이면 거부
- **처리 규칙**:
  - `id`는 클라이언트가 UUID v4 발급
  - `projectId`는 다음 우선순위로 결정: `projectIdOverride` → `currentProjectId` → `currentProjectId === 'all'`이면 `projects[0].id`
  - 형제 가중치 합 100 보장 (`rescaleSiblingsToSum100`)
  - 일정이 프로젝트 범위 밖이면 클램프 (`clampTaskToProjectRange`)
  - `startDate > endDate`이면 `startDate = endDate`로 정규화
  - 부모 체인 롤업(`syncParentRollups`) — 잠금 필드 존중
- **데이터 영향**:
  - `tasks` INSERT (id·project_id·parent_id·sort_order·name·start_date·end_date·work_effort·progress·status·assignee·weight·is_milestone·is_issue·expanded·custom_fields)
  - `tasks` UPDATE (형제 weight·sort_order, 부모 체인 start_date·end_date·progress·status)
  - `wbs_audit_log` INSERT (action='create')
- **사후 조건**:
  - 같은 부모 형제 weight 합 = 100 (소수 1자리)
  - 부모 startDate ≤ 자식 startDate min, 부모 endDate ≥ 자식 endDate max (잠금 없을 때)
  - DB와 클라이언트 fingerprint 동일 (다음 동기화 후)
- **예외**:
  - DB RLS 차단 → 토스트 "권한 없음" + 로컬 변경 롤백
  - 같은 ID UUID 충돌 (확률 0에 가까움) → upsert로 자동 해결
- **검증**:
  - Unit: `addTask` 단독 호출 시 형제 weight 합 100 보장
  - Unit: `clampTaskToProjectRange`가 범위 밖 일정을 정확히 클램프
  - Integration: 프로젝트 P 선택 + `addTask` → DB에서 P의 작업 수 +1

#### SR-TM-002 — 인라인 셀 편집 (단일 필드 UPDATE)

- **트리거**: `updateTask(id, partialUpdates)` 호출
- **입력 무결성**:
  - `id`는 기존 task.id
  - 컬럼별 타입 검증 (날짜는 YYYY-MM-DD, 숫자는 finite)
  - `progress`는 0~100, `weight`는 ≥0, `workEffort`는 ≥0
- **처리 규칙**:
  - 사용자 직접 편집 시 해당 필드를 `userLockedFields`에 자동 추가
  - `startDate` 변경 → workEffort로 endDate 자동 재계산 (endDate 잠금 없을 때)
  - `endDate` 직접 편집 → startDate 역산 (startDate 잠금 없을 때)
  - 의존성 변경 → 순환 검사(`hasDependencyCycle`) 후 시프트
  - 가중치 변경 → 형제 합 100 재정규화
  - 상태 변경 + `linkStatusAndProgress=true` → progress 자동
  - 자식 변경 → 부모 롤업 (잠금 존중 정책)
- **데이터 영향**: `tasks` UPDATE (변경 필드 + 자동 산정 필드 + 부모 체인 + audit_log)
- **사후 조건**:
  - 사용자 직접 편집 필드는 `userLockedFields`에 포함됨
  - 자동 산정 결과는 잠금 필드 외에만 반영됨
- **예외**:
  - 순환 의존성 시도 → 변경 거부 + 편집 모드 유지
  - 잠금 필드를 자동 산정이 변경하려 함 → 차단(잠금이 우선)
- **검증**:
  - Unit: startDate 변경 시 endDate 자동 산정 정확성
  - Unit: 잠금된 필드에 자동 산정 시 변경 없음
  - Property: 가중치 임의 변경 후 형제 합 = 100 (±0.1 허용)

#### SR-TM-003 — 모달 편집 (다중 필드 UPDATE + 메타)

- SR-TM-002와 동일한 핵심 규칙 + 추가:
  - `memo`, `checklist`, `userLockedFields`, `parentId` 변경 가능
  - `parentId` 변경 시: 이전 부모 그룹·새 부모 그룹 모두 가중치 재정규화 + 양쪽 롤업
- **검증**:
  - Integration: 모달에서 부모 변경 → 양쪽 부모 그룹의 weight 합 모두 100
  - Property: 후손을 부모로 지정 시도 → UI에서 후보 제외 + 직접 호출에는 거부

#### SR-TM-004 — 작업 삭제 (cascade)

- **트리거**: `deleteTask(id)` 또는 `deleteTasks(ids)`
- **처리 규칙**:
  - 후손 일괄 수집(`collectDescendantTaskIds`) 후 모두 삭제
  - 삭제된 ID를 선행으로 참조하는 다른 작업의 `dependencies`에서 제거
  - 형제 가중치 재정규화
  - 부모 체인 롤업
  - `wbs_audit_log` INSERT (action='delete')
- **데이터 영향**: `tasks` DELETE (해당 + 후손), `tasks` UPDATE (의존성·형제·부모 체인)
- **사후 조건**: 다른 작업에 cascade 정합성 유지 (없는 ID 참조 0건)
- **검증**:
  - Integration: 부모 삭제 → 후손도 모두 삭제 + 의존성 dangling 0
  - Undo: 삭제 직후 Ctrl+Z → 모든 데이터(작업·의존성·가중치) 원복

#### SR-TM-005 — 복사·잘라내기·붙여넣기

- **트리거**: `Ctrl+C` / `Ctrl+X` / `Ctrl+V` 키보드 또는 컨텍스트 메뉴
- **저장**: localStorage 키 `wbs:clipboard:v1`에 트리 + 모드 + 타임스탬프
- **처리 규칙**:
  - **복사**: 모든 작업에 새 UUID, parentId·dependencies는 매핑 후 새 ID로 변환, 클립보드 외부 의존성은 제거
  - **잘라내기**: 원본 ID 유지, parentId만 변경
  - 다른 프로젝트 붙여넣기: projectId 교체 + 일정 클램프 + 외부 프로젝트 의존성 제거
- **데이터 영향**: `tasks` INSERT(복사) 또는 UPDATE(이동)
- **검증**:
  - Unit: 복사 후 ID 매핑이 자기 참조 없이 정확
  - Integration: 다른 프로젝트로 잘라내기 → 일정 클램프, 의존성 제거

#### SR-TM-006 — 들여쓰기·내어쓰기

- **트리거**: `Tab` / `Shift+Tab`
- **사전 조건**:
  - `canEditCurrentProject = true`
  - WBS 정렬 = 'wbs asc' 또는 정렬 해제 (그 외엔 거부)
  - 들여쓰기: 직전 형제 존재
  - 내어쓰기: 부모 존재
- **처리 규칙**:
  - 후손 동반 이동
  - 새 부모와 의존성 사이 순환 형성 시 거부
  - 새 부모 일정 범위 밖이면 클램프
  - 양쪽 부모 그룹 가중치 재정규화 + 롤업
- **데이터 영향**: `tasks` UPDATE (parent_id, sort_order, 가중치, 부모 체인)
- **검증**:
  - Unit: Tab 적용 시 parentId가 직전 형제 ID로
  - Property: 정렬 ≠ 'wbs asc'이면 Tab 호출이 무동작

#### SR-TM-007 — 형제 순서 이동

- **트리거**: `Alt+↑` / `Alt+↓`
- **처리 규칙**: 위/아래 형제와 sort_order 교환만, 다른 필드 영향 없음
- **데이터 영향**: `tasks` UPDATE (sort_order × 2건)
- **검증**: Unit: 첫째 위치에서 Alt+↑은 무동작

#### SR-TM-008 — 트리 펼치기·접기

- **트리거**: 행 토글 / `Shift+→·←` / `Ctrl+Alt+1~9` / 검색 점프 시 자동
- **데이터 영향**: `tasks` UPDATE (expanded — 단일 또는 다건)
- **사후 조건**:
  - 단일 토글: 그 행만 변경
  - N 레벨 펼치기: 모든 작업의 expanded 일관 상태
- **검증**: Property: 깊이 N 토글 후 깊이 ≤N의 expanded=true, >N의 expanded=false

#### SR-TM-009 — 다중 선택 상태 관리

- **클라이언트 상태**: `selectedTaskIds: Set<string>`, `lastSelectedId: string | null`
- **처리 규칙**:
  - Shift+클릭: lastSelectedId ~ click 사이의 visibleTasks 모두 추가
  - Ctrl+클릭: 단일 토글 + lastSelectedId 갱신
  - 헤더 체크박스: visibleTasks ⊆ selectedTaskIds 여부로 토글 방향 결정
- **데이터 영향**: 없음 (메모리 상태만)
- **사후 조건**: 프로젝트 전환·뷰 전환 시에도 유지(명시적 초기화 없음)
- **검증**: Unit: Shift+클릭 범위 정확

#### SR-TM-010 — 일괄 수정

- **트리거**: 일괄 수정 바의 [적용] 또는 액션 버튼
- **트랜잭션**: 모든 변경을 단일 setAllTasks로 묶어 한 번에 반영
- **처리 규칙**:
  - 권한 없는 작업은 자동 제외
  - 담당자 자식 캐스케이드 옵션: 후손 ID 수집 후 같은 patch 적용
  - [선행 순차 연결]: 표시 순서 idx>0인 작업의 dependencies = [이전 작업 id]
  - [선행작업 지우기]: dependencies=[] + userLockedFields에 'dependencies' 추가
- **검증**: Integration: 권한 혼합 선택 시 권한 있는 것만 변경

#### SR-TM-011 — 컨텍스트 메뉴

- **렌더링 규칙**: `canEditCurrentProject` 기반 항목 필터링
- **데이터 영향**: 항목별 다른 SR (FD-TM-001/004/005/006 등)에 위임
- **검증**: 권한 등급별 메뉴 항목 노출 일치

#### SR-TM-012 — 사용자 정의 컬럼

- **저장 위치**:
  - 컬럼 정의: `wbs_settings.config_json.customColumns[]`
  - 셀 값: `tasks.custom_fields` JSONB
- **처리 규칙**:
  - 컬럼 ID 형식: `custom:<timestamp>` (충돌 방지)
  - 미입력 셀은 키 자체 미저장 (sparse)
  - 컬럼 삭제: 정의 + 모든 작업의 `custom_fields[colId]` 키 제거 (지연 정리 가능)
- **데이터 영향**:
  - `wbs_settings` UPDATE (config_json)
  - `tasks` UPDATE (custom_fields, 다건)
- **검증**: Integration: 컬럼 삭제 후 모든 작업에서 그 키가 없음

#### SR-TM-013 — 검색

- **검색 범위**: `name`, `description/memo`, `assignee`, `custom_fields` 텍스트 값
- **권한 필터**: RLS 자연 적용 (사용자가 SELECT 가능한 작업만)
- **결과 정렬**: `name` 일치 우선 → `memo` 일치 → 기타
- **점프 처리**:
  - `currentProjectId` = 작업의 projectId
  - `view` = 'table'로 강제
  - 조상 모두 expanded=true
  - `scrollToTaskId` 설정 후 500ms 후 해제 + 표 focus
- **검증**: Unit: 검색 결과 정렬 우선순위, Integration: 다른 프로젝트 작업 점프 시 프로젝트 전환

### D.1 신규 기능 추가 시

1. **US 먼저** — 어떤 사용자가 무엇을, 왜 원하는지 한 줄 작성
2. **수용 기준** — 사용자가 직접 체크할 수 있는 항목을 5개 이내로
3. **SR 도출** — US를 만족시키려면 시스템이 무엇을 해야 하는지 (트리거·데이터·예외·검증)
4. **불변식 영향** — 기존 INV-TM-NN을 깨지 않는지 확인. 새 불변식이 필요하면 추가
5. **추적성 갱신** — 매트릭스에 새 행 추가
6. **원본 FD 갱신** — `01_작업관리.md`에도 동일 ID로 상세 스펙 작성

### D.2 결함 분류

- **US 미충족**: 사용자가 원한 워크플로우대로 동작하지 않음 → 요구사항 재정의 필요
- **SR 미충족 (기능)**: US는 맞지만 시스템 규칙대로 동작하지 않음 → 코드 결함, 테스트로 회귀 방지
- **SR 미충족 (불변식)**: 데이터 무결성이 깨짐 → 긴급. 데이터 복구 절차 + 코드 수정
- **NFR 미충족**: 동작은 맞지만 느리거나 보안 문제 → 별도 트랙
