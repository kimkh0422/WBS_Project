| 항목 | 값 |
|---|---|
| 그룹 ID | SCH (Scheduling) |
| 기능 ID 범위 | FD-SCH-001 ~ FD-SCH-012 |

## 0. 그룹 개요

### 0.1 범위

본 그룹은 작업의 **일정 자동 산정 / 의존성 관리 / 캘린더(휴일) / 상태 정의 / 진척도 / 가중치 / 부모 롤업 / 잠금 필드 정책**을 정의한다. 사용자가 시작일·공수만 입력해도 휴일·의존성을 반영해 종료일이 산출되도록 하는 것이 핵심이다.

### 0.2 비-목표

- 작업 CRUD 자체 (→ FD-TM)
- 프로젝트 일정 클램프 (→ FD-PM-007)
- 화면 표시 규칙 (→ FD-UI)
- 자원 평준화·CPM 자동 분석 (제품 비-목표)

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **MD (Man-Day)** | 1인이 1영업일(8시간)에 수행하는 작업량 |
| **영업일** | 월~금 중 공휴일이 아닌 날 |
| **FS (Finish-to-Start)** | 의존성 유형. 후행은 선행이 끝난 다음 영업일에 시작 |
| **위상 정렬** | 의존성 그래프의 노드를 선행→후행 순서로 정렬 |
| **롤업(Rollup)** | 자식들의 값으로 부모 값을 도출 |
| **캐스케이드(Cascade)** | 변경이 자식·후행으로 자동 전파 |
| **잠금 필드** | 자동 산정 제외할 필드 (`userLockedFields`) |
| **진척도(Progress)** | 0~100 정수. 작업 완료도 |
| **가중치(Weight)** | 같은 부모 자식들의 progress 가중평균에 사용 |
| **상태(Status)** | 작업의 단계 (todo / in-progress / done 등). 환경설정에서 정의 |

## 1. 데이터 정의 (관련 필드)

```ts
type Task = {
  startDate?: string;       // YYYY-MM-DD
  endDate?: string;
  workEffort?: number;      // 단위 = project.work_effort_unit
  status?: string;          // 환경설정의 status_configs[].id
  progress?: number;        // 0~100
  weight?: number;          // 같은 부모 자식 합 = 100
  dependencies?: string[];  // 선행 작업 ID 배열
  userLockedFields?: ('startDate' | 'endDate' | 'workEffort' | 'progress' | 'dependencies')[];
}
```

```ts
{
  statusConfigs: { id, name, color, progress }[],
  linkStatusAndProgress: boolean,
  customColumns: { id, name, ...}[]
}
```

## 2. 상세 기능 정의

### FD-SCH-001 — 영업일·휴일 캘린더

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

자동 일정 산정과 영업일 계산의 기준이 되는 휴일을 결정한다.

#### 4. 처리 규칙

##### 4.1 휴일 정의

- 주말(토·일)은 항상 휴일.
- 한국 법정 공휴일(양력·음력·임시 공휴일) 자동 포함.
- 환경설정에서 사용자 추가 휴일·근무일 변경 가능 (예: 사내 창립기념일, 명절 대체 영업).

##### 4.2 음력 공휴일

- 매년 자동 계산 (설·추석은 음력→양력 변환).
- 대체 공휴일 규칙 적용 (일요일과 겹치면 다음 평일).

##### 4.3 캐싱

- `getHolidaysForTaskDates(tasks)` — 작업 일정 범위에 해당하는 휴일만 캐싱하여 매 산정마다 재계산 비용 줄임.

#### 11. 수용 기준

```
AC-FD-SCH-001-1
  Given 2026년 캘린더
  When 추석(2026-10-04 일요일) 처리
  Then 추석 당일은 휴일
       대체 공휴일은 2026-10-05 (월요일)도 휴일

AC-FD-SCH-001-2
  Given 환경설정에서 2026-12-31 사내 휴일 추가
  When 작업 산정에서 2026-12-31 평일 처리
  Then 영업일에서 제외, 종료일 자동 산정 시 건너뜀
```

### FD-SCH-002 — 공수→종료일 자동 산정

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

사용자가 시작일·공수만 입력하면 휴일과 투입율을 반영해 종료일을 산출한다.

#### 4. 처리 규칙

##### 4.1 산정식 (의사코드)

```
computeEndDateFromEffort(startDate, effortMD, assignments, holidays):
    ratio = max(sum(assignments[].ratio), 0.01)   # 0이면 0.01로 보정 (무한 방지)
    actualDays = ceil(effortMD / ratio)
    cur = startDate
    accumulated = 0
    while accumulated < actualDays:
        if cur is not weekend and cur not in holidays:
            accumulated += 1
            if accumulated == actualDays: return cur
        cur = cur + 1 day
    return cur
```

##### 4.2 단위 환산

- 작업의 `work_effort` × 프로젝트 단위 → MD 환산:
  - `MD` × 1
  - `MM` × 20
  - `H` × 0.125

##### 4.3 트리거

- 사용자가 `startDate` 또는 `workEffort` 변경 시 종료일 재계산.
- `endDate` 잠금이면 재계산 결과를 적용하지 않음.

##### 4.4 종료일에서 시작일 역산

- `endDate`만 변경된 경우 (`startDate` 미잠금) → 영업일 역방향 누적으로 `startDate` 산출.

#### 11. 수용 기준

```
AC-FD-SCH-002-1
  Given 작업 T (start=2026-06-01 월, workEffort=5MD, 투입율=100%, 공휴일 6/6)
  When 자동 산정
  Then T.endDate = 2026-06-08 (월~금 중 6/6 제외 → 5영업일 후)

AC-FD-SCH-002-2
  Given T (effort=5MD, 투입율=50%)
  When 산정
  Then 실제 영업일 10일 누적 → endDate 그만큼 늘어남

AC-FD-SCH-002-3
  Given T.userLockedFields=['endDate']
  When workEffort 변경
  Then endDate 미변경 (잠금)

AC-FD-SCH-002-4
  Given T (endDate=2026-06-15, startDate 미잠금, workEffort=5MD)
  When 사용자가 endDate=2026-06-30으로 변경
  Then startDate가 영업일 5일 역산되어 자동 변경
```

### FD-SCH-003 — 의존성(FS) 자동 시프트

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

선행 작업의 종료일이 변하면 후행 작업이 자동으로 다음 영업일부터 시작하도록 일정을 시프트한다.

#### 4. 처리 규칙

##### 4.1 위상 정렬

- 의존성 그래프를 위상 정렬하여 선행→후행 순서로 처리.
- 순환 발견 시 [FD-SCH-004](#fd-sch-004--순환-의존성-차단)에서 차단.

##### 4.2 시프트 알고리즘 (의사코드)

```
applyDependencySchedule(tasks, projectAssignments, excludeIds):
    order = topologicalSort(tasks by dependencies)
    for task in order:
        if task.id in excludeIds: continue
        if task.userLockedFields contains 'startDate': continue
        deps = task.dependencies
        if deps empty: continue
        latestEnd = max(predecessor.endDate for predecessor in deps)
        nextWorkday = nextBusinessDay(latestEnd)
        if task.startDate < nextWorkday:
            task.startDate = nextWorkday
            recompute task.endDate (FD-SCH-002)
```

##### 4.3 같은 담당자 한정 시프트 (선택)

- 부하 분산을 위해 같은 담당자가 여러 후행을 가지면 순차 처리 — 이후 확장 옵션 (`assigneeChainShift=true`).

##### 4.4 잠금 존중

- `startDate` 잠금: 시프트 제외.
- `endDate` 잠금: startDate 시프트는 되지만 endDate 재계산 안 함.

#### 7. 예외

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 선행 작업의 종료일이 후행보다 늦음 (사용자 수동 입력) | 후행 시프트로 자연 보정 |
| EX-002 | 선행이 잠금된 종료일 + 후행도 잠금된 시작일 | 둘 다 변경 안 됨 → 충돌 표시 (시각 경고) |

#### 11. 수용 기준

```
AC-FD-SCH-003-1
  Given A→B→C 의존성 (A end=6/10, B start=6/11, C start=6/13)
  When A.endDate를 6/15로 변경
  Then B.startDate=다음 영업일(6/16), B.endDate 재계산
       C.startDate=B의 새 endDate 다음 영업일

AC-FD-SCH-003-2
  Given B.userLockedFields=['startDate'], A.endDate 변경
  When 시프트 트리거
  Then B 미변경, B의 후행만 영향 받음
       시각 경고: A-B 사이에 startDate 잠금으로 FS 충돌 가능
```

### FD-SCH-004 — 순환 의존성 차단

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 검증 시점

- 사용자가 의존성 추가 시 `hasDependencyCycle(tasks, taskId, newDeps)` DFS로 사이클 탐지.
- 발견 시 토스트 + 변경 거부.

##### 4.2 알고리즘

```
hasDependencyCycle(tasks, taskId, newDeps):
    graph = build adjacency: { id -> dependencies }
    graph[taskId] = newDeps
    visited = set()
    onStack = set()
    return dfs(taskId)  # true if cycle
```

#### 11. 수용 기준

```
AC-FD-SCH-004-1
  Given A→B 의존성
  When B의 의존성에 A 추가 시도 (B→A → 순환)
  Then 차단, 토스트 "순환 의존성: A → B → A"

AC-FD-SCH-004-2
  Given A→B→C 의존성
  When A의 의존성에 C 추가 시도
  Then 차단, 토스트 "순환 의존성"
```

### FD-SCH-005 — 자동 일정 동기화 트리거

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 트리거 이벤트

| 이벤트 | 트리거되는 산정 |
|--------|------------------|
| `startDate` 변경 | endDate 재계산(공수 기반), 후행 시프트 |
| `endDate` 변경 | startDate 역산(잠금 아닐 때), 후행 시프트 |
| `workEffort` 변경 | endDate 재계산 |
| 의존성 추가/제거 | 후행 시프트 |
| 작업 추가 | 부모 롤업 |
| 작업 삭제 | 형제 weight 재정규화 + 부모 롤업 |
| 들여쓰기·내어쓰기 | 새 부모 롤업, 이전 부모 롤업 |
| 프로젝트 일정 변경 | 작업 클램프 ([FD-PM-007](./02_프로젝트관리.md)) |
| 환경설정 휴일 변경 | 전 작업 endDate 재계산 |

#### 11. 수용 기준

```
AC-FD-SCH-005-1
  Given A→B 의존성, A workEffort 5MD → 8MD 변경
  When 변경 저장
  Then A.endDate 재계산
       B.startDate 자동 시프트
       부모 P의 endDate 롤업 갱신
       모두 1회 트랜잭션 단위로 처리 (UI 깜빡임 최소화)
```

### FD-SCH-006 — 부모 일정 롤업

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

```
parent.startDate = min(children.startDate)
parent.endDate   = max(children.endDate)
```

##### 4.1 잠금 정책

- 부모 일정은 `userLockedFields`와 무관하게 **항상 자식의 min/max로 동기화**.
  → 이유: 부모 일정은 자식의 합산이지 독립 입력이 아니다.

##### 4.2 재귀 전파

- 부모 변경 후 그 조부모도 같은 규칙으로 갱신. 루트까지 전파.

##### 4.3 자식이 0건일 때

- 부모는 일정 직접 입력 모드. 자식 추가 후에는 자동 동기화로 전환.

#### 11. 수용 기준

```
AC-FD-SCH-006-1
  Given 부모 P, 자식 C1 (6/1~6/10), C2 (6/5~6/20)
  When 자동 롤업
  Then P.startDate=6/1, P.endDate=6/20

AC-FD-SCH-006-2
  Given P.userLockedFields=['startDate']
  When 자식 변경 → 롤업
  Then P.startDate가 자식 min으로 동기화 (잠금 무시 — 일정 롤업 정책)
```

### FD-SCH-007 — 상태 정의 관리

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 상태 스키마

```ts
type StatusConfig = {
  id: string;        // 'todo', 'doing', 'done', 또는 사용자 정의
  name: string;      // '시작 전'
  color: string;     // Tailwind 클래스 또는 HEX
  progress: number;  // 이 상태일 때의 기본 진척도 (0~100)
}
```

##### 4.2 기본 상태

- `todo` (시작 전, progress=0)
- `doing` (진행 중, progress=50)
- `done` (완료, progress=100)

##### 4.3 사용자 정의 상태

- 환경설정 → 상태/진척도 탭에서 추가·수정·순서 변경·삭제.
- 색은 프리셋 + 사용자 HEX (#RRGGBB).
- 삭제 시 해당 상태 사용 작업 수 표시 + 대체 상태 선택 강제.

##### 4.4 권한

- 관리자(`effectiveIsAdmin`)만 상태 정의 변경.

#### 11. 수용 기준

```
AC-FD-SCH-007-1
  Given 환경설정 → 상태 탭, 관리자
  When 상태 "검토 중" 추가 (progress=80, 색=주황)
  Then statusConfigs에 추가됨
       표 상태 셀 드롭다운에 "검토 중" 등장 (모든 사용자에게)

AC-FD-SCH-007-2
  Given 상태 "검토 중" 사용 작업 12건
  When 해당 상태 [삭제] 시도
  Then 다이얼로그 "12건의 작업이 이 상태입니다. 대체 상태를 선택하세요"
       대체 상태 선택 후 확인 → 12건 작업의 status가 대체값으로 일괄 갱신
```

### FD-SCH-008 — 상태↔진척도 연동

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 토글 (`linkStatusAndProgress`)

- 환경설정 → 상태/진척도 탭의 토글 (전역).

##### 4.2 ON일 때 (기본)

- 상태 변경 → progress 자동 = 해당 상태의 progress 값.
- 사용자가 동일 입력에서 progress를 함께 명시하면 사용자 입력값 우선.

##### 4.3 OFF일 때

- 상태와 진척도 독립 — 사용자가 직접 둘 다 입력.

#### 11. 수용 기준

```
AC-FD-SCH-008-1
  Given linkStatusAndProgress=true, 작업 T (status='todo', progress=0)
  When status='done'으로 변경
  Then T.progress=100 자동

AC-FD-SCH-008-2
  Given linkStatusAndProgress=false
  When status='doing'으로 변경
  Then T.progress 변화 없음 (수동 입력 유지)

AC-FD-SCH-008-3
  Given linkStatusAndProgress=true, 사용자가 동일 동작에서 status='done', progress=80 함께 저장
  When 저장
  Then T.progress=80 (사용자 입력 우선)
       T.status='done'
```

### FD-SCH-009 — 부모 진척도·상태 롤업

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 진척도 롤업 (`syncParentRollups`)

```
parent.progress = Σ(child.progress × weight) / Σ(weight)
```

- weight 합 0 → 단순 평균 fallback.
- 부모의 `progress` 잠금:
  - 자식 변경 전파 경로(`forceProgress=true`)이면 잠금 **무시**하고 강제 롤업.
  - 부모 단독 표시 갱신(`forceProgress=false`)이면 잠금 보존.

##### 4.2 상태 롤업 (`syncParentStatus`)

| 자식 상태 분포 | 부모 상태 |
|----------------|-----------|
| 모두 완료(progress=100) | 완료 상태 |
| 일부 완료/진행 | 진행 중 (가장 작은 progress의 진행 중 상태 우선) |
| 모두 시작 전(progress=0) | 시작 전 |

##### 4.3 강제 롤업 옵션

- 자식 변경 시 `syncParentRollups(..., forceProgress=true)` 호출 → 잠금 무시.
- 부모 단독 표시 변경 시 `forceProgress=false` → 잠금 존중.

#### 11. 수용 기준

```
AC-FD-SCH-009-1
  Given 부모 P, 자식 C1(weight=30, progress=100), C2(weight=70, progress=50)
  When 자동 롤업
  Then P.progress = (30×100 + 70×50) / 100 = 65

AC-FD-SCH-009-2
  Given P.progress=50 잠금, 자식 모두 완료(100)
  When 자식 변경 전파 (forceProgress=true)
  Then P.progress=100 (잠금 무시)

AC-FD-SCH-009-3
  Given P 자식 모두 진행 중
  When 상태 롤업
  Then P.status='doing' (또는 가장 작은 progress의 진행 상태)
```

### FD-SCH-010 — 가중치 분배·재정규화

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 신규 추가 시

- `n` = 추가 후 형제 수.
- 새 작업 weight = `100/n`.
- 기존 형제는 비율 유지하며 `100 - 100/n`을 비례 재분배.

##### 4.2 형제 weight 변경 시

- `rescaleSiblingsToSum100(tasks, projectId, parentId, anchorId)` — 변경된 작업(anchorId)의 weight는 그대로, 나머지 형제를 비율 유지하며 재정규화.

##### 4.3 부모 weight 직접 입력 시

- 부모 weight 변경 → 부모의 형제들도 합 100 보장 재분배.
- 자식 weight 비율은 유지(`redistributeWeightsDown`).

##### 4.4 부모 progress 직접 입력 시

- 자식들에게 비례 분배 (`distributeProgressDown`).
- 자식들의 weight 비율로 progress 분배.

##### 4.5 표시 정밀도

- 표시·저장 모두 소수 1자리 (`round1`).

#### 11. 수용 기준

```
AC-FD-SCH-010-1
  Given 부모 P, 형제 C1 weight=50, C2 weight=50
  When C3 신규 추가
  Then C3.weight=33.3, C1.weight=33.3, C2.weight=33.3 (합 99.9 ≈ 100, 마지막 1건 보정)

AC-FD-SCH-010-2
  Given C1=30, C2=70
  When C1을 40으로 변경
  Then C1=40, C2=60 (비율 유지하며 재정규화)

AC-FD-SCH-010-3
  Given 부모 P의 progress=80을 직접 입력, 자식 C1·C2 (weight=50/50)
  When 저장
  Then C1.progress=80, C2.progress=80 (비례 분배)

AC-FD-SCH-010-4
  Given 부모 P.weight=20 → 30으로 변경, 자식들 weight 합 100
  When 저장
  Then P의 형제들 합 100 재분배
       자식들 weight 비율 유지
```

### FD-SCH-011 — 잠금 필드 정책

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

자동 산정·롤업·AI 보정에서 사용자가 의도적으로 보호하고 싶은 필드를 제외한다.

#### 4. 처리 규칙

##### 4.1 잠금 가능 필드

`userLockedFields: ('startDate' | 'endDate' | 'workEffort' | 'progress' | 'dependencies')[]`

##### 4.2 잠금 영향 매트릭스

| 필드 | 자동 산정 | 부모 롤업 | AI 보정 |
|------|:---------:|:---------:|:-------:|
| `startDate` | 제외 | n/a (롤업은 자식 min/max로) | 제외 |
| `endDate` | 제외 | n/a | 제외 |
| `workEffort` | 제외 | — | 제외 |
| `progress` | — | 자식 변경 시 강제 롤업 / 부모 단독 갱신 시 보존 | 제외 |
| `dependencies` | 자동 추가 차단 | — | 제외 |

##### 4.3 토글 위치

- TaskModal — 각 필드 옆 자물쇠 아이콘 또는 [잠금] 체크.
- 일괄 액션 [선행작업 지우기]는 자동으로 `dependencies` 잠금 추가.

#### 11. 수용 기준

```
AC-FD-SCH-011-1
  Given 작업 T.userLockedFields=['endDate']
  When workEffort 변경 → 자동 산정
  Then T.endDate 그대로 (잠금)
       startDate, workEffort는 입력 반영

AC-FD-SCH-011-2
  Given 일괄 [선행작업 지우기] 실행
  When 선택 작업들
  Then 그들의 dependencies=[] + userLockedFields에 'dependencies' 추가
       이후 자동 시프트에서 의존성 자동 추가 차단
```

### FD-SCH-012 — 자원 부하 경고

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 1. 목적

같은 담당자가 동일 영업일에 100% 초과 투입되면 시각적으로 경고하여 부하 조정 기회를 제공한다.

#### 4. 처리 규칙

##### 4.1 부하 계산

- `computeWorkloadOverloads(tasks, assignments, holidays)` — 담당자별·일별 누적 투입율.
- 임계치: 100%(설정 가능). 초과 시 `overload=true`.

##### 4.2 표시

- 표 컬럼 [부하] 또는 별도 [투입현황] 페이지([FD-UI-008](./04_화면_뷰.md)).
- 간트 차트 위에 부하 바.

##### 4.3 자동 보정 옵션

- `fixOverloadByExtending(tasks, day)` — 일정 늘려 분산.
- `fixOverloadByIncreasingAllocation(...)` — 투입율 ↑ (가능 한도까지).

#### 11. 수용 기준

```
AC-FD-SCH-012-1
  Given 담당자 X에 작업 T1·T2 같은 날 각 50%·60% 투입
  When 부하 계산
  Then 해당 일 110% 초과 → overload 경고 표시

AC-FD-SCH-012-2
  Given 부하 모달의 [일정 늘려 분산] 버튼
  When 클릭
  Then T2의 종료일이 영업일 1일 시프트, 다음날에 60% 분배
       시각 경고 해제
```
