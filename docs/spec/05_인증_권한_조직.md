# 05. 인증·권한·조직 (Authentication, Authorization & Organization) — 사전 기능 정의서

| 항목 | 값 |
|---|---|
| 그룹 ID | AUTH |
| 기능 ID 범위 | FD-AUTH-001 ~ FD-AUTH-010 |
| 의존 그룹 | FD-PM, FD-TM, FD-SYNC |
| 작성일 | 2026-05-07 |

---

## 0. 그룹 개요

### 0.1 범위

회원가입·로그인·승인 흐름, 시스템 관리자·조직 책임자·프로젝트 소유자의 권한 모델, 회원 체험 모드, 조직도(부서 트리), 회원 관리 UI.

### 0.2 비-목표

- 작업·프로젝트의 변경 액션 자체 (→ FD-TM, FD-PM)
- DB RLS 정책 정의(SQL) — 본 그룹에서는 클라이언트 게이트 정책만. RLS는 [08_비기능_요구](./08_비기능_요구.md) 보안 섹션 보강.

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **회원(Profile)** | `profiles` 테이블의 1행. 1 사용자 = 1 프로필 |
| **승인(approved)** | 관리자가 가입자를 활성화. `profiles.approved=true` |
| **시스템 관리자** | `profiles.is_admin=true` |
| **관리자 비밀번호 모드** | 비-관리자가 사전 합의된 비밀번호로 일시 관리 권한 (`adminOverride`) |
| **조직 책임자(Manager)** | `profiles.managed_org_node_id != null`. 본인 산하 회원만 관리 |
| **프로젝트 소유자(Owner)** | `projects.owner_id = user.id` |
| **회원 체험 모드(memberPreview)** | 관리자가 일반 회원 시점으로 화면 보는 임시 모드 |
| **`effectiveIsAdmin`** | UI 게이팅 단일 게이트. `(isAdmin || adminOverride) && !memberPreview` |
| **`canEditCurrentProject`** | 프로젝트별 편집 게이트. `currentProjectId != 'all'`인 프로젝트의 owner 또는 admin |

## 1. 데이터 정의

### `profiles`

| 필드 | 타입 | 의미 |
|------|------|------|

## 2. 상세 기능 정의

### FD-AUTH-001 — 회원가입·로그인

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

사용자를 식별하고 권한 모델의 출발점인 `profiles` 행을 만든다.

#### 4. 처리 규칙

##### 4.1 가입 방식

- 이메일 + 비밀번호 (Supabase Auth 표준).
- 이메일 도메인 화이트리스트 옵션 (`emailDomain.ts`).
- 향후 SSO 확장 여지 (Google·SAML 등 P3).

##### 4.2 가입 직후 상태

- `profiles.approved = false` (승인 대기).
- 이 상태에서 로그인은 가능하지만 DB 기반 기능은 차단(클라이언트 안내 + RLS 차단).
- 로컬 전용 모드로 시범 사용 가능.

##### 4.3 로그인

- 이메일·비밀번호 입력 → Supabase Auth 토큰 → `profiles` 행 조회 → `approved` 상태 확인.
- 미승인 시 안내 화면 표시 ("관리자 승인 대기 중").
- 비밀번호 재설정 메일 옵션.

##### 4.4 세션

- Supabase 토큰을 localStorage에 저장 (Supabase SDK 기본).
- 토큰 만료 시 자동 새로 고침 (refresh token).
- 로그아웃: 토큰 제거 + 메모리 상태 초기화.

#### 7. 예외

| ID | 케이스 | 처리 |
|----|--------|------|
| EX-001 | 가입 시 도메인 화이트리스트 미일치 | 가입 거부, 안내 메시지 |
| EX-002 | 비밀번호 재설정 메일 미수신 | "스팸함 확인 + 재발송" |
| EX-003 | 토큰 만료 + 새로 고침 실패 | 자동 로그아웃 + 로그인 화면 |

#### 11. 수용 기준

```
AC-FD-AUTH-001-1
  Given 회원가입 화면
  When 이메일 + 비밀번호 입력 → [가입]
  Then auth.users INSERT, profiles INSERT (approved=false)
       이메일 인증 메일 발송
       로그인 후 "승인 대기" 화면 표시

AC-FD-AUTH-001-2
  Given 가입 시 도메인 화이트리스트 ['company.com'], 사용자 이메일 user@gmail.com
  When [가입]
  Then 가입 거부, "허용된 도메인이 아닙니다"

AC-FD-AUTH-001-3
  Given 토큰 만료
  When 자동 새로 고침
  Then 새 토큰으로 사용자 액션 정상 처리, 사용자에게 보이지 않음
```

### FD-AUTH-002 — 회원 승인 흐름

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

신규 가입자를 관리자가 검토하여 활성화한다. 무분별한 가입으로 인한 데이터 오염·악용 방지.

#### 4. 처리 규칙

##### 4.1 미승인 사용자의 가능 동작

- 로그인 가능.
- 로컬 전용 모드로 데이터 입력·실험 가능.
- 클라우드 동기화 차단 (DB RLS).
- UI에 "승인 대기" 안내 배너 상시 표시.

##### 4.2 승인 트리거

- 시스템 관리자 또는 조직 책임자가 [회원 관리]에서 승인.
- 승인 후 `approved=true` 즉시 반영 (다음 동기화에서 클라우드 사용 가능).

##### 4.3 거부·삭제

- 관리자가 명시적으로 거부 → `auth.users` + `profiles` cascade DELETE.
- 거부 시 사용자 측에는 "가입이 거부되었습니다" 안내 메일 옵션.

##### 4.4 자동 알림

- 신규 가입자 발생 시 모든 관리자에게 알림 (`FD-UI-014` 알림 벨).

#### 11. 수용 기준

```
AC-FD-AUTH-002-1
  Given 사용자 X 가입 직후 (approved=false)
  When 표 화면 진입
  Then "관리자 승인 대기 중" 배너 상시 표시
       클라우드 동기화 차단 (수동 [동기화] 버튼 비활성)

AC-FD-AUTH-002-2
  Given 관리자가 회원 관리 모달에서 X [승인]
  When 클릭
  Then X.approved=true 즉시 반영
       X 화면에서 다음 동기화 시 클라우드 데이터 정상 로드

AC-FD-AUTH-002-3
  Given 신규 가입 발생
  When 시스템 관리자 로그인 중
  Then 알림 벨 배지 +1, "신규 가입: user@example.com" 알림
```

### FD-AUTH-003 — 자동 프로필 생성

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

OAuth·기존 사용자 등으로 `auth.users` 행은 있지만 `profiles` 행이 없는 경우 자동 생성하여 권한 게이트가 깨지지 않게 한다.

#### 4. 처리 규칙

##### 4.1 RPC `ensure_profile()`

- 클라이언트가 로그인 직후 호출.
- 서버 측 RPC가 `profiles` 행 존재 여부 확인 후 없으면 INSERT.
- 멱등 — 여러 번 호출해도 안전.

##### 4.2 기본값

- `approved=false`, `is_admin=false`.

##### 4.3 호출 시점

- AuthContext 초기화 직후, `Pending` 상태 판정 직전.

#### 11. 수용 기준

```
AC-FD-AUTH-003-1
  Given auth.users 행 있음, profiles 행 없음
  When 로그인 후 ensure_profile() RPC 호출
  Then profiles INSERT (approved=false, is_admin=false)

AC-FD-AUTH-003-2
  Given 이미 profiles 행 있음
  When ensure_profile()
  Then 변경 없음 (멱등)
```

### FD-AUTH-004 — 시스템 관리자 권한

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 권한 부여

- DB에서 `profiles.is_admin=true` 직접 설정 (SQL/관리자 콘솔).
- 클라이언트 UI에는 관리자 부여 기능 없음 (보안).

##### 4.2 가능 동작

- 모든 프로젝트 편집·삭제·복사.
- 회원 관리·환경설정·조직도 편집.
- 백업·복원·전체 초기화·AI 분석.
- 모든 프로젝트의 변경 이력 조회.

##### 4.3 회원 체험 모드

- 관리자가 [회원 체험] 토글 → 일반 회원 시점으로 화면 표시 (FD-AUTH-007).
- 본인 소유 프로젝트는 여전히 편집 가능 (Owner 권한).

#### 11. 수용 기준

```
AC-FD-AUTH-004-1
  Given is_admin=true 사용자
  When 다른 회원의 프로젝트에 진입
  Then 표 셀 편집 가능, 컨텍스트 메뉴 모든 항목 노출

AC-FD-AUTH-004-2
  Given is_admin=true, memberPreview=false
  When 환경설정 진입
  Then 모든 탭 편집 가능 (상태 정의·조직도·휴일 등)
```

### FD-AUTH-005 — 관리자 비밀번호 모드 (`adminOverride`)

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

`is_admin=false`인 사용자가 사전 합의된 비밀번호 입력으로 일시 관리 권한을 얻는다 (예: 신규 환경 초기 설정).

#### 4. 처리 규칙

##### 4.1 진입

- 헤더 ⋮ → [관리자 모드 전환] → 비밀번호 입력 모달.
- 비밀번호는 환경변수 또는 DB 설정값과 비교.

##### 4.2 효과

- `adminOverride=true` (sessionStorage). 탭 닫으면 해제.
- `effectiveIsAdmin = (isAdmin || adminOverride) && !memberPreview` → true.
- 모든 관리자 UI 일시 활성.

##### 4.3 보안

- 비밀번호는 클라이언트 환경변수 노출 → 사내 배포에서만 사용. 외부 배포에서는 비활성.
- 토큰 자체에 영향 없음 (UI 게이팅만). DB RLS는 여전히 `is_admin`만 인정.
- 따라서 `adminOverride`는 **UI 표시만** 가능. 실제 DB 변경은 RLS로 차단됨.

##### 4.4 한계 명시

- 사용자에게 "이 모드는 화면 노출만 변경합니다. DB 변경은 일부 제한될 수 있습니다." 안내.

#### 11. 수용 기준

```
AC-FD-AUTH-005-1
  Given 비-관리자, 사전 합의 비밀번호 'admin1234'
  When ⋮ → [관리자 모드 전환] → 'admin1234' 입력
  Then adminOverride=true (sessionStorage)
       관리자 메뉴 노출

AC-FD-AUTH-005-2
  Given adminOverride=true
  When 환경설정의 상태 정의 변경 시도 → 저장
  Then UI는 저장 동작, DB 단계에서 RLS 차단
       토스트 "권한 부족 — DB 변경 차단"

AC-FD-AUTH-005-3
  Given adminOverride=true, 탭 닫고 다시 열기
  When 새 세션
  Then adminOverride=false (sessionStorage 유실)
```

### FD-AUTH-006 — 프로젝트 편집 권한 (`canEditCurrentProject`)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

작업·프로젝트의 모든 편집 동작에 대한 클라이언트 단일 게이트.

#### 4. 처리 규칙

##### 4.1 계산식

```ts
function canEditCurrentProject(currentProjectId, projects, userId, isAdmin):
    if !currentProjectId or currentProjectId === 'all': return false
    project = projects.find(p => p.id === currentProjectId)
    if isAdmin: return true
    return project?.owner_id === userId
```

##### 4.2 단일 게이트 원칙

- 모든 편집 UI 요소(헤더 [+새 작업], 표 셀 편집, 컨텍스트 메뉴, 칸반 카드 추가, 마인드맵 등)는 **이 단일 함수만** 참조.
- 새 편집 기능 추가 시 별도 권한 로직을 만들지 말고 본 게이트를 통과.

##### 4.3 'all' 보기

- `currentProjectId='all'`이면 항상 false. 사용자에게 "프로젝트를 선택하세요" 안내.

##### 4.4 회원 체험 모드 영향

- `memberPreview=true`이면 `isAdmin` 인정 안 함. 단 본인 소유 프로젝트는 owner로 인정 (편집 가능).

##### 4.5 editor 멤버 (현재 미구현)

- 향후 확장 — `projects.assignments`에 role='editor'가 있으면 편집 가능. 현재는 owner/admin만.

#### 11. 수용 기준

```
AC-FD-AUTH-006-1
  Given currentProjectId='A', user=비-소유자, isAdmin=false
  When canEditCurrentProject 평가
  Then false
       헤더 [+새 작업] disabled
       표 셀 편집 진입 안 됨

AC-FD-AUTH-006-2
  Given currentProjectId='all', user=admin
  When canEditCurrentProject 평가
  Then false ('all' 강제 false)

AC-FD-AUTH-006-3
  Given user=admin, memberPreview=true, currentProjectId='A' (소유자=admin 본인)
  When canEditCurrentProject 평가
  Then true (Owner 권한)
```

### FD-AUTH-007 — 회원 체험 모드 (`memberPreview`)

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

관리자가 일반 회원 시점으로 화면을 보고 회원이 보는 상태를 확인한다 (고객 시연·UX 검수·문제 재현).

#### 4. 처리 규칙

##### 4.1 토글

- 헤더 ⋮ → [회원 체험] 토글.
- sessionStorage에 저장 — 탭 닫으면 해제.

##### 4.2 효과

- `effectiveIsAdmin = (isAdmin || adminOverride) && !memberPreview` → false.
- 모든 관리자 전용 UI 숨김 (환경설정·조직도·전체 변경 이력 등).

##### 4.3 본인 소유 프로젝트는 편집 유지

- `canEditCurrentProject`는 owner도 인정 → 본인 소유는 편집 가능. 다른 사람 프로젝트는 읽기 전용.

##### 4.4 시각적 표시

- 헤더에 "체험 모드" 배지 (잊지 않게).
- 토글 끄기 버튼 항상 노출.

#### 11. 수용 기준

```
AC-FD-AUTH-007-1
  Given isAdmin=true
  When [회원 체험] 토글 ON
  Then memberPreview=true (sessionStorage)
       헤더에 "체험 모드" 배지 표시
       환경설정·조직도 메뉴 항목 미노출

AC-FD-AUTH-007-2
  Given memberPreview=true, 본인 소유 프로젝트 P
  When P 편집 시도
  Then 편집 가능 (Owner 권한)

AC-FD-AUTH-007-3
  Given memberPreview=true, 다른 사람 소유 프로젝트 Q
  When 셀 편집 시도
  Then 진입 안 됨 (읽기 전용)
```

### FD-AUTH-008 — 조직도 관리

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

조직 부서 구조를 트리로 정의하고 회원을 배속하여, 조직 책임자 권한·보고 라인의 기준 데이터를 제공한다.

#### 4. 처리 규칙

##### 4.1 데이터 구조

- `org_nodes`: 부서 트리 (parent_id로 계층).
- `org_members`: 부서 ↔ 회원 N:M.
- 1 회원은 여러 부서 소속 가능 (matrix 조직).

##### 4.2 편집 UI

- 환경설정 → 조직도 탭.
- 트리 추가·이름 변경·삭제·이동.
- 회원 드래그앤드롭으로 부서 배속.

##### 4.3 권한

- 시스템 관리자만 편집.

##### 4.4 활용

- [FD-AUTH-009] 조직 책임자 권한 — 본인 산하 회원만 관리 가능.
- 조직별 진척도 보기 — [FD-UI-007 대시보드](./04_화면_뷰.md) 보강 옵션.

#### 11. 수용 기준

```
AC-FD-AUTH-008-1
  Given 환경설정 → 조직도 탭, 관리자
  When 부서 "개발팀" 추가 → 회원 X 배속
  Then org_nodes INSERT, org_members INSERT
       다른 사용자에게 다음 동기화 시 반영

AC-FD-AUTH-008-2
  Given 부서 "운영팀" 삭제, 소속 회원 5명
  When 삭제 시도
  Then 다이얼로그 "5명의 소속이 해제됩니다 — 계속하시겠습니까?"
       확인 → 회원의 org_members 행 삭제, 회원 자체는 보존
```

### FD-AUTH-009 — 조직 책임자 권한

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

부서 책임자에게 본인 부서 회원의 승인·권한 변경 권한을 위임 (시스템 관리자 부담 분산).

#### 4. 처리 규칙

##### 4.1 정의

- `profiles.managed_org_node_id` 설정 → 조직 책임자.
- 한 사람이 여러 부서 책임자일 경우 다중 노드 — 향후 확장.

##### 4.2 가능 동작

- 본인이 관리하는 조직 노드 + 후손의 회원만:
  - 승인·승인 취소
  - 일반 회원의 비밀번호 재설정 메일 트리거
  - 회원 정보 수정 (이름·소속 부서)
- 시스템 관리자 권한 부여는 불가 (관리자만).

##### 4.3 게이트

- `canOpenMembersManagement = effectiveIsAdmin || isOrgScopedManager`.
- 회원 관리 모달에서 본인 관리 범위 회원만 노출.

##### 4.4 환경설정·조직도 편집

- 책임자라도 환경설정·조직도 편집은 불가 (관리자 전용).

#### 11. 수용 기준

```
AC-FD-AUTH-009-1
  Given 사용자 M, managed_org_node_id='개발팀'
  When 회원 관리 모달 진입
  Then 개발팀 + 산하 부서의 회원만 목록에 노출
       다른 부서 회원 미노출

AC-FD-AUTH-009-2
  Given M, 개발팀 회원 X 미승인
  When [승인] 클릭
  Then X.approved=true

AC-FD-AUTH-009-3
  Given M
  When 환경설정 → 조직도 탭 진입 시도
  Then 탭 미노출 (또는 진입 시 권한 부족 안내)
```

### FD-AUTH-010 — 회원 관리 모달

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 진입

- 헤더 ⋮ → [회원 관리]. `canOpenMembersManagement=true`만 노출.

##### 4.2 표시 항목

- 회원별: 이메일·이름·소속 부서·승인 상태·관리자 여부·즐겨찾기 프로젝트 수.

##### 4.3 액션 (관리자)

| 액션 | 대상 | 설명 |
|------|------|------|
| 승인 / 취소 | 모든 회원 | `approved` 토글 |
| 관리자 부여 / 회수 | 모든 회원 | `is_admin` 토글 (단 본인 강등 차단) |
| 조직 책임자 지정 | 모든 회원 | `managed_org_node_id` 설정 |
| 부서 배속 | 모든 회원 | `org_members` 편집 |
| 비밀번호 재설정 메일 | 모든 회원 | Supabase Auth 트리거 |
| 회원 영구 삭제 | 모든 회원 | `auth.users` + `profiles` cascade |

##### 4.4 액션 (조직 책임자)

- 관리자 부여·회수, 영구 삭제 제외.
- 본인 산하만 노출.

##### 4.5 본인 강등 차단

- 자신을 관리자에서 회수하면 시스템에 관리자가 0명이 될 수 있음 → 차단.

#### 11. 수용 기준

```
AC-FD-AUTH-010-1
  Given 시스템 관리자 단 1명 (자신), 자신 [관리자 회수] 시도
  When 클릭
  Then 차단, 토스트 "마지막 관리자입니다 — 회수 불가"

AC-FD-AUTH-010-2
  Given 회원 X 미승인
  When [승인] 클릭
  Then X.approved=true 즉시 반영
       알림 벨로 X에게 통보 ("승인되었습니다")
```
