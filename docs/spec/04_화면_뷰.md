## 0. 그룹 개요

### 0.1 범위

**같은 작업 데이터를 6개 시점(표/표+간트/간트만/칸반/마인드맵/대시보드)으로 보여주는 화면 레이아웃 + 필터·정렬·검색·헤더·사이드바·확인 다이얼로그·토스트** 등 UI 차원의 기능.

본 그룹은 **렌더링·인터랙션 표준**을 정의한다. 데이터 변경 자체는 [01_작업관리](./01_작업관리.md), 일정 산정은 [03_일정_상태_진척도](./03_일정_상태_진척도.md) 참조.

### 0.2 비-목표

- 작업 데이터 변경 로직 (→ FD-TM)
- 권한 게이트 자체 (→ FD-AUTH)
- 동기화 표시기 (→ FD-SYNC)

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **뷰(View)** | URL `/`의 첫 세그먼트로 결정되는 화면 종류 (`list`, `table`, `gantt`, `kanban`, `mindmap`, `dashboard`, `projects`, `allocation`) |
| **작업 보기** | `list`/`table`/`gantt`/`kanban`/`mindmap` — 작업 데이터를 보여주는 5개 뷰 |
| **풀스크린** | 헤더·사이드바를 숨기고 메인 영역만 |
| **가상 스크롤** | 행 수가 많을 때 보이는 행만 렌더 |
| **VisibleTasks** | 필터·검색·트리 펼침이 적용된 후 화면에 표시되는 작업 |

## 1. 상세 기능 정의

### FD-UI-001 — 뷰 라우팅·전환

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

URL 기반 딥링크와 뒤/앞으로 가기를 지원하면서, 사용자가 의도한 화면을 최소 인터랙션으로 전환한다.

#### 4. 처리 규칙

##### 4.1 URL 매핑

| URL | view | 화면 |
|-----|------|------|
| `/` | (기본) `'table'` | 표만 |
| `/list` | `'list'` | 표+간트 |
| `/table` | `'table'` | 표만 |
| `/gantt` | `'gantt'` | 간트만 |
| `/kanban` | `'kanban'` | 칸반 |
| `/mindmap` | `'mindmap'` | 마인드맵 |
| `/dashboard` | `'dashboard'` | 대시보드 |
| `/projects` | `'projects'` | 프로젝트 목록 |
| `/allocation` | `'allocation'` | 투입현황 |

##### 4.2 전환 시 상태 보존

- `currentProjectId`, 필터, 정렬, 선택 작업, 펼침 상태 — 모두 보존.
- 표 셀 편집 상태·인라인 편집은 컴포넌트 언마운트로 리셋.

##### 4.3 프로젝트 전환 시 뷰 처리

- 작업 보기 5개(`list/table/gantt/kanban/mindmap`)에서 다른 프로젝트 선택 → **현재 뷰 유지**.
- 그 외(`dashboard/projects/allocation`)에서는 `'list'`로 전환.

##### 4.4 검색 점프 (`navigateToTask`)

- 결과 클릭 시 `'table'`로 강제 전환 (작업 셀 컨텍스트가 가장 풍부).
- 정책 옵션: 사용자 환경설정으로 "현재 뷰 유지" 토글 제공 가능 (P3).

##### 4.5 환경변수 숨김

- `VITE_HIDDEN_VIEWS`로 일부 뷰를 메뉴에서 숨김 (예: 사내 배포에서 마인드맵 비표시).

#### 11. 수용 기준

```
AC-FD-UI-001-1
  Given view='table', currentProjectId='A'
  When 헤더 드롭다운에서 프로젝트 'B' 선택
  Then view='table' 유지, currentProjectId='B'

AC-FD-UI-001-2
  Given view='dashboard'
  When 헤더에서 프로젝트 'B' 선택
  Then view='list'로 전환

AC-FD-UI-001-3
  Given view='kanban'
  When 검색 결과의 작업 클릭
  Then view='table'로 강제 전환

AC-FD-UI-001-4
  Given URL = /gantt
  When 새로고침
  Then view='gantt'으로 복원
```

### FD-UI-002 — 표 화면 (WBSTable)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

작업 트리를 행·열로 보여주며 키보드 중심으로 빠른 편집을 지원한다.

#### 4. 처리 규칙

##### 4.1 컬럼 (기본)

| 컬럼 | 폭 | 편집 |
|------|----|----|
| 체크박스 | 32 | — |
| WBS 번호 | 80 | — (자동) |
| 작업명 (트리 들여쓰기 표시) | 가변 | ✓ |
| 담당자 | 120 | ✓ |
| 시작일 | 110 | ✓ |
| 종료일 | 110 | ✓ |
| 공수 | 80 | ✓ |
| 진척도 | 80 | ✓ |
| 가중치 | 70 | ✓ |
| 상태 | 110 | ✓ (드롭다운) |
| 의존성 | 140 | ✓ (다중 선택) |
| 마일스톤·이슈 | 60 | (컨텍스트 메뉴로 토글) |
| 사용자 정의 컬럼 N개 | 가변 | ✓ |

##### 4.2 행 상태

- 선택 (`lastSelectedId`) — 옅은 강조.
- 다중 선택 — 더 진한 강조.
- 편집 중 (`editingCell`) — 두꺼운 외곽선.
- 다른 사용자 편집 중 — 사용자 색상 외곽선 ([FD-SYNC-006](./06_협업_동기화.md)).
- 검색 점프 결과 — 잠깐(2초) 깜빡임.

##### 4.3 트리 표시

- `task.expanded=false`인 부모 아래의 자식들은 숨김.
- 들여쓰기 = depth × 16px 패딩.
- 토글 화살표 ▶/▼.

##### 4.4 가상 스크롤

- 행 수 ≥ 100일 때 활성. 보이는 행 + 위·아래 버퍼 5행만 DOM 마운트.
- 점프(검색)·정렬 변경 시 적절 위치로 스크롤.

##### 4.5 하단 인라인 추가 행

- 항상 마지막 행 아래에 입력 행 표시 ("새 작업 추가 (Enter)").
- `canEditCurrentProject=false`면 미렌더.

#### 11. 수용 기준

```
AC-FD-UI-002-1
  Given 표, 작업 1000건
  When 진입
  Then 가상 스크롤 활성, 보이는 행 ≈ 30 + 버퍼 10 = ~40만 DOM
       스크롤 시 60fps 유지

AC-FD-UI-002-2
  Given 부모 P (자식 5건, expanded=false)
  When P 행의 토글 ▶ 클릭
  Then 자식 5건 노출, ▼ 표시

AC-FD-UI-002-3
  Given canEditCurrentProject=false
  When 진입
  Then 하단 인라인 추가 행 미렌더
       셀 호버 시 cursor=default (편집 cursor 아님)
```

### FD-UI-003 — 표+간트 화면 (list)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 레이아웃

- 좌측: 표 (FD-UI-002와 동일)
- 우측: 간트 차트 (FD-UI-004 참조)
- 가운데 리사이즈 핸들 — 폭 비율 사용자 조정 (`useResizablePane`).

##### 4.2 동기화

- 표 행과 간트 막대는 같은 작업이면 같은 Y 좌표.
- 표 스크롤·간트 스크롤이 양방향 동기화 (`useScrollSync`).

##### 4.3 좌측 폭 한계

- 최소 30%, 최대 70%. 미만/초과 시 클램프.

#### 11. 수용 기준

```
AC-FD-UI-003-1
  Given list 뷰, 좌측 폭 50%
  When 가운데 핸들 드래그
  Then 폭 비율 변경, 새로고침 시 사용자 설정 유지 (localStorage)

AC-FD-UI-003-2
  Given 표 스크롤
  When 표를 위/아래로 스크롤
  Then 간트 영역도 같은 비율로 동기화 스크롤
```

### FD-UI-004 — 간트만 화면

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 표시 요소

- 시간축 헤더: 일/주/월/분기 — 줌 레벨에 따라 단위 변경.
- 작업 막대: 시작~종료 영역. 진척도 채움 표시.
- 마일스톤: 다이아몬드 형태.
- 의존성 화살표: 선행 종료 → 후행 시작.
- 베이스라인 바: 회색.
- 오늘 표시선: 빨강.

#### 4.1 인터랙션

- 막대 드래그 좌/우: 시작/종료일 이동.
- 막대 좌/우 끝 잡고 드래그: 길이 조정 (workEffort 자동 재계산).
- 막대 더블클릭: TaskModal 열기.
- 시간축 드래그: 가로 스크롤.
- Ctrl+휠 / 핀치: 줌.

#### 4.2 줌 레벨

- 일 / 주 / 월 / 분기 — 사용자가 [+]/[-] 또는 단축키로 변경.

#### 11. 수용 기준

```
AC-FD-UI-004-1
  Given 작업 T 막대
  When 우측 끝을 +5일만큼 드래그
  Then T.endDate +5일, workEffort 자동 재계산 (영업일·휴일 반영)

AC-FD-UI-004-2
  Given A→B 의존성, A 막대 종료를 +3일 드래그
  When 드롭
  Then A.endDate 변경, B.startDate 자동 시프트, 화살표가 새 위치로 갱신
```

### FD-UI-005 — 칸반 보드

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 컬럼

- 환경설정의 `statusConfigs` 순서대로 컬럼 생성. 각 컬럼 = 1 상태.

##### 4.2 카드

- 작업 1건 = 카드 1개.
- 카드 표시: 작업명·담당자·일정·진척도·체크리스트 진행 표시.

##### 4.3 드래그앤드롭

- 카드 드래그 → 다른 컬럼 드롭: 작업 status 변경.
- `linkStatusAndProgress=true` → progress 자동 변경.
- 컬럼 내 드래그 = 표시 순서만 변경 (sort_order, kanban 전용 정렬 키).

##### 4.4 카드 추가

- 컬럼 하단 [+ 카드 추가]: 제목 입력 → Enter → 해당 status로 신규 작업 생성 ([FD-TM-001](./01_작업관리.md) E11).

##### 4.5 카드 클릭

- TaskModal 열기.

#### 11. 수용 기준

```
AC-FD-UI-005-1
  Given 카드 T (status='todo')
  When 'doing' 컬럼으로 드래그앤드롭
  Then T.status='doing', linkStatusAndProgress=true이면 progress=50

AC-FD-UI-005-2
  Given 'in-progress' 컬럼 [+ 카드 추가]
  When "신규 A" 입력 → Enter
  Then 새 작업, status='in-progress', parentId=null (루트)
```

### FD-UI-006 — 마인드맵

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 4. 처리 규칙

##### 4.1 노드 표시

- 작업 = 노드. 부모-자식 = 곡선 연결.
- 색상: 상태별. 진척도: 노드 둘레 게이지.

##### 4.2 인터랙션

- 노드 드래그: 위치 이동 (사용자 정의 레이아웃 저장).
- 더블클릭: TaskModal.
- Tab / Ctrl+Enter: 자식 추가.
- 노드 우클릭: 컨텍스트 메뉴.

##### 4.3 자동 레이아웃

- 사용자 위치 미저장 시 방사형 자동 배치.
- 사용자가 드래그 후 [자동 정렬] 버튼으로 재정렬 가능.

#### 11. 수용 기준

```
AC-FD-UI-006-1
  Given 노드 T 선택
  When Tab
  Then T의 자식 신규 노드 추가, 노드 텍스트 인라인 편집 진입

AC-FD-UI-006-2
  Given 노드 드래그하여 위치 이동
  When 드롭
  Then 위치 사용자 레이아웃에 저장. 새로고침해도 위치 복원
```

### FD-UI-007 — 대시보드

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 표시 카드

- 진행 중 작업 수, 지연 작업 수, 완료 작업 수.
- 이번 주 시작/종료 작업 일람.
- 프로젝트별 진척도 게이지.
- 번다운 차트 (선택 기간).
- 담당자별 부하.

##### 4.2 권한별 가시성

- `Admin`: 전체 프로젝트 데이터.
- `Member`: 본인 참여 프로젝트만 (RLS + 클라이언트 필터).

##### 4.3 카드 클릭 액션

- 카드 → `view` 전환 + 해당 필터 자동 적용 (예: "지연 작업" → list 뷰 + `pastDueOnly` 필터).

#### 11. 수용 기준

```
AC-FD-UI-007-1
  Given 일반 회원, 본인 참여 프로젝트 3개
  When 대시보드 진입
  Then 본인 참여 3개 프로젝트의 데이터만 집계 표시

AC-FD-UI-007-2
  Given 대시보드의 "이번 주 작업" 섹션
  When [표·간트에서 보기] 버튼 클릭
  Then view='list', filterOn=true, startDate=주 시작일, endDate=주 종료일
```

### FD-UI-008 — 투입현황 페이지

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 4. 처리 규칙

##### 4.1 보기 모드

- **프로젝트별**: 프로젝트 × 멤버 매트릭스 — 일별/주별 투입율.
- **사람별**: 멤버 × 프로젝트 매트릭스 — 멤버 한 명의 모든 프로젝트 투입.

##### 4.2 부하 색상

- ≤ 80%: 녹색
- 81~100%: 황색
- > 100%: 적색 (overload)

##### 4.3 액션

- 셀 클릭 → 해당 멤버의 해당 일 작업 일람 (사이드 패널).

##### 4.4 권한

- `Admin` / `Manager`: 전사 전체.
- `Member`: 본인 행만.

#### 11. 수용 기준

```
AC-FD-UI-008-1
  Given 관리자, 사람별 보기
  When 진입
  Then 모든 멤버 × 모든 프로젝트 매트릭스
       100% 초과 셀은 적색

AC-FD-UI-008-2
  Given 일반 회원, 본인 행
  When 셀(2026-06-15) 클릭
  Then 사이드 패널: 해당 일 본인 작업 일람 + 투입율 합계
```

### FD-UI-010 — 필터 바

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 필터 항목

| 필드 | 타입 | 적용 화면 |
|------|------|-----------|
| `projectIds` | `'all'` \| string[] | 전체 |
| `status` | `'all'` \| string | 표·간트·칸반·마인드맵 |
| `assignee` | string (자동완성) | 〃 |
| `startDate` / `endDate` | YYYY-MM-DD | 〃 |
| `level` | `'all'` \| 1~9 | 표 |
| `milestoneOnly` | bool | 표·간트 |
| `issueOnly` | bool | 표·간트 |
| `pastDueOnly` | bool | 표·간트 |
| `completedThisWeekOnly` | bool | 표·간트·대시보드 |

##### 4.2 토글 (`filterOn`)

- 헤더의 [필터] 토글 — `filterOn=true`이면 필터 바 표시 + 필터 적용.
- `filterOn=false`이면 필터 객체는 메모리 유지하되 UI·적용 모두 OFF.

##### 4.3 화면별 노출

- `view='projects'`, `view='allocation'`에서는 필터 바 미표시.

##### 4.4 새 작업 추가 시 기본값

- 필터의 `startDate`, `endDate`, `assignee`가 신규 작업 기본값으로 상속 (적용되는 진입점은 [FD-TM-001](./01_작업관리.md) 참조).

##### 4.5 필터 적용 후 가시성 안내

- 새 작업이 활성 필터로 가려질 경우 토스트 "필터에 의해 가려졌습니다 [필터 해제]".

#### 11. 수용 기준

```
AC-FD-UI-010-1
  Given filterOn=false
  When 헤더 [필터] 토글
  Then filterOn=true, 필터 바 표시, 모든 필드 마지막 값 복원

AC-FD-UI-010-2
  Given 표 화면, status='in-progress' 필터, 새 작업 status='todo'로 추가
  When 추가 후
  Then 작업은 DB에 추가되나 표에서 즉시 가려짐
       토스트 "필터에 의해 가려졌습니다 [필터 해제]"
```

### FD-UI-011 — 정렬

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 정렬 키

- 기본: WBS 번호 오름차순(트리 순서).
- 사용자가 컬럼 헤더 클릭 → 해당 컬럼 정렬, 다시 클릭 → 내림차순, 다시 → 해제.

##### 4.2 트리 보존

- 정렬 변경해도 부모-자식 관계는 유지(depth 패딩).
- 정렬 키가 `wbs`가 아니면 표시 순서만 정렬됨.

##### 4.3 트리 조작 차단

- 정렬 ≠ `wbs asc`이면 Tab/Shift+Tab/Alt+↑/↓ 비활성.

##### 4.4 저장

- 사용자별 마지막 정렬은 localStorage. 새 세션은 기본(`wbs asc`).

#### 11. 수용 기준

```
AC-FD-UI-011-1
  Given 정렬 = wbs asc
  When 컬럼 헤더 [작업명] 클릭
  Then 정렬 = name asc, 표시 순서 변경
       Tab/Shift+Tab/Alt+↑↓ 비활성

AC-FD-UI-011-2
  Given 정렬 = name asc
  When [작업명] 헤더 다시 클릭
  Then 정렬 = name desc

AC-FD-UI-011-3
  Given 정렬 = name desc
  When [작업명] 헤더 다시 클릭
  Then 정렬 해제 → wbs asc로 복귀
```

### FD-UI-018 — 토스트·확인 다이얼로그

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 토스트 종류

- 성공(녹색) / 정보(청색) / 경고(황색) / 오류(적색).
- 자동 닫힘 4초. [닫기] / 액션 버튼 포함 가능.

##### 4.2 위치

- 화면 우상단. 다중 토스트는 위→아래 스택.

##### 4.3 확인 다이얼로그

- 모달. 제목·본문·[취소]·[확인] 버튼.
- 위험 동작(삭제·초기화)은 적색 [확인] 버튼.
- Esc=취소, Enter=확인.

##### 4.4 사용자 입력 확인 다이얼로그 (이름 일치)

- 영구 삭제 등 비가역 작업: 사용자에게 이름 입력시켜 일치 확인 후 진행.

#### 11. 수용 기준

```
AC-FD-UI-018-1
  Given 작업 추가 성공
  When 처리 완료
  Then 우상단 녹색 토스트 "작업 추가됨", 4초 후 자동 닫힘

AC-FD-UI-018-2
  Given 프로젝트 [영구 삭제] 시도
  When 다이얼로그 표시
  Then 프로젝트명 정확히 입력해야 [확인] 버튼 활성화
       Esc → 취소, Enter → 확인 (이름 입력 정확 시)
```
