## 1. 사전 합의 — 본 스펙이 의도하는 제품의 모습

### 1.1 한 문장 정의

**다수 프로젝트의 작업(WBS)을 단일 화면에서 표·간트·칸반·마인드맵·대시보드·투입현황의 6개 시점으로 관리·시각화·공유하는 협업형 웹 애플리케이션.**

### 1.2 핵심 가치 (Why)

- **단일 진입점**: 여러 프로젝트의 진행 상황을 한 사람의 머릿속이 아닌 한 화면에서 본다.
- **시점 다양성**: 같은 데이터를 표·간트·칸반·마인드맵으로 본다. 사용자는 시점만 바꿔도 사고 방식이 바뀐다.
- **자동 일정 산정**: 사용자가 시작일·공수만 입력하면 휴일·의존성을 반영해 종료일을 계산한다. 사용자가 일정을 직접 잠그면 자동 산정에서 제외된다.
- **권한 모델은 단순**: 프로젝트 소유자 + 시스템 관리자가 편집한다. 그 외는 보기. 협업의 사회적 신호(누가 어디서 편집 중인지)는 시각으로만 표시한다.
- **실수 회복**: Undo 50개, 로컬 1초 디바운스 자동 저장, 클라우드 수동 동기화, JSON 백업.

### 1.3 사용자 페르소나

| 페르소나 | 사용 빈도 | 관심사 | 권한 |
|----------|-----------|--------|------|
| **PM (Project Manager)** | 매일 | 일정 일관성, 진척도, 자원 부하 | 본인 프로젝트 소유자 또는 관리자 |
| **팀원** | 주 2~3회 | 본인 작업의 일정·상태 갱신 | viewer (현재) |
| **시스템 관리자** | 필요 시 | 전사 회원·조직·환경 관리 | 시스템 관리자 |
| **조직 책임자** | 주 1회 | 본인 산하 회원 관리·승인 | `managed_org_node_id` |
| **임원/외부 보고 대상** | 월 1회 | 대시보드·주간 보고 | 보기 권한 |

### 1.4 비-목표 (Out of Scope, 전체 제품 차원)

- 마이크로소프트 프로젝트(MPP) 수준의 자원 평준화·CPM(Critical Path) 자동 분석.
- 회계·예산 청구·인보이스 발행.
- 실시간 화상 회의·채팅 메시지(다른 도구로 대체).
- Native 모바일 앱(반응형 웹만).

## 3. 공통 표기 약속

### 3.1 기능 ID 체계

`FD-{그룹}-{번호3자리}` — 예) `FD-TM-001` = Task Management 첫 기능.

상세 기능을 더 쪼개야 할 경우 `FD-TM-001-A`, `FD-TM-001-B`처럼 알파벳 서픽스를 붙인다.

### 3.2 우선순위

| 등급 | 의미 |
|------|------|
| **P0 (필수)** | 이 기능 없으면 제품이 성립하지 않음. 첫 출시에 반드시 포함 |
| **P1 (중요)** | 핵심 사용자 흐름의 일부. 첫 출시 또는 직후 |
| **P2 (보강)** | 사용자 경험을 개선하나 우회 가능 |
| **P3 (선택)** | 일부 사용자에만 가치. 출시 후 추가 |

### 3.3 권한 등급 (전 그룹 공통)

| 등급 | 정의 | 식별 |
|------|------|------|
| `Anon` | 비로그인 | 인증 토큰 없음 |
| `Pending` | 가입 후 미승인 | `profiles.approved=false` |
| `Member` | 승인 회원 | `profiles.approved=true` |
| `Manager` | 조직 책임자 | `profiles.managed_org_node_id != null` |
| `Owner` | 프로젝트 소유자 | `projects.owner_id === user.id` |
| `Admin` | 시스템 관리자 | `profiles.is_admin=true` 또는 관리자 비밀번호 모드 |

> 회원 체험 모드(`memberPreview`) ON 상태에서 `Admin`은 일시적으로 `Member` 시점으로 화면을 본다. 본인 소유 프로젝트는 `Owner` 권한 유지.

### 3.4 수용 기준 (Acceptance Criteria, AC) 작성 규칙

각 기능의 AC는 Given–When–Then 형식으로 작성한다.

```
AC-{기능ID}-{번호}
  Given: 사전 상태(데이터·권한·UI 상태)
  When: 사용자 행동 또는 시스템 이벤트
  Then: 기대 결과(UI 변화·데이터 변화·이벤트)
```

체크 통과 = 자동 테스트 통과 + 수동 확인 통과(둘 다).
