# 06. 협업·동기화 (Collaboration & Sync) — 사전 기능 정의서

| 항목 | 값 |
|---|---|
| 그룹 ID | SYNC |
| 기능 ID 범위 | FD-SYNC-001 ~ FD-SYNC-010 |
| 의존 그룹 | FD-AUTH, FD-TM, FD-PM, FD-IO |
| 작성일 | 2026-05-07 |

---

## 0. 그룹 개요

### 0.1 범위

자동 저장(디바운스), 클라우드/로컬 모드, 수동·실시간 DB 동기화, 동시 편집 표시(Presence), Undo/Redo, 충돌 정책, 감사 로그(변경 이력), 에러 복구.

### 0.2 비-목표

- DB 스키마·RLS SQL (→ FD-NFR-003 보안)
- 백업·복원의 사용자 인터랙션 (→ FD-IO)

### 0.3 주요 용어

| 용어 | 정의 |
|------|------|
| **자동 저장** | 사용자 입력 후 디바운스 시간 경과 시 로컬 저장(IndexedDB/localStorage) |
| **수동 동기화** | 헤더 [동기화] 버튼 → 클라이언트 ↔ DB 푸시·풀 |
| **Realtime** | Supabase Realtime broadcast 채널 — 다른 사용자의 변경을 즉시 수신 |
| **Presence** | 동시 접속·셀 포커스 표시 |
| **LWW** | Last-Write-Wins. 충돌 시 마지막 쓰기 우선 |
| **Yjs CRDT** | Conflict-free Replicated Data Type. 향후 셀 단위 머지를 위한 옵션 |
| **Dirty 플래그** | 로컬 변경이 DB에 반영되지 않은 상태(`hasLocalChangesSinceSync`) |

### 0.4 기능 일람

| ID | 기능명 | 우선순위 |
|----|--------|----------|
| FD-SYNC-001 | 자동 저장 (디바운스) | P0 |
| FD-SYNC-002 | 수동 동기화 | P0 |
| FD-SYNC-003 | Cloud 모드 | P0 |
| FD-SYNC-004 | Local-only 모드 | P1 |
| FD-SYNC-005 | Realtime DB 동기화 | P1 |

| FD-SYNC-010 | 에러 처리·복구 | P0 |

## 1. 상세 기능 정의

### FD-SYNC-001 — 자동 저장 (디바운스)

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

사용자가 명시적 [저장]을 누르지 않아도 입력 변경이 일정 시간 후 자동으로 로컬에 영속화되어 새로고침·탭 닫기·크래시에 의한 데이터 손실을 최소화한다.

#### 4. 처리 규칙

##### 4.1 디바운스 타이밍

- 마지막 변경 후 **1초** 후 로컬 저장 트리거.
- 추가 변경이 발생하면 타이머 리셋.

##### 4.2 저장 대상

- 작업 트리(`tasks`), 프로젝트(`projects`), 환경설정(`wbs_settings`), 삭제 큐(`deletedTaskIdsByProject`, `deletedProjectIds`).

##### 4.3 저장소 우선순위

- 1차: IndexedDB. 용량 제한 적고 비동기 — 큰 데이터에 유리.
- 2차: localStorage (IndexedDB 실패 시).
- 3차: 메모리만 (둘 다 실패 시) + 사용자 경고.

##### 4.4 사용자 가시 인디케이터

- 헤더에 작은 점/스피너로 "저장 중" / "저장됨" 표시.
- 30초 이상 저장 실패 시 적색 경고.

##### 4.5 `beforeunload` 가드

- Dirty 상태에서 탭 닫기 시도하면 브라우저 기본 확인 다이얼로그.

#### 11. 수용 기준

```
AC-FD-SYNC-001-1
  Given 작업 셀 변경 직후
  When 1초 경과
  Then IndexedDB에 저장 완료, 헤더 인디케이터 "저장됨"

AC-FD-SYNC-001-2
  Given 변경 후 1초 이내 추가 변경
  When 추가 변경 발생
  Then 타이머 리셋, 추가 변경 후 1초에 저장

AC-FD-SYNC-001-3
  Given 로컬 변경 있고 저장 미완료(디바운스 진행 중)
  When 탭 닫기 시도
  Then beforeunload 다이얼로그 "변경사항이 있습니다"
       사용자 [머무르기] → 디바운스 1초 후 저장 완료
       [나가기] → 변경 손실 (사용자 명시 동의)

AC-FD-SYNC-001-4
  Given IndexedDB 저장 실패 (용량 초과)
  When 저장 시도
  Then localStorage 폴백 시도
       토스트 "저장소 용량 부족 — 백업 후 일부 데이터 정리 권장"
```

### FD-SYNC-002 — 수동 동기화

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 1. 목적

로컬 변경을 DB에 푸시하고 다른 사용자의 DB 변경을 풀하는 명시적 트리거 제공.

#### 4. 처리 규칙

##### 4.1 진입

- 헤더 [동기화] 버튼 — `Cloud` 모드일 때만 표시.
- 진행 중에는 버튼 비활성 + 진행률 표시.

##### 4.2 동기화 절차

1. **푸시(Push)**: 로컬의 `dirty` 변경분을 DB에 INSERT/UPDATE/DELETE.
2. **풀(Pull)**: 서버 최신 상태를 받아 로컬에 반영.
3. **충돌 검사**: 푸시·풀 사이의 충돌은 [FD-SYNC-008](#fd-sync-008--충돌-정책-lww)에 따라 해결.

##### 4.3 진행률

- 콜백으로 0~100%. 토스트로 표시.

##### 4.4 자동 동기화 옵션

- 탭 활성화 시 5분 주기 자동 풀 (사용자 환경설정으로 ON/OFF).
- 푸시는 자동 안 함 (사용자 명시 트리거 우선).

##### 4.5 영역 한정

- 옵션: 현재 프로젝트만 / 전체.

#### 11. 수용 기준

```
AC-FD-SYNC-002-1
  Given Cloud 모드, 로컬 dirty=true, 헤더 [동기화] 클릭
  When 진행
  Then 푸시 → 풀 순으로 진행, 토스트 진행률 0→50→100
       완료 후 hasLocalChangesSinceSync=false

AC-FD-SYNC-002-2
  Given 동기화 진행 중
  When 사용자가 셀 편집
  Then 로컬 변경은 정상 반영, 동기화 완료 후 dirty=true 다시 설정

AC-FD-SYNC-002-3
  Given 5분 주기 자동 풀 ON, 다른 사용자가 작업 추가
  When 5분 경과 (또는 탭 활성화)
  Then 풀 자동 실행, 새 작업 표 화면에 등장
```

### FD-SYNC-003 — Cloud 모드

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 진입 조건

- Supabase 환경변수(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) 설정됨.
- 사용자 로그인 + `approved=true` (`Member` 이상).

##### 4.2 동작

- 로그인 시 DB에서 프로젝트·작업·설정 풀.
- 로컬 캐시(IndexedDB)에 저장.
- 사용자 변경은 [FD-SYNC-001] 자동 저장 + [FD-SYNC-002] 수동 동기화로 DB 반영.

##### 4.3 RLS

- DB 접근은 모두 Row Level Security 적용. 사용자가 권한 없는 행은 자동 필터링.

#### 11. 수용 기준

```
AC-FD-SYNC-003-1
  Given Cloud 모드, 사용자 첫 로그인
  When 앱 진입
  Then RLS 통과한 프로젝트·작업이 IndexedDB로 풀
       표 화면에 데이터 표시
```

### FD-SYNC-004 — Local-only 모드

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

Supabase 환경변수 미설정 시 또는 인터넷이 없는 환경에서도 로컬에서 사용 가능하게 한다 (시범·교육·오프라인 작업).

#### 4. 처리 규칙

##### 4.1 진입 조건

- 환경변수 미설정 또는 인증 실패 시 자동 진입.
- 또는 명시적 토글 (관리자 환경에서).

##### 4.2 동작

- 모든 데이터 IndexedDB/localStorage에만 저장.
- 회원가입·로그인 UI 숨김 또는 데모 사용자.

##### 4.3 차단 기능

- 동기화 버튼 비활성.
- Realtime·Presence 비활성.
- AI 분석 (외부 API 호출 필요한 기능)은 옵션 — 별도 키 입력 시 가능.

##### 4.4 Local → Cloud 전환

- 환경변수 추가 + 재시작 시 자동 진입.
- **마이그레이션 도구 필요**: 로컬 데이터를 클라우드로 일괄 업로드 (현재 미구현, 향후 추가 — P2).
- 미구현 단계에서는 사용자에게 "백업(JSON) → Cloud 모드 진입 → 복원" 절차 안내.

#### 11. 수용 기준

```
AC-FD-SYNC-004-1
  Given Supabase 환경변수 미설정
  When 앱 진입
  Then Local-only 모드 자동 진입
       헤더에 "로컬 모드" 배지

AC-FD-SYNC-004-2
  Given Local-only 모드에서 작업 추가 후
  When Cloud 모드로 전환 (환경변수 + 재시작)
  Then 사용자에게 "로컬 데이터를 백업하시겠습니까?" 안내
       사용자 동의 시 JSON 백업 다운로드 → Cloud 모드 진입 → 사용자 명시 복원
```

### FD-SYNC-005 — Realtime DB 동기화

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 1. 목적

다른 사용자의 변경을 즉시(수 초 이내) 자동 반영하여 협업 시점 차이를 줄인다.

#### 4. 처리 규칙

##### 4.1 토글

- 환경변수 또는 사용자 환경설정 (`VITE_ENABLE_REALTIME`).
- 기본 OFF — 5분 풀에 의존.

##### 4.2 채널

- Supabase Realtime의 `postgres_changes` 채널 — `tasks`, `projects`, `wbs_settings` 테이블의 INSERT/UPDATE/DELETE 수신.

##### 4.3 충돌 처리

- 로컬 dirty=false → 즉시 반영.
- 로컬 dirty=true → 충돌 감지 후 사용자에게 경고 (UI 업데이트 스킵, 사용자가 [동기화] 명시 클릭 시 머지).

##### 4.4 콘텐츠 fingerprint

- 자기 변경의 echo는 fingerprint 비교로 구분 (자기 broadcast 무시).

##### 4.5 향후 — Yjs CRDT

- 셀 단위 머지가 필요한 경우 Yjs 도입 옵션 (향후 P2).

#### 11. 수용 기준

```
AC-FD-SYNC-005-1
  Given Realtime ON, 사용자 A·B 같은 프로젝트
  When A가 작업 추가
  Then B 화면에 수 초 이내 새 작업 등장 (5분 기다리지 않음)

AC-FD-SYNC-005-2
  Given B가 셀 편집 중(dirty=true), A가 같은 작업의 다른 셀 수정 → 동기화
  When B 화면에 broadcast 도착
  Then UI 즉시 업데이트 안 함 (충돌 가능성)
       헤더에 "다른 변경이 있습니다 — 동기화하세요" 배지
       B가 [동기화] 클릭 시 머지 시도
```

### FD-SYNC-006 — Presence (셀 포커스 표시)

| 메타 | 값 |
|------|----|
| 우선순위 | P2 |

#### 4. 처리 규칙

##### 4.1 토글

- `VITE_ENABLE_PRESENCE` 환경변수.

##### 4.2 표시

- 헤더 우측: 동시 접속자 아바타.
- 표 셀·간트 막대·칸반 카드: 다른 사용자가 편집 중이면 그 사용자 색상의 외곽선.
- 사용자 색상은 `colorForUserId(id)` 결정적 매핑.

##### 4.3 broadcast

- 사용자가 셀 클릭/편집 시 120ms 디바운스 후 `cell_focus` broadcast 전송.
- 15초 무업데이트 시 다른 사용자 화면에서 자동 제거.

##### 4.4 차단 정책

- **차단 없음**. 시각적 표시만. 동시 편집은 LWW로 해결.

#### 11. 수용 기준

```
AC-FD-SYNC-006-1
  Given A·B 같은 프로젝트 접속
  When A가 셀 X 편집
  Then B 화면에 셀 X 외곽선이 A 색상으로 표시
       A가 다른 셀로 이동 → X 외곽선 제거, 새 셀에 표시
```

### FD-SYNC-007 — Undo / Redo

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 트리거

- Ctrl+Z (Undo), Ctrl+Y 또는 Ctrl+Shift+Z (Redo).
- 헤더 화살표 버튼.

##### 4.2 히스토리 저장 시점

- 모든 변경 op(`addTask`, `updateTask`, `deleteTask`, indent/outdent, paste 등) 직전에 `saveHistory()` 호출 → 현재 작업 트리 스냅샷 푸시.

##### 4.3 한계

- 최대 50개 스냅샷 (그 이상 누적되면 오래된 것부터 폐기).
- Redo 스택도 50개.
- 새 변경 발생 시 Redo 스택 비움.

##### 4.4 범위

- 작업 트리 전역 — 프로젝트 전환해도 히스토리 유지.
- 단 환경설정 변경(상태 정의 등)은 히스토리 미포함 (별도 처리).

##### 4.5 동기화 영향

- Undo는 로컬 변경으로 간주 → `dirty=true` → 다음 동기화에 반영.
- 다른 사용자의 변경 수신 후 Undo: 사용자 본인의 마지막 변경만 되돌림(서버 상태와 차이 발생 가능).

#### 11. 수용 기준

```
AC-FD-SYNC-007-1
  Given 작업 추가 후 Ctrl+Z
  When Undo 실행
  Then 추가된 작업 사라짐, 가중치 원복

AC-FD-SYNC-007-2
  Given 50개 변경 누적
  When 51번째 변경
  Then 가장 오래된 스냅샷 폐기, 51번째 추가
       Undo 50번 가능

AC-FD-SYNC-007-3
  Given Undo 후 새 변경
  When 변경 발생
  Then Redo 스택 비워짐 (방금 Redo는 더 이상 가능하지 않음)
```

### FD-SYNC-008 — 충돌 정책 (LWW)

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 기본 정책

- 같은 행의 같은 필드를 둘이 동시에 변경 → 마지막 INSERT/UPDATE가 우선 (`updated_at` 비교).

##### 4.2 fingerprint 비교

- 동기화 시 클라이언트와 서버 fingerprint 비교. 동일하면 변경 없음(echo 무시).

##### 4.3 사용자 안내

- 사용자 본인의 변경이 다른 사용자에 의해 덮어 쓰여진 경우 → 토스트 + 변경 이력에서 추적 가능.

##### 4.4 향후 — 셀 단위 머지

- Yjs CRDT 도입 시 같은 행 다른 필드는 자동 머지.

#### 11. 수용 기준

```
AC-FD-SYNC-008-1
  Given A가 작업 T의 작업명 편집 (저장 안 함), B가 T의 진척도 편집 후 저장
  When A가 작업명 저장
  Then T의 작업명 = A의 입력, T의 진척도 = B의 입력 (둘 다 보존, LWW가 아닌 필드 단위 차이)

AC-FD-SYNC-008-2
  Given A·B가 동시에 T의 작업명 편집
  When A 먼저 저장, B 5초 뒤 저장
  Then T의 작업명 = B의 입력 (LWW)
       A 화면에서 다음 동기화 시 B 값으로 갱신
       토스트 "내 변경이 다른 사용자에 의해 갱신되었습니다"
```

### FD-SYNC-009 — 감사 로그 (변경 이력)

| 메타 | 값 |
|------|----|
| 우선순위 | P1 |

#### 4. 처리 규칙

##### 4.1 기록 대상

- 작업 INSERT / UPDATE / DELETE.
- 프로젝트 INSERT / UPDATE / DELETE.
- 환경설정 변경.
- 멤버 권한 변경.

##### 4.2 저장 위치

- `wbs_audit_log` 테이블.

| 필드 | 의미 |
|------|------|
| `id` | 로그 ID |
| `entity_type` | 'task' / 'project' / 'settings' / 'member' |
| `entity_id` | 대상 ID |
| `action` | 'create' / 'update' / 'delete' |
| `actor_id` | 변경한 사용자 |
| `diff` | jsonb — 필드별 [old, new] |
| `created_at` | 시각 |

##### 4.3 조회 권한

- 작업·프로젝트의 변경 이력: 본인 참여 프로젝트 + 관리자.
- 환경설정·멤버 변경: 관리자.

##### 4.4 진입

- 컨텍스트 메뉴 [변경 이력].
- 헤더 ⋮ → [전체 변경 이력] (관리자만, 모든 프로젝트).

##### 4.5 표시

- 시간 역순. 행별: 시각·사용자·액션·필드별 변경값.

##### 4.6 보존 기간

- 무제한 (현재). 향후 데이터 정리 정책 (P3).

#### 11. 수용 기준

```
AC-FD-SYNC-009-1
  Given 작업 T 진척도 50→100 변경
  When 저장
  Then wbs_audit_log INSERT (entity_id=T.id, action='update', diff={progress:[50,100]}, actor_id=user.id)

AC-FD-SYNC-009-2
  Given 사용자 X 본인 참여 프로젝트
  When 작업 T 우클릭 → [변경 이력]
  Then T의 모든 변경 이력 표시

AC-FD-SYNC-009-3
  Given 사용자 X, 비-참여 프로젝트의 작업 T
  When 변경 이력 조회 시도
  Then RLS로 차단, "권한 없음"
```

### FD-SYNC-010 — 에러 처리·복구

| 메타 | 값 |
|------|----|
| 우선순위 | P0 |

#### 4. 처리 규칙

##### 4.1 DB 에러 분류

- **권한**: RLS 차단 → "이 프로젝트에 대한 권한이 없습니다" 토스트.
- **네트워크**: timeout/offline → 재시도 버튼 + 로컬은 보존.
- **데이터**: validation/constraint → 사용자 입력 거부 + 안내.
- **서버**: 5xx → 토스트 "일시적 오류 — 잠시 후 재시도".

##### 4.2 ErrorBoundary

- React 렌더링 오류 → fallback UI + [다시 시도] 버튼.
- 반복 오류 시 [페이지 새로고침] 권장.

##### 4.3 동기화 부분 실패

- 푸시 중 일부 실패: 성공한 부분만 반영, 실패 부분은 로컬에 dirty 유지 + 재시도 가능.
- 풀 중 실패: 로컬 유지, 다음 시도에서 재시작.

##### 4.4 복구 도구

- 백업 다운로드 ([FD-IO-003](./07_데이터_이동_AI.md)).
- 로컬 → DB 일괄 푸시 옵션.

#### 11. 수용 기준

```
AC-FD-SYNC-010-1
  Given 셀 변경 후 동기화, 네트워크 끊김
  When 동기화 시도
  Then 토스트 "네트워크 오류 — 재시도하세요" + [재시도] 버튼
       로컬 변경은 보존 (dirty 유지)

AC-FD-SYNC-010-2
  Given 컴포넌트 렌더링 중 예외
  When 발생
  Then ErrorBoundary fallback 표시
       [다시 시도] 클릭 → 자식 재렌더링 (대부분 성공)
       반복 실패 시 [새로고침] 버튼

AC-FD-SYNC-010-3
  Given 권한 없는 작업의 셀 편집 → 저장
  When DB가 RLS 차단
  Then 토스트 "권한 없음" + 로컬 변경 자동 롤백 (서버 값 복원)
```
