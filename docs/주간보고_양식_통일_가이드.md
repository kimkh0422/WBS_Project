# 주간보고: 양식 통일 · 내용만 변경

전사 통합 주간보고는 **같은 틀(상단 보조 바·차트 3패널·표·내비)**을 쓰고, **주차마다 바뀌는 값만** 갱신하는 것을 원칙으로 합니다.

## 1. 통합 대시보드(웹 · `WeeklyReportPage`)

| 구분 | 파일 | 바꿔도 되는 것 | 바꾸면 안 되는 것 |
|------|------|----------------|-------------------|
| 주차·제목·기준일·푸터 조직 수 문구 | `src/data/weeklyReportMeta.ts` | 매주/매회차 값 | — |
| 부서별 보고 본문 | `src/data/weeklyReport.html` 안의 `const REPORTS = [ ... ]` | 배열 안 객체·문자열만 | 배열 변수명 `REPORTS`, 렌더 함수 |
| 화면 골격·스타일·차트 | `weeklyReport.html`의 `<style>`, 상단 `subtop`, 패널 HTML, `<script>` 렌더 로직 | 원칙적으로 **수정 금지** (공통 양식) | — |

앱은 `WeeklyReportPage`에서 `buildWeeklyReportSrcDoc()`로 HTML을 읽은 뒤, `weeklyReportMeta.ts`의 값을 플레이스홀더에 주입합니다.

### `REPORTS` 한 건의 통일 스키마

타입 정의는 `src/data/weeklyReportTypes.ts`를 참고하세요. 요약:

- **공통 필드:** `id`, `org`, `reporter`, `recipient`, `group`, `icon`(선택)
- **선택 블록:** `strategy`, `issues`, `projects`, `sales`, `research`, `nextWeek`
- 없는 블록은 생략하면 됩니다. 빈 배열만 넣어도 됩니다.

`projects[].type` 문자열은 차트·뱃지 분류에 쓰이므로, 기존 보고서와 **같은 용어 체계**(예: 수행, 유지보수, 입찰, 제안, 기획 등)를 유지하는 것이 좋습니다.

### 메타와 데이터 개수 맞추기

`weeklyReportMeta.organizationCount`는 가능하면 **`REPORTS.length`**와 같게 두세요. (푸터「N개 보고 조직」과 실제 섹션 수가 어긋나지 않게)

## 2. WBS 앱 안의「주간보고 자동 생성」(`WeeklyReportModal`)

- **고정 양식:** 금주 한일 · 차주 계획 · 이슈, 표 구조, 복사/엑셀보내기 형식
- **내용만 변경:** 기준 주, 담당자 범위(나/전체), 프로젝트 범위, 그리고 WBS에 적힌 작업·메모
- 프로젝트 카드의 **주간보고용 메타 필드**(분류, 주관기관, 예산, 기간 표기 등)는 `src/types.ts`의 `Project` 주석을 참고하면, 자동 생성 문구가 한결같이 나옵니다.

## 3. 정리

- **통합 HTML 대시보드:** `weeklyReportMeta.ts` + `REPORTS`만 손대면 됩니다.
- **WBS 연동 주간보고:** 작업/프로젝트 데이터를 표준 필드에 맞게 쌓으면, 생성 결과의 형식은 항상 동일합니다.
