# /push — 커밋 + 푸시 (버전 끝자리 +1 · 커밋 시각 날짜·시·분 자동)

## 이 저장소가 버전·날짜를 처리하는 방식 (중요)

`pre-commit` 훅(`simple-git-hooks` → `scripts/bump-version.mjs`)이 **커밋할 때마다 자동으로**:

- `package.json` / `package-lock.json` / `version.txt` 의 **patch 끝자리를 +1**
- `CHANGELOG.md` 맨 위에 `## v{새버전} ({로컬 YYYY-MM-DD HH:mm})` 항목 추가
- 위 파일들을 `git add` 하여 **같은 커밋에 포함**

→ 따라서 **버전 끝자리 증가와 커밋 시각(날짜·시·분) 기록은 "그냥 커밋"만으로 자동 처리된다.**
앱 푸터의 `v{버전} ({날짜·시·분})`는 `package.json` 버전 + `CHANGELOG.md`의 해당 버전 타임스탬프에서 나온다([vite.config.ts](../../../vite.config.ts) `computeReleaseMeta`).

**그러므로 이 스킬은 버전을 직접 올리지 않는다.** `update-release.mjs`를 따로 실행하거나 `package.json` 버전을 손으로 고치면 훅과 합쳐져 **2씩 증가**하므로 금지한다.

## 수행 단계

1. **변경 확인** — `git status`와 `git --no-pager diff`(+`--staged`)로 무엇이 커밋될지 본다.
   - 커밋할 변경이 없으면 사용자에게 알리고 중단한다.
   - 의도치 않은 파일(빌드 산출물 `dist/`, 비밀키, 대용량 등)이 섞였으면 커밋 전에 사용자에게 확인한다.
   - 새로 만든 파일이 추적되지 않은 상태(`??`)면 의도된 것인지 확인해 누락을 막는다.

2. **다음 버전 계산** — `package.json`의 현재 `version`을 읽어 **patch+1** 한 값을 `{next}`로 둔다. (예: `0.6.45` → `0.6.46`). 훅이 정확히 이 값으로 올리므로 커밋 제목에 미리 쓸 수 있다.

3. **요약 작성** — 커밋 제목용 한국어 한 줄 요약을 정한다.
   - 사용자가 인자로 요약을 주면 그대로 사용한다.
   - 없으면 diff를 보고 기존 커밋체(명사형 나열, 예: "…마이그레이션·동기화·UI, …플러시, …보강·정리")로 한 줄 작성한다.

4. **커밋** — `git add -A` 후, 제목을 이 저장소 관례인 **`v{next}: {요약}`** 형식으로 커밋한다.
   - **`--no-verify` 금지** — 훅이 버전·날짜·포맷을 처리해야 한다.
   - `lint-staged`(prettier + `eslint --fix`)가 스테이징 파일을 자동 수정/검사한다. lint 오류로 커밋이 실패하면 원인을 사용자에게 보고하고, 코드 문제면 고친 뒤 다시 시도한다(훅을 우회하지 말 것).
   - 커밋 메시지 끝에 줄을 띄우고 `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` 를 붙인다. (제목 줄은 그대로 `v{next}: {요약}` 유지 — CHANGELOG/푸터에는 영향 없음)

5. **검증** — 커밋 직후:
   - `package.json`의 `version`이 `{next}`와 같은지
   - `CHANGELOG.md` 최상단 항목이 `## v{next} ({로컬 날짜·시·분})`인지
   확인한다. 어긋나면(훅 미동작 등) 멈추고 사용자에게 보고한다. 절대 강제로 다시 올리지 않는다.

6. **푸시** — `git push` (현재 브랜치 그대로). 이 저장소 릴리스 흐름은 `main`에 직접 커밋·푸시한다.
   - 업스트림이 없으면 `git push -u origin <현재브랜치>`.
   - 거부(non-fast-forward)되면 강제 푸시하지 말고 원인(원격이 앞섬 등)을 사용자에게 보고한다.

7. **보고** — 푸시된 `v{next}`, 커밋 시각(로컬 `YYYY-MM-DD HH:mm`), 커밋 해시 짧은 것, 변경 파일 수를 한국어로 한두 줄 요약한다.

## 참고
- CHANGELOG.md의 변경 항목 줄은 훅이 항상 `- 버전 업데이트`로 넣는다(고정). 앱 "변경이력" 메뉴는 `docs/변경이력_주요기능.md`를 보고, 푸터·수정일은 CHANGELOG의 **날짜·시·분**(신규) 또는 구버전 항목의 날짜만(플레이스홀더)에서 나온다. 사용자용 기능 설명을 남기려면 `docs/변경이력_주요기능.md`를 따로 수정한다.
- 기존 수동 흐름은 `push.bat`(메모장으로 메시지 입력)이다. 이 스킬은 그 흐름을 Claude가 대신 수행하는 것에 해당한다.
